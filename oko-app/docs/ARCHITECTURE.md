# Архитектура OKO — принятые решения

## Поток разработки
1. **Этап 0 (сейчас):** `prototype/index.html` — весь интерфейс и UX собираются
   и правятся ЛОКАЛЬНО: открыл файл в браузере — увидел. Без хостинга, без сборки,
   без npm. Мок-данные внутри файла. Это песочница дизайна и сценариев.
2. **Этап 1:** утверждённый UX переносится в ядро `apps/mobile` (Expo,
   один код на iOS/Android/Web), подключается живой API.
3. **Этап 2:** веб-сборка ядра оборачивается в TG Mini App (`apps/tg-adapter`).

## Backend: Fastify (а не NestJS)
ТЗ допускает оба. Выбран Fastify: меньше боилерплейта, быстрее итерации в
15-дневном темпе, легче на VPS. Модульность держим структурой папок
`server/src/modules/*` — каждый модуль регистрируется со своим префиксом.

## Данные
- Supabase = Postgres + Realtime + Auth. Схема: `server/src/db/migrations/`.
- API ходит в БД service-role клиентом; проверки прав — в коде API
  (единая точка), RLS добавим на прямые клиентские подписки Realtime.
- Realtime доставка сообщений: клиент подписан на insert в `messages`
  по своим chat_id; отправка — только через API (валидация, антиспам, лимиты).

## Медиа
Presigned URL: файл летит с устройства прямо в S3, API выдаёт только подпись
(`/media/presign`) и проверяет лимит размера по тарифу. Видео на проверку —
отдельный бакет `oko-tmp` с lifecycle 24 часа (автоудаление — критерий запуска).

## Тарифы и лимиты
`server/src/tiers.ts` — единственное место, где описаны лимиты тарифов.
Проверки: `requireTier('pro')` для доступов, `consumeCounter(...)` для
месячных счётчиков (проверки видео, ролики контент-завода). -1 = безлимит.

## Партнёрка
Начисления происходят в момент вебхука оплаты (`billing/routes.ts`):
L1 15% (после 6 месяцев с привязки клиента — 5%), L2 5%. Идемпотентность —
уникальный `(provider, external_id)` на payments и `(partner_id, payment_id)`
на accruals: дубль вебхука не даёт двойного начисления.

## ИИ
- Нейро-эндпоинты имеют собственный жёсткий rate limit поверх глобального.
- Агенты: промпты в `agents/*/system-prompt.md`, оркестрация n8n,
  все диалоги в `agents_logs`.
- Конвейеры (системы по анкете, видео-анализ, контент-завод) — асинхронные:
  API ставит задачу (status=queued), воркер/n8n двигает статусы, клиент
  видит прогресс по Realtime/поллингу.

## Деплой
`infra/docker-compose.yml`: api + n8n + Caddy (TLS автоматом) на VPS Timeweb.
Supabase и LiveKit — облачные. Секреты — только в `.env` на сервере.
