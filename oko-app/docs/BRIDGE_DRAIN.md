# Мост в Claude Code под каждый mini-app — как это работает и как «сливать» очередь

Мини-аппы OKO ставят тяжёлую задачу (картинка / видео / клип / обложка /
сайт / пост / письмо) в очередь на сервере, а выполняет её сессия Claude Code
(«сливщик») своими инструментами (Higgsfield и т.п.). Мгновенный ИИ-чат идёт
отдельно, через `api.php?action=assistant`, и работает всегда.

## Как задача попадает в очередь

Любой мини-апп зовёт `window.okoBridge` (слой `media/app/oko-bridge.js`):

```js
// поставить и дождаться результата:
okoBridge.run('image', 'кот в очках, стиль бренда OKO', {
  source: 'reels', title: 'обложка урока',
  onQueued: r => console.log('в очереди', r.uid),
  onUpdate: s => console.log('статус', s.status)
}).then(final => { /* final.status === 'done' → final.result (URL) */ });

// или по частям:
okoBridge.submit('cover', {prompt:'...'}, {source:'academy'});  // → {uid}
okoBridge.status(uid);   // опрос
okoBridge.mine(user);    // список задач пользователя
```

В окне **ОКО Ai** это подключено командой: пользователь пишет
`/картинка описание` — задача уходит в очередь, результат приходит прямо
в переписку картинкой.

## Серверные экшены (api.php)

| Экшен | Кто | Что |
|---|---|---|
| `oko_task` | публично (rate-limit) | поставить задачу → `{uid}` |
| `oko_task_status?uid=` | публично | статус/результат |
| `oko_task_mine?user=` | публично | список задач пользователя |
| `oko_task_pull` | **токен** | забрать pending (атомарный захват) |
| `oko_task_result` | **токен** | вернуть результат |

Токен для `pull`/`result` — любой из трёх (drainer_ok): `admin_password`,
`agent_token`, либо выделенный **`queue_token`** (наименьшие права: только
очередь, ни диалогов, ни денег, ни админки). Рекомендуется `queue_token` —
его можно безопасно раздать всем сессиям-сливщикам.

### Что добавить на VPS (один раз, как config-pay.php)

В `/var/www/okoteam/config.php` (или оверлеем в `config-pay.php`) добавить строку:

```php
'queue_token' => '<openssl rand -hex 24>',
```

Этот же токен положить в Environment variables окружений Claude Code как
`OKO_QUEUE_TOKEN`, чтобы сессии могли сливать очередь.

## Как сливать очередь из сессии Claude Code

Хелпер `oko-app/tools/oko-queue.mjs` (транспорт pull/result):

```bash
export OKO_QUEUE_TOKEN=...        # или OKO_AGENT_TOKEN / OKO_ADMIN_KEY
node oko-app/tools/oko-queue.mjs pull 5            # забрать до 5 задач
node oko-app/tools/oko-queue.mjs pull 3 image      # только картинки
# → делаешь работу своими инструментами (Higgsfield generate_image и т.п.),
#   заливаешь результат, получаешь публичный URL
node oko-app/tools/oko-queue.mjs result <uid> done '{"url":"https://.../out.png"}'
node oko-app/tools/oko-queue.mjs result <uid> failed '' 'генератор недоступен'
```

Цикл сливщика (для сессии):
1. `pull` — забрать pending (сервер атомарно пометит их `working`, чужой
   сливщик те же не возьмёт).
2. По каждой задаче: разобрать `kind` + `payload`, выполнить своими MCP-
   инструментами, получить публичный URL результата (или текст).
3. `result <uid> done '<url|json>'` — вернуть. Ошибка → `result <uid> failed`.
4. Повторять, пока `pull` не вернёт пусто.

## Как сделать сливщик автоматическим (по желанию Даниэля)

Каждая новая задача уже шлёт Даниэлю уведомление в Telegram (`oko_task`).
Чтобы очередь разбиралась сама, можно завести Routine (scheduled trigger),
который раз в N минут поднимает свежую сессию Claude Code с командой
«слей очередь OKO по BRIDGE_DRAIN.md». Всегда-включённый сливщик тратит
токены на холостых опросах, поэтому по умолчанию НЕ включён — включается
явным решением.

## Границы (честно)

- Задача выполняется, **когда работает сессия-сливщик**. Нет сессии — задача
  ждёт в очереди (приложение честно пишет «в очереди», не подделывает «готово»).
- Продакшн-ядро агентов (`oko-agents`, платящие клиенты, банковские данные)
  этот мост **не трогает** — очередь живёт в своей SQLite сайта (`app_tasks`),
  www-data пишет в неё напрямую, без контрол-эндпоинта и без токенов на бэкенде.
