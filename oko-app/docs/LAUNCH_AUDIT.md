## P1 — РЕАЛЬНЫЙ ПРОДУКТ (превратить прототип в рабочее приложение)

### 3. Бэкенд не подключён к UI
Каркас есть (`oko-app/server`, Fastify + Supabase): маршруты `auth`, `chats`,
`media`, `miniapps`, `billing`, `partners`, `feed`, `agents`. Но прототип
(single HTML) их почти не зовёт — работает на mock. Нужно: поднять сервер,
подключить реальные API, персистентность, JWKS/ключи, задеплоить сервер.

### 4. Реальная авторизация
Регистрация/вход — UI-мок. Нет настоящей верификации (email/phone OTP) через
Supabase Auth + бэкенд, нет валидации Telegram `initData`, нет сессий/ролей.

### 5. Платежи — нет реальных денег
Пейволл, вывод средств, эскроу Биржи, подписки, билеты рулетки — только UI и
TON-заглушка (TonConnect упомянут). Нет фиатного провайдера (ЮKassa/CloudPayments/
СБП/Stripe). Нужно: merchant-аккаунт (решение Даниэля) + вебхуки оплат + проведение
подписок/комиссий/выводов через бэкенд.

### 6. Данные — везде демо
Чаты, объявления Биржи, каналы, курсы Академии, KPI админки — засеяны. Для запуска
нужна стратегия: реальный контент Академии (уроки/тесты/сертификаты), сид + модерация
Биржи и каналов, или «пустой старт» с онбордингом.

### 7. Медиа/загрузки
S3-бакеты (`oko-media`, `oko-tmp`) настроены, но аплоад фото/видео/голосовых в UI —
мок (кроме локальной записи в blob). Нужно: реальный upload → S3 → отдача по CDN,
превью, лимиты по тарифу.

### 8. Telegram-бот @okoappbot
Mini-app открывается, но серверную часть бота проверить/дореализовать: вебхуки,
команды, валидация initData, оплаты через бот (Telegram Payments/Stars), уведомления.

### 9. AI-функции — сейчас демо-ответы
«Проверка видео», «Система роста», Контент-завод, ИИ-агенты поддержки/модерации —
выдают заготовленный текст. Ключи есть (Gemini ×3, Claude). Нужно: подключить модели
через бэкенд, реальная обработка, очереди, лимиты по тарифу.

## P2 — ГОТОВНОСТЬ И КАЧЕСТВО

10. **External CDN**: `three.js` и `telegram-web-app.js` грузятся с esm.sh/telegram.org.
    Риск (CSP/даунтайм). 3D-штаб не откроется, если CDN/политика заблокирует.
    Решение: self-host/инлайн three.js, ленивая загрузка с фолбэком.

    overflow + runtime на каждый push, авто-деплой при зелёном.

    CORS, секреты (уже вне git — хорошо), аудит прав.
13. **Аналитика/мониторинг**: события воронки, трекинг ошибок (Sentry-подобное),
    метрики (DAU/оплаты/охваты) — реальные, а не демо в админке.
14. **Юр/сторы**: документы RU+EN есть (✓). Проверить: оферта платежей, политика
    для Telegram/App Store/Google Play, возрастные ограничения, обработка ПДн.
15. **Первый запуск нового юзера**: сейчас всё засеяно демо. Новый пользователь
    должен видеть осмысленный онбординг и пустые состояния, а не чужие данные.
