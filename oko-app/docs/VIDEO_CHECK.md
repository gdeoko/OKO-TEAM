# ПРОВЕРКА ВИДЕО — runbook сессии-разборщика

Рабочий чат «🎥 ПРОВЕРКА ВИДЕО ОКО». Сюда через мост приходят задачи вида
`video_check` из мини-аппа приложения OKO. Проверено сквозным прогоном 13.08.2026.

---

## 1. Что приходит и чего не приходит

Мини-апп (`media/app/oko-factory2.js`, раздел «ПРОВЕРКА ВИДЕО») открывает файл
через `URL.createObjectURL` прямо в браузере человека. **Файл не уходит никуда:
ни на сервер, ни в мост, ни к нам.** Так и написано человеку в интерфейсе, и это
правда — менять это нельзя, не изменив само обещание в приложении.

Слой моста (`media/app/oko-bridge-apps.js`, `vcSend`) отправляет только замеры:

```json
{ "measured": { "name": "", "size": 0, "mime": "", "duration": 0,
                "w": 0, "h": 0, "fps": 0, "audio": null,
                "luma": null, "motion": null, "platform": "" },
  "checks": [ {"v":"ok|bad|unk","t":"название","n":"пояснение"} ],
  "want": "deep_review" }
```

Как эти числа получены (важно для честности вердикта):

| Поле | Откуда | Чего оно НЕ значит |
|---|---|---|
| `duration`, `w`, `h` | `loadedmetadata` у `<video>` | — |
| `size`, `mime` | сам объект `File` | `mime` часто пустой, тогда судить нечем |
| `fps` | `requestVideoFrameCallback`, реальные кадры за ~0,9 с, округление | точности до кадра нет; в Safari API нет вовсе → `0` |
| `audio` | `mozHasAudio` / `audioTracks` / `webkitAudioDecodedByteCount` | `null` = «браузер не даёт проверить», а НЕ «звука нет» |
| `luma` | средняя яркость пяти кадров 64×36, 0-255 | это не экспозиция и не контраст |
| `motion` | среднее отличие соседних **снятых** кадров | кадры сняты с шагом `duration/6`. Это НЕ темп монтажа, НЕ склейки и НЕ ритм — только признак «картинка вообще меняется» |

**Отсюда главное ограничение: смысловую часть ролика мы по этим данным не видим.**
Обещать разбор хука, ритма, субтитров или громкости, глядя на семь чисел, нельзя.
Вердикт обязан говорить это вслух каждый раз.

## 2. По каким критериям судим

Две базы норм, обе живые:

* **`oko-agents/docs/montage/ЭТАЛОН_МОНТАЖА.md`** — снят с пятнадцати реальных
  рилсов (ffprobe, детект склеек, кривая громкости, покадровые сетки). Таблица
  «Числа, по которым агент себя проверяет» и чек-лист приёмки на 20 пунктов.
* **`OKO-TEAM` ветка `claude/diesel-content-factory`, `oko-app/factory/QA_15POINT.md`**
  и `qa_score.py` — 15 пунктов на 100 баллов, ворота публикации 85.
  Флагманский VS-ролик DIESEL набрал 93/100.

### Технический допуск — то, что действительно считается

Движок `oko-app/tools/video-verdict.mjs`. Девять осей, 100 баллов, ворота 85
(та же цифра, что и у DIESEL — держим одну планку на весь контент-завод):

| Ось | Балл | Полный балл при |
|---|---|---|
| Кадр и соотношение | 14 | ровно 1080×1920 |
| Длительность | 14 | 18-24 с (пересечение окна эталона 12-24 и окна QA 18-40) |
| Звуковая дорожка | 12 | дорожка есть |
| Яркость кадра | 12 | 60-215 из 255 |
| Средний битрейт | 12 | 4-8 Мбит/с (норма выгрузки) |
| Частота кадров | 10 | 30 (съёмка) или 60 (графика) |
| Изменчивость картинки | 10 | разброс ≥10 из 255 |
| Контейнер | 8 | MP4 |
| Вес файла | 8 | до 30 МБ |

**Балл считается как доля от измеренного, а не от полной сотни.** Ось, которую
браузер не смог замерить, выпадает и из числителя, и из знаменателя. Иначе
`audio: null` превращалось бы в приговор «звука нет», а `fps: 0` в Safari ронял бы
любой ролик. В ответе всегда написано, сколько осей посчитано и на какой шкале.

### Чего технический допуск не касается

Из 20 пунктов чек-листа приёмки замерами закрыты **два** (кадр 1080×1920,
длительность) и один частично (звук — только факт наличия, не уровень).
Остальные семнадцать движок перечисляет в поле `not_measured` и НЕ оценивает:
хук первых 0,7-2,0 с, первая смена до 2,5 с, склейки и средний план, число
объектов на экране, субтитры по слову, безопасные поля, чем закрыт стык, вход и
выход элементов, вырезка по контуру, водяной знак генератора, громкость -19 ± 2 дБ,
пик, гашение хвоста, удар на смене, CTA в финале, читается ли ролик без звука.

Из 15 пунктов QA замерами закрыт **один** (длительность). Остальные требуют
`meta.json` и спеки сборки — через мост они не приходят.

## 3. Как сливать очередь

Токен `queue_token` **уже стоит на VPS** в `/var/www/okoteam/config-pay.php`
(проверено 13.08.2026; старая запись в `CLAUDE.md` про «нужно от Даниэля» устарела).
В окружении сессий его нет, поэтому берём через контрол-эндпоинт:

```bash
source <(base64 -d /workspace/oko-agents/secrets.env.b64)   # CONTROL_URL + CONTROL_TOKEN
export OKO_QUEUE_TOKEN=$(curl -s -X POST "$CONTROL_URL/x" -H "X-Token: $CONTROL_TOKEN" \
  --data 'php -r "\$a=include \"/var/www/okoteam/config-pay.php\"; echo \$a[\"queue_token\"];"' \
  | sed -n '/--- stdout ---/,/--- stderr ---/p' | sed '1d;$d' | tr -d '\n\r ')
```

Дальше обычным инструментом моста:

```bash
node oko-app/tools/oko-queue.mjs pull 5 video_check     # → {claim, items:[{uid,payload,...}]}
node oko-app/tools/video-verdict.mjs payload.json       # → {text, fixes, score, axes, not_measured}
node oko-app/tools/oko-queue.mjs result <uid> done '<json результата>'
```

`result` кладём в том виде, который умеет показать карточка
(`oko-bridge-apps.js`, `statusHtml`): `{text, fixes, url}`. Текст режется на
1200 знаках, правок показывается не больше двенадцати — движок укладывается сам.

Посмотреть очередь без токена, root-доступом:

```bash
curl -s -X POST "$CONTROL_URL/x" -H "X-Token: $CONTROL_TOKEN" --data 'php -r "
\$p=new PDO(\"sqlite:/var/www/okoteam/data/oko.db\");
foreach(\$p->query(\"SELECT id,uid,kind,status,title FROM app_tasks ORDER BY id DESC LIMIT 20\") as \$r)
  echo implode(\" | \",[\$r[0],\$r[1],\$r[2],\$r[3],\$r[4]]).PHP_EOL;"'
```

Проверка движка перед тем, как верить его нулям (урок 19 памяти проекта):

```bash
node oko-app/tools/video-verdict.mjs --self-test    # пять проб, все должны пройти
```

## 4. Правила ответа

1. **Не судить неизмеренное.** Нет `fps` — пишем «браузер не даёт считать кадры»,
   а не «частота в норме». Нет `audio` — «проверить нельзя», а не «звука нет».
2. **Балл всегда с шкалой.** «97 из 100, считано по 9 осям» — читаемо;
   голое «97» врёт, когда посчитано четыре оси из девяти.
3. **Каждый ответ несёт границу.** Строка про то, что файла у нас нет и смысловая
   часть не оценивалась, идёт в текст всегда, а не только когда балл низкий.
4. **Правки сортированы по цене.** Сначала ось, потерявшая больше всего баллов.
5. **Ворота 85 — это не «плохой ролик».** Это «технически не готов к выгрузке».
   Ролик может пройти допуск на 100 и при этом быть скучным: допуск про пиксели,
   а не про смысл.
6. **Ничего не выдумывать про содержание.** Ни «хук слабый», ни «добавь субтитры» —
   мы их не видели.

## 5. Что закрыло бы смысловую часть

Всё упирается в один файл, которого у нас нет. На VPS для настоящего разбора
уже стоит **ffmpeg/ffprobe 8.0.1** и свободно 125 ГБ, S3-бакет `oko-tmp` с
lifecycle 24 ч тоже есть. Если добавить в мини-апп **необязательную** выгрузку
ролика в `oko-tmp` по presigned-ссылке (человек нажимает отдельно, с явным
текстом «файл уйдёт на сервер OKO и удалится через сутки»), то ffprobe и ffmpeg
закрывают ещё примерно двенадцать пунктов чек-листа: настоящие склейки и средний
план, кривая громкости по секундам (-19 ± 2 дБ, пик, гашение хвоста), покадровые
сетки под хук, субтитры и безопасные поля, детект водяного знака.

Пока такой выгрузки нет — работаем по замерам и говорим об этом прямо.
Обещание «файл не уходит никуда» в интерфейсе трогать без решения Даниэля нельзя.
