# Злой аудит Rocket CDN — вне игры и вне финала

Зона: index.html целиком, app.html, admin.html, splash.html, splash-lk.html, offer.html, privacy.html.
Метод: чтение кода + точечные прогоны Playwright (общее.mjs), один браузер за раз.
Сервер: `php -S 127.0.0.1:8123 -t .` поднят локально.

Находки пишутся по ходу работы, тяжёлые сверху.

## НАХОДКИ

### 1. Тема оформления не применяется на privacy.html и offer.html — переключение на светлую тему на главной не действует на страницах политики и оферты
Файлы: `privacy.html:2`, `offer.html:2` (сравнение с `index.html:41-42` и `admin.html:558-567`).

`index.html` хранит выбор темы в `localStorage.rc_theme` и читает его инлайн-скриптом ещё до первой отрисовки (`index.html:41-42`):
```
41  <script>/* Тема до первой отрисовки... */
42  try{var _t=localStorage.getItem("rc_theme");if(_t==="light"||_t==="dark")document.documentElement.setAttribute("data-theme",_t);}catch(e){}</script>
```
`admin.html` делает то же самое штатно (`admin.html:558-567`, `applyTheme(localStorage.getItem("rc_theme") || "dark")`).

А вот `privacy.html` и `offer.html` — просто:
```
<html lang="ru" data-theme="dark">
```
Ни строчки JS, читающей `rc_theme`, ни переключателя темы на странице вообще. `grep -n 'rc_theme|data-theme' privacy.html offer.html` находит только этот один хардкод `dark`.

Обе страницы прямо связаны с главной: чекбокс согласия в форме заявки ведёт на `privacy.html` (`index.html:1301`, `target="_blank"`), футер и мобильное меню ведут на обе (`index.html:870-871, 1341-1342`).

**Воспроизведено вживую** (`tools/audit/зло-тема.mjs`, ПК 1440×900):
1. Открыл главную, кликнул переключатель на светлую тему. `localStorage.getItem("rc_theme")` → `"light"`.
2. Тот же браузер/вкладка/origin, переход на `privacy.html`: `document.documentElement.getAttribute("data-theme")` → `"dark"`, `getComputedStyle(document.body).backgroundColor` → `"rgb(5, 12, 21)"` (это тёмный фон `#050C15`, не светлый `#F3F7FB`).
3. То же самое на `offer.html`: снова `"dark"`, снова `rgb(5, 12, 21)`.

Человек осознанно переключил тему на сайте, открывает по ссылке из этого же сайта политику конфиденциальности перед отправкой формы — и получает страницу в другой, незапрошенной теме. Это прямое противоречие тому, что тема на сайте вообще подаётся как выбор пользователя (кнопка есть в шапке, состояние сохраняется).

### 3. Пункт меню «Сценарии» есть в мобильном меню, но отсутствует в десктопной навигации
Файл: `index.html:816-823` (десктоп-нав) vs `index.html:858-865` (мобильный drawer).

Десктопная навигация в шапке:
```
816  <nav class="nav" aria-label="Основная навигация">
817    <a href="#products"  data-i18n="nav.products">Продукты</a>
818    <a href="#infra"     data-i18n="nav.infra">Инфраструктура</a>
819    <a href="#adv"       data-i18n="nav.adv">Преимущества</a>
820    <a href="#how"       data-i18n="nav.how">Как работает</a>
821    <a href="#faq"       data-i18n="nav.faq">Вопросы</a>
822    <a href="#contact"   data-i18n="nav.contact">Контакты</a>
823  </nav>
```
Мобильный drawer (`.drawer`, строка 858):
```
859  <a href="#products" data-i18n="nav.products">Продукты</a>
860  <a href="#infra"    data-i18n="nav.infra">Инфраструктура</a>
861  <a href="#adv"      data-i18n="nav.adv">Преимущества</a>
862  <a href="#how"      data-i18n="nav.how">Как работает</a>
863  <a href="#cases"    data-i18n="nav.cases">Сценарии</a>
864  <a href="#faq"      data-i18n="nav.faq">Вопросы</a>
865  <a href="#contact"  data-i18n="nav.contact">Контакты</a>
```
На сайте есть полноценный раздел `<section id="cases">` (строка 1198, «Сценарии», 12 карточек: OTT, телеканалы, e-commerce и т.д.). С десктопа/широких экранов на него нет пути через навигацию вообще — ни якоря в шапке, ни ссылки где-то ещё в основном потоке (проверено `grep -n '#cases'` по всему файлу — единственное вхождение это drawer). Пользователь с десктопа/планшета в альбомной ориентации может узнать о разделе только листая всю страницу вручную.

Воспроизвести: открыть index.html на ширине ≥ той, где `.burger` скрыт и `.nav` показан (проверить брейкпоинт в rc-adapt.css/rc.css), посмотреть на 6 пунктов меню — «Сценарии» нет.

**Доказано чтением кода.** Не требует браузера — единственное вхождение `#cases` во всём index.html это мобильный drawer (grep подтверждает).

### 2. Переключение на английский не переводит выпадающий список «Направление» в форме заявки — 7 пунктов остаются на русском
Файл: `index.html:1283-1291` (форма `#leadForm`, поле `#lfTopic`).

```
1283  <select id="lfTopic" name="topic">
1284    <option data-i18n="prod.1h">CDN</option>
1285    <option data-i18n="prod.2h">Стриминг</option>
1286    <option data-i18n="prod.3h">Медиа-хранилище</option>
1287    <option data-i18n="prod.4h">Плеер</option>
1288    <option data-i18n="prod.5h">Облако</option>
1289    <option data-i18n="prod.6h">Безопасность</option>
1290    <option data-i18n="prod.7h">Виртуальный диктор</option>
1291  </select>
```
Ключи `prod.1h`…`prod.7h` не существуют ни в `RU`, ни в `EN` словаре `assets/rc-i18n.js` (проверено скриптом сверки ключей: словарь содержит `prod.tag`, `prod.h`, `prod.p`, но не `prod.1h..7h` — карточки продуктов в `#gridProducts` вообще не имеют `data-i18n`, значит эти семь ключей никогда никем не заполнялись, мёртвая привязка).

Механизм перевода (`assets/rc-app.js:88` функция `t()`) при отсутствии ключа в обоих словарях тихо откатывается на `_i18nOrig` — исходный текст из разметки, то есть русский. Само переключение языка при этом не ломается и не бросает ошибку, поэтому дефект незаметен в консоли — только визуально.

**Воспроизведено вживую** (`tools/audit/зло-lang.mjs`, ПК-экран 1440×900): после клика по `button[data-lang="en"]` `document.documentElement.lang` становится `"en"`, шапка и drawer переводятся полностью (`Products`, `Advantages`, `Use cases` и т.д.), а `#lfTopic option` возвращает ровно:
```
["CDN", "Стриминг", "Медиа-хранилище", "Плеер", "Облако", "Безопасность", "Виртуальный диктор"]
```
То есть весь сайт на английском, а выпадающий список в форме заявки — единственное место — остаётся на русском. Для англоязычного посетителя это выглядит как забытый перевод прямо в форме, которую он должен заполнить.
