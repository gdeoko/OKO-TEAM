## НАХОДКА 1 (самая тяжёлая). rc-cinema.js: переключение языка в режиме «салона» безвозвратно уничтожает настоящий заголовок секции «Надёжность»

Файлы: `assets/rc-cinema.js:561-582, 599-611, 788` + `assets/rc-fill.js:92-99, 111-117` + `index.html:1213-1222`.

Разметка секции (`index.html:1213-1222`):
```html
<section id="reliability">
  <div class="wrap">
    <div class="sec-head rv" data-par="0.03">
      <div class="sec-tag" data-i18n="rel.tag">Надёжность</div>
      <h2 class="sec-h" data-i18n="rel.h">Работает, когда на вас смотрят</h2>
      <p class="sec-p" data-i18n="rel.p">...</p>
    </div>
    <div class="grid g-4" id="relGrid"></div>
  </div>
</section>
```

Шаг 1. Пока рубка включена (`cabinAllowed()` истинно для обычного десктопа без reduced-motion и без деградации — это дефолтный путь для любого нормального посетителя), `collect()` в rc-cinema.js реально перемещает `.sec-head` ВНУТРЬ `#relGrid`:
```js
// rc-cinema.js:561-582

if (head && !head._cabHome) {
  head._cabHome = { parent: head.parentNode, next: head.nextSibling };  // .wrap, #relGrid
}
...
if (on) {
  if (head.parentNode !== ring) ring.insertBefore(head, ring.firstChild);  // ring === #relGrid
  head.classList.add("card", "cab-head");
}
...
if (on) cards = [head].concat(cards);
```
и следом (rc-cinema.js:599-611) вкладывает все карточки, включая `head`, в новый `<div class="cin-world">`, который сам является ребёнком `ring` (`#relGrid`):
```js

if (on) {
  if (!world) { world = doc.createElement("div"); world.className = "cin-world"; ring.appendChild(world); }
  cards.forEach(function (el) { if (el.parentNode !== world) world.appendChild(el); });

```
Итог: реальный узел `.sec-head` (с текстом «Надёжность» / «Работает, когда на вас смотрят» / описанием) физически стал потомком `#relGrid`.

Шаг 2. Пользователь переключает язык (обычное действие, есть переключатель RU/EN на сайте). Летит `rc:lang`. Обработчик в `assets/rc-fill.js:111-117` синхронный, без `setTimeout`:
```js
document.addEventListener("rc:lang", function (e) {
  if (!window.RC_I18N) return;
  fill(e.detail.t, e.detail.blocks);
});
```
а внутри `fill()` (rc-fill.js:92-99):
```js
var rel = $("#relGrid");
if (rel) rel.innerHTML = [1, 2, 3, 4].map(function (n) { return '<article class="card ...">...</article>'; }).join("");
```
`rel.innerHTML = ...` полностью стирает ВСЕХ детей `#relGrid` — то есть `.cin-world` вместе со всем, что в нём лежит, включая перемещённый на шаге 1 настоящий `.sec-head`. Новые дети — это только четыре generic `<article class="card">`, никакого `.sec-head` среди них rc-fill.js не создаёт (он про заголовок секции ничего не знает).

Шаг 3. Обработчик `rc:lang` в самом rc-cinema.js (rc-cinema.js:788) откладывает пересборку:
```js
doc.addEventListener("rc:lang", function () { setTimeout(collect, 120); });
```
`setTimeout` гарантированно выполняется ПОСЛЕ того, как все синхронные подписчики того же `dispatchEvent` (в том числе fill() из rc-fill.js) уже отработали — это гарантия цикла событий, а не зависящий от порядка регистрации факт. Значит к моменту, когда `collect()` снова запустится, узел `.sec-head` уже физически удалён из документа (не просто отсоединён — он был ребёнком уничтоженного `.cin-world`, ссылок на него больше ниоткуда нет, кроме as `head._cabHome`, которая ссылается сама на себя).

Шаг 4. `collect()` при повторном запуске делает:
```js
var head = rel.querySelector(".sec-head");   // null — узла больше нет нигде в DOM
if (head && !head._cabHome) { ... }           // не выполняется
...
if (head) { ... }                             // не выполняется вовсе
```
Дальше строится новый `.cin-world` вокруг четырёх свежих карточек — без заголовка. Раздел «Надёжность» лишается своего тайтла и подписи НАВСЕГДА до перезагрузки страницы: ни возврат языка обратно, ни отключение сцены (сработает `else if (head._cabHome...)`, но условие начинается с `head &&`, а `head` уже `null`) этого не восстановит, потому что переменная `head` в следующих вызовах `collect()` элемент больше не находит - он физически удалён из документа.

Проверено по коду напрямую (не по рендерингу, без браузера): у `rel.innerHTML = ...` в rc-fill.js нет ни единой проверки на наличие `.cin-world`/`.sec-head` внутри `#relGrid`, а перемещение `head` в `#relGrid` в rc-cinema.js подтверждено явным `ring.insertBefore(head, ring.firstChild)` и `world.appendChild(head)` при живом `ring === doc.getElementById("relGrid") === rel` из rc-fill.js.

Условие срабатывания — обычнейшее для сайта: WebGL есть, reduced-motion не запрошен, деградация не на ступени 3 (дефолт для любого не самого слабого устройства), пользователь хоть раз щёлкнул переключатель языка после того, как сцена рубки уже поднялась и хотя бы раз пересобрала карточки (что происходит быстро после загрузки). Единственный явный текстовый заголовок секции «Надёжность» после этого пропадает необратимо, а вместе с ним - `rel.tag`/`rel.h`/`rel.p` контент, который эта секция обязана нести.

Файл: `assets/rc-world.js:156-175, 128-142, 477`.

`DEPTH` (rc-world.js:82-87) содержит селектор `.card` (и `.case`, `.step`) с ненулевым коэффициентом, то есть эти узлы реально попадают в `watchLay()` и остаются в `layIO`.

Путь к багу:
1. `assets/rc-fill.js:94-99` строит блок «Надёжность» так:

   и аналогично `#howGrid` (rc-fill.js:82-89) — `<article class="card case step rv rv-d...">`. 2. Пока язык не переключили, эти `.card` уже отслеживаются `layIO` (rc-world.js seed() выполнился на boot() или на первом `rc:lang`).

4. `layIO` (единственный, живёт всё время жизни страницы — `var layIO = null;` в замыкании модуля, не пересоздаётся) продолжает держать внутри себя ссылки на отсоединённые DOM-узлы прежних `.card`. Это классическая утечка «наблюдатель без disconnect на пересобранный интерфейс, указывающий в отсоединённые узлы» — то же самое, что уже нашли сегодня в салоне и в кэшах после смены языка, только здесь источник это `rc-world.js`.

Каждое переключение языка (а его можно щёлкать многократно) добавляет очередную партию мёртвых узлов в `layIO`, которые браузер обязан держать живыми в памяти (GC не может собрать поддерево, пока на него есть ссылка из observation target list), и что 3D-мир платит за них лишний расчёт пересечений, хотя показывать их уже нечего.

## Подозрения (не могу до конца доказать путь срабатывания или эффект минимальный)

### П1. assets/rc-fill.js:61-77 — IntersectionObserver для подстановки снимков ЦОД плодится заново на каждый `rc:lang`, тоже без disconnect для отработавшего
```js
if (dc && "IntersectionObserver" in window) {
  var dcIo = new IntersectionObserver(function (es) { ... dcIo.disconnect(); }, { rootMargin: "1400px 0px" });
  dcIo.observe(dc);
}
```
`dcIo` — локальная переменная функции `fill()`, вызываемой заново на каждое `rc:lang`. Если пользователь переключил язык до того, как секция `#dcGrid` попала в вьюпорт (наблюдатель ещё не сработал и не сделал self-disconnect), старый `dcIo` остаётся зарегистрированным на тот же самый узел `dc` (сам контейнер `#dcGrid` не пересоздаётся, меняется только `.innerHTML`). При повторных переключениях языка накапливается по одному наблюдателю на каждый цикл. Эффект слабее находки 2: контейнер не отсоединяется (сам `dc` жив), и когда секция всё же попадёт в кадр, все накопленные наблюдатели просто сработают почти одновременно и каждый вызовет `dcIo.disconnect()` сам на себя — повторный, но безвредный проход по одним и тем же `[data-shot]`. Не привожу как основную находку, потому что не вижу реального ущерба кроме нескольких лишних экземпляров IntersectionObserver в памяти на время до первого скролла к секции.

### П4. bot.php: `contest_code()` использует `admin_key` как HMAC-секрет для публичных реферальных кодов
`bot.php:74-77`:
```php
function contest_code($uid) {
    $secret = (string)rc_cfg('admin_key', 'rocketcdn');
    return strtoupper(substr(hash_hmac('sha256', 'contest:' . (string)$uid, $secret), 0, 10));
}
```
Смешение назначения ключа (пароль входа в админку одновременно HMAC-секрет генератора публичных реферальных ссылок). Само по себе не эксплуатируется (HMAC однонаправленный, а совпадение кода реального пользователя и так публично — оно рассылается в его личной ссылке), поэтому не привожу как боевую уязвимость, но это архитектурный риск: смена `admin_key` в будущем (например, после утечки пароля) молча меняет формулу генерации кодов для новых участников, а старые продолжают матчиться по значению, записанному в `contest.json` на момент вступления — то есть ключ безопасности и параметр несвязанной бизнес-фичи завязаны друг на друга без явной причины.
