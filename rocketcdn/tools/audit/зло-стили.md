## НАХОДКИ (тяжёлые сверху)

### 1. Кнопка закрытия голограммы RocketVPN — 31×31 px, ниже собственной нормы проекта (32 px)
Файл: `assets/rc-vpn.css:228-236`

```css
.rc-vpn-x {
  position: absolute;
  z-index: 4;
  top: 10px;
  right: 12px;
  width: 31px;
  height: 31px;
  ...
}
```

Кнопка реальная (`assets/rc-vpn.js:143-167`: `<button type="button" class="rc-vpn-x" aria-label="Закрыть">×</button>`,
слушатель клика на строке 169), других определений `.rc-vpn-x` в CSS нет ни на одной ширине —
`grep -n "rc-vpn-x" rc-vpn.css` даёт единственное совпадение.

Рядом, в этом же пульте, для двух похожих крестиков (`.rcf-dos-x`, `.rcf-help-x`,
`rc-flight.css:1415-1428` и `rc-flight.css:2533-2544`) стоит прямой комментарий заказчика,
зафиксированный в коде: «Тридцать точек под палец мало (норма тридцать две) — подрос» —
и оба выросли до 34×34 px. Крестик голограммы RocketVPN в эту правку не попал и остался
на 31 px — на 1 px меньше даже той нормы, которую команда сама считает нижней границей,
и на 3 px меньше соседних крестиков в том же интерфейсе.

Проявляется на любой ширине экрана, в том числе на телефоне (голограмма открывается кликом
по проектору VPN в кабине или по пункту RocketVPN в мобильном меню — `rc-vpn.js:116-127`,
`ensureDrawer()`). Человек на телефоне промахивается по кресту чаще, чем по соседним
крестам того же экрана, потому что палец физически не различает разницу в 1-3 px, но
разработчик, тестировавший именно 34-px крестики, промах не увидит.

### 2. Кнопки действий голограммы RocketVPN — кегль 8 px на ширинах ≤390 px, подписи полей — 6 px на ширинах 391-760 px
Файл: `assets/rc-vpn.css:283-286` (база), `:364-365` (≤760px), `:390-395` (≤390px или ≤650px по высоте)

База (любая ширина ≥761px и в диапазоне тоже, пока не перебито ниже):
```css
.rc-vpn-grid i {
  color: rgba(161, 203, 255, .64);
  font: 600 8px/1 "Golos Text", system-ui, sans-serif;
  letter-spacing: .14em;
}
```
При ≤760px (`rc-vpn.css:364-374`):
```css
.rc-vpn-grid b { font-size: 9px; }
.rc-vpn-grid i { font-size: 6px; }
```
При ≤390px или высоте ≤650px (`rc-vpn.css:390-395`):
```css
.rc-vpn-actions a,
.rc-vpn-actions button { min-height: 33px; padding: 6px; font-size: 8px; }
```

Три разных элемента:
- `.rc-vpn-grid i` — подписи «МАРШРУТ / КОНТУР / СТАТУС» — уже 8 px на десктопе,
  становятся 6 px на любой ширине от 391 до 760 px (то есть почти на всех телефонах и
  многих планшетах в портретной ориентации). Шесть точек нечитаемо ни при каком
  letter-spacing.
- `.rc-vpn-actions a, .rc-vpn-actions button` — это не служебные капсы, а целые фразы:
  «Открыть RocketVPN», «Розыгрыш · пригласить друзей», «Вернуть контур CDN»
  (`rc-vpn.js:158-160`). На ширине ≤390px (стандартный iPhone, большинство Android)
  или при невысоком окне (альбомная ориентация телефона, ≤650px по высоте — то есть
  ровно та ситуация, которую сам файл называет частой: см. `rc-vpn.css:397`
  `@media (prefers-reduced-motion: reduce)` рядом) эти три предложения набраны 8-точечным
  кеглем. Это единственные три кнопки перехода на сайт rocketvpn.top и в конкурс в Telegram
  на всей голограмме — то есть буквально то, ради чего диалог открыт.

Ухудшение противоположно логике: чем уже экран, тем мельче шрифт (8px база → 6px на
≤760px для подписей полей), хотя обычно на узком экране кегль либо держат, либо
увеличивают.

## ПОДОЗРЕНИЯ (не доказано до конца)

### A. Мини-кнопки пульта (снимок, справка) — 26×26 px на телефоне, ниже собственной нормы 32 px
Файл: `assets/rc-flight.css:3474-3481` (база, десктоп/планшет), `:3572` (≤760px)

```css
.rc-flight .rcf-key.rcf-mini {
  min-width: 0;
  width: clamp(28px, 3.2vh, 34px);
  height: clamp(28px, 3.2vh, 34px);
  ...
}
```
На `≤760px` (`rc-flight.css:3560-3576`):
```css
.rc-flight .rcf-key { height: 40px; min-width: 40px; padding: 0 5px; gap: 1px; }
...
.rc-flight .rcf-key.rcf-mini { width: 26px; height: 26px; }
...
.rc-flight .rcf-zoom-in, .rc-flight .rcf-zoom-out { display: none; }
```
Класс `.rcf-mini` стоит на четырёх кнопках пульта: `rcf-zoom-in`, `rcf-zoom-out`,
`rcf-shot` (снимок из кабины), `rcf-help-key` (справка «Как летать») —
`assets/rc-flight.js:828-841`. На телефоне (`max-width: 760px`, самый частый экран по
памяти проекта — «Даниэль читает с телефона») zoom-кнопки скрыты, но `rcf-shot` и
`rcf-help-key` остаются видимыми и одновременно сжимаются до 26×26 px — на 6 px ниже
даже нижней нормы 32 px, которую команда сама зафиксировала в комментарии к соседним
крестикам (см. находку №1), и заметно ниже основных клавиш пульта (`.rcf-key` на той же
ширине — честные 40×40).

Это отдельные элементы от «крестиков досье и справки», которые чинились сегодня
(`.rcf-dos-x`, `.rcf-help-x` — панели закрытия, а не эти кнопки открытия/снимка на самом
пульте), так что в список сегодняшних правок не попадает.

Не довожу до «находки», потому что не могу проверить рендер: на десктопе базовый размер
тоже ниже 40 px (`clamp(28px, 3.2vh, 34px)`), и не исключено, что это осознанный компромисс
плотной приборной панели (тесная группа из четырёх кнопок с шагом clamp) — в отличие от
одиночного крестика голограммы, у которого такого оправдания плотностью нет.

### B. `.rc-shine` — постоянный fixed-слой на весь экран с `mix-blend-mode`, живёт всё время полёта
Файл: `assets/rc-world.css:322-341`

Слой `position: fixed; inset: 0` с двумя `radial-gradient` и `mix-blend-mode: plus-lighter`
(или `multiply` в светлой теме) существует в DOM постоянно вне `.rc-inside/.rc-flying/.rc-approach`
и меняет `opacity` через `transition: opacity .5s linear` от CSS-переменных `--rocket-x/--rocket-y/--rocket-near`,
которые, судя по имени, обновляются по кадру из JS при прокрутке. Не нашёл явного
`will-change` на нём, но композитинг `mix-blend-mode` на full-viewport слое, который живёт
всю прокрутку страницы, а не только «активные» секции — потенциально дорогой слой без
явного ограничения времени жизни. Не проверено вживую (браузер недоступен), поэтому не
поднимаю до находки — возможно, `mix-blend-mode` тут достаточно дёшев на практике из-за
малой непрозрачности и отсутствия анимации самого фильтра.
