# Злой ревизор кода — Rocket CDN

Разбор только по коду, без запуска браузера. Тяжёлые находки сверху.

---

## НАХОДКА 1. rc-interior.js: boot() гарантированно запускается дважды — все слушатели вешаются по два раза

Файл: `assets/rc-interior.js:1336-1391`

```js
function boot() {
  if (root.classList.contains("rc-reduced")) return;
  T = g.THREE;
  if (!T) return;
  measure();
  doc.addEventListener("rc:lang", function () { setTimeout(measure, 200); });
  addEventListener("resize", function () { setTimeout(measure, 250); }, { passive: true });
  addEventListener("load", function () { setTimeout(measure, 400); });
  addEventListener("rc:hatch", function (e) { ... });
  if (g.RC_MOTION) g.RC_MOTION.on(function (p) { setProgress(p); });
  else addEventListener("scroll", function () { ... }, { passive: true });
  addEventListener("pageshow", function () { ... }, { passive: true });
  doc.addEventListener("visibilitychange", function () { ... }, { passive: true });
}
...
addEventListener("rc:3d", boot);
if (g.THREE) boot();
```

Нет защёлки (`if (T) return`, флага `booted` и т.п.), которая бы не пускала повторный вызов.

Как до неё дойти:
1. `assets/rc-gl.js` грузит объёмный слой пачкой файлов через `document.createElement("script")` с `sc.async = false` (строка 226) — это гарантирует, что скрипты ВЫПОЛНЯЮТСЯ строго по порядку списка `FILES` (rc-gl.js:184-187):
   `["vendor/three.min.js", "gen/cab/meta.js", "gen/cab/flat.js", "gen/cab/deck.js", "rc-real.js", "rc-globe3d.js", "rc-rack.js", "rc-rocket.js", "rc-interior.js", "rc-planets.js", "rc-keys.js", "rc-deck.js", "rc-panel.js", "rc-cabin.js", "rc-flight.js"]`
   `vendor/three.min.js` стоит раньше `rc-interior.js` в списке — значит к моменту, когда собственный код `rc-interior.js` выполняется (нижние строки IIFE), `window.THREE` уже установлен предыдущим файлом.
2. Поэтому строка `if (g.THREE) boot();` (rc-interior.js:1390) срабатывает СРАЗУ же, при обычной загрузке файла — это первый вызов `boot()`.
3. Когда прогрузятся ВСЕ 15 файлов (включая сам `rc-interior.js`), `rc-gl.js` в функции `ready()` (rc-gl.js:196-198) вызывает `fire("rc:3d")`, а `fire()` (rc-gl.js:148-151) шлёт событие и на `window`, и на `document`:
   ```js
   function fire(name) {
     try { dispatchEvent(new CustomEvent(name)); } catch (e) {}
     try { document.dispatchEvent(new CustomEvent(name)); } catch (e) {}
   }
   ```
4. `rc-interior.js` заранее подписался на это же событие через голый `addEventListener("rc:3d", boot);` (window-слушатель) — событие долетает, `boot()` вызывается ВТОРОЙ раз.

Что происходит: каждый слушатель внутри `boot()` регистрируется дважды. Проверено на `g.RC_MOTION.on`: в `rc-motion.js` это просто `push` в массив без дедупликации —
```js
on: function (fn) { if (typeof fn === "function") listeners.push(fn); },
```
(rc-motion.js:384) — значит `setProgress(p)` при обычном скролле будет вызываться на каждый тик ДВАЖДЫ, то есть весь пересчёт геометрии рубки, проекции панелей и вызовы щелчков/`blip`-звука в `setProgress` выполняются вдвое чаще, чем нужно. То же самое — двойная подписка на `rc:lang`, `resize`, `load`, `rc:hatch`, `pageshow`, `visibilitychange`: каждое из этих событий после загрузки объёмного слоя обслуживается двумя независимыми обработчиками одновременно.

Для сравнения — в `assets/rc-scroll.js:402-414` для ракеты сделана правильная защёлка от того же паттерна гонки:
```js
function makeRocket() {
  if (!cv || rocket || !g.RCRocket) return;   // <-- защёлка есть
  ...
}
if (g.RCRocket) makeRocket();
else { addEventListener("rc:3d", makeRocket); ... }
```
здесь `if/else` не даёт повесить слушатель, если объект уже создан синхронно, а сам `makeRocket` вдобавок проверяет `rocket` — двойной вызов безвреден. В `rc-interior.js` ни `if/else`, ни защёлки по флагу нет — событие подписывается безусловно, а `boot()` ничего не проверяет.

## Мелкая находка 2. rc-scroll.js: слушатель rc:lang на window никогда не сработает — мёртвый код, выглядящий как двойная регистрация

Файл: `assets/rc-scroll.js:461-462`

```js
addEventListener("rc:lang", function () { setTimeout(collect3D, 60); });
document.addEventListener("rc:lang", function () { setTimeout(collect3D, 60); });
```

Событие `rc:lang` рассылается в `assets/rc-app.js:199`:
```js
document.dispatchEvent(new CustomEvent("rc:lang", { detail: { lang: v, t: t, blocks: blocks } }));
```
— без `bubbles: true` (по умолчанию `bubbles: false`), и диспатчится оно НЕ на `window`, а на `document`. События, у которых `bubbles` не включён, не поднимаются от `document` до `window` вообще (фаза всплытия не выполняется), поэтому строка 461 (голый `addEventListener`, то есть подписка на `window`) никогда не получит это событие — рабочей остаётся только строка 462 (`document.addEventListener`).

Это подтверждается собственным комментарием разработчиков в другом месте того же кода, `assets/rc-app.js:554-555`:
```js
/* Слушаем на document: событие rc:lang рассылается именно там и не всплывает
   до window, поэтому подписка на window молча не срабатывала. */
```
и там же (rc-app.js:557) подписка сделана правильно, только на `document`.

Практического вреда нет — `document.addEventListener` в той же паре строк отрабатывает исправно, `collect3D()` вызывается один раз, а не два. Но строка 461 — нерабочий, ничего не делающий код, который на вид выглядит как повторная подписка (кандидат на "двойной обработчик"), а по факту не срабатывает никогда. Тот же паттерн — на строках `assets/rc-flight.js:200-201`:
```js
doc.addEventListener("rc:lang", relang);
addEventListener("rc:lang", relang);
```
(строка 201 тоже не сработает по той же причине).

## Подозрения (не доказаны путём до срабатывания, для протокола)

- `assets/rc-desk.js`: `homeForms(unpin)` без аргумента `unpin` не снимает `pinHeight` даже когда форма физически возвращена в разметку раньше срока (обработчик клика по `.js-callback` вне пульта, `rc-desk.js:568-573`, вызывает `homeForms()` без `unpin`). Отдельно это не ломает вёрстку сразу — `minHeight` снимается позже, когда `frame()` увидит `on === false` и вызовет `homeForms(true)`. Не нашёл сценария, где это «позже» не наступает, поэтому не привожу как находку.
- `assets/rc-i18n.js` / `assets/rc-app.js`: явных расхождений ключей словаря RU/EN с разметкой (`data-i18n`) и с динамическими `t("...")` не найдено — все проверено сверкой множеств ключей.
