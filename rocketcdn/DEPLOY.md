# Rocket CDN · развёртывание на сервере

Что здесь лежит и как это поднять на боевом домене `rocketcdn.ru`.
Стек намеренно простой: статика плюс PHP, никакой базы данных.
Хватает любого хостинга с PHP 7.4 и выше.

`https://rocketcdn.ru`, `http` уводит на `https` перенаправлением.

## 0а. Телеграм на российских площадках

С этого сервера имя `api.telegram.org` резолвится в адрес, до которого
маршрута нет: и по IPv4, и по IPv6 соединение не устанавливается. Живым
оказался `149.154.167.220`.

Чинить руками ничего не нужно. `config.php` при неудаче перебирает
известные адреса Телеграма, рабочий запоминает в `data/tg_ip.txt` и дальше
ходит сразу по нему. Свой список можно задать ключом `tg_ips`, а если
площадка закрыта целиком - прописать `tg_proxy` (обычная строка прокси
для curl).

## 3. Секреты: файл `config.local.php`

В git его нет и быть не должно. Создайте руками рядом с `config.php`:

```php
<?php
return [
    'admin_key' => 'ПРИДУМАЙТЕ_ДЛИННЫЙ_ПАРОЛЬ',   // вход в admin.html
    'site_url'  => 'https://rocketcdn.ru',
    'lk_url'    => 'https://lk.rocketcdn.ru',

    // Почта: ящик Gmail и пароль приложения на 16 знаков
    'mail_user' => 'ваш-ящик@gmail.com',
    'mail_pass' => 'xxxx xxxx xxxx xxxx',
    'mail_name' => 'Rocket CDN',
    'mail_to'   => 'куда-присылать-заявки@gmail.com',

    // Токен бота @rocket_cdn_bot от @BotFather
    'tg_token'  => 'ТОКЕН_БОТА',

    // Кому доступна админская часть бота
    'tg_admins' => [1966985736, 6547482131, 581327337],

    // Необязательно: увести папку с заявками выше корня сайта.
    // Пригодится, если правила веб-сервера настроить не получается.
    // 'data_dir' => '/var/www/rocketcdn-data',

    // Если сайт стоит за Cloudflare или своим прокси, перечислите его
    // адреса. Только им доверяются заголовки X-Forwarded-For и подобные,
    // иначе ограничение частоты обходится одной строкой в curl.
    // 'trusted_proxies' => ['203.0.113.10'],
];
```

**Пароль админки менять обязательно.** Пока в конфиге стоит значение по
умолчанию `rocket2026`, все закрытые разделы API отвечают отказом: заявки
с персональными данными не должны открываться чужим паролем из репозитория.

```bash
chmod 640 config.local.php
chown root:www-data config.local.php
```

Пароль приложения Google берётся так: аккаунт Google → включить двухэтапную
аутентификацию → «Пароли приложений» → создать → скопировать 16 знаков.
Обычный пароль от почты не подойдёт.

## 4. Веб-сервер

### Apache
`.htaccess` уже лежит в папке, нужен включённый `AllowOverride All`.

### Nginx + PHP-FPM

```nginx
server {
    listen 443 ssl http2;
    server_name rocketcdn.ru www.rocketcdn.ru;
    root /var/www/rocketcdn;
    index index.html;

    ssl_certificate     /etc/letsencrypt/live/rocketcdn.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/rocketcdn.ru/privkey.pem;

    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options SAMEORIGIN;
    add_header Referrer-Policy strict-origin-when-cross-origin;

    # служебное наружу не отдаём
    location ^~ /data/                       { deny all; }
    location ~ ^/(config|config\.local|lib_report|cron|bot)\.php$ { deny all; }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    location ~* \.(woff2|png|jpg|svg|webp)$ { expires 30d; access_log off; }
    location ~* \.(css|js)$                 { expires 7d; }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}

server {
    listen 80;
    server_name rocketcdn.ru www.rocketcdn.ru;
    return 301 https://$host$request_uri;
}
```

Сертификат: `certbot --nginx -d rocketcdn.ru -d www.rocketcdn.ru`.


```cron
# бот: проверяет сообщения раз в минуту, внутри крутится шесть циклов по 9 секунд
```


## 6. Бот и общий чат

1. Токен `@rocket_cdn_bot` положить в `config.local.php`.
2. Написать боту `/start` в личку - появится нижнее меню.
3. Добавить бота в общий чат и дать ему право писать.
4. В нужной теме чата написать `/bindchat` - туда пойдут заявки.
5. Разложить остальное по темам:
   - в теме ошибок: `/bindtopic errors`
   - в теме аналитики: `/bindtopic stats`
   - в теме форм: `/bindtopic forms`

Привязка пишется в `data/bindings.json`, конфиг руками править не нужно.
Пока чат не привязан, все уведомления идут администраторам в личку.

Мини-приложение: в `@BotFather` → бот → *Bot Settings* → *Menu Button* →
*Configure menu button* → ссылка `https://rocketcdn.ru/app.html`, название
«Rocket CDN». Кнопка в нижнем меню бота работает и без этой настройки.

## 8. Как менять содержимое

- **Тексты заголовков и показателей** - админка, вкладка «Тексты сайта».
  Сохраняется в `data/content.json`, сайт подхватывает сразу.
- **Продукты, преимущества, сценарии, вопросы** - там же, блоком JSON.
- **Точки присутствия** - файл `assets/rc-geo.js`, строка вида
  `["Город", широта, долгота, регион, флаги]`.
  Регион: `0` Россия и СНГ, `1` Азия и Восток, `2` Европа,
  `3` Северная Америка, `4` Южная Америка.
  Флаги складываются: `1` облако, `2` защита, `4` скоро. Ноль означает обычный узел.
- **Ссылка кнопки регистрации** - `lk_url` в `config.local.php` и адрес
  `https://lk.rocketcdn.ru` в `index.html`.

## 10. Сертификат: выпускается сам

На сервере лежит `/usr/local/sbin/rocketcdn-tls.sh`, его запускает
`/etc/cron.d/rocketcdn-tls` раз в десять минут. Скрипт ничего не делает,
пока `rocketcdn.ru` указывает на чужой адрес. Как только записи `A`
переведут на этот сервер, он сам вызовет certbot, включит перенаправление
с http на https и пришлёт сообщение в тему аналитики. После успеха
отключается сам, попыток не больше двенадцати, чтобы не упереться в
ограничения Let's Encrypt.

Посмотреть, как идут дела:

```bash
cat /var/log/rocketcdn-tls.log
cat /var/lib/rocketcdn-tls.state   # done - сертификат уже есть
```

Выпустить руками, не дожидаясь расписания:

```bash
sudo certbot --nginx --redirect -d rocketcdn.ru -d www.rocketcdn.ru
```

Продление берёт на себя `certbot.timer`, он ставится вместе с пакетом.

## 12. Что площадка делает сама

`cron.php` крутится раз в час и, кроме утреннего отчёта, взял на себя ещё три
дела.

**Напоминает про забытые заявки.** Заявка со статусом «новая», которая висит
дольше трёх часов, попадает в сообщение в тему форм. Про одну и ту же заявку
напоминаем один раз, работает с 9 до 21. Порог меняется ключом
`lead_remind_hours` в `config.local.php`, ноль выключает напоминания.

**Смотрит за здоровьем.** Раз в сутки в 10:00 проверяет место на диске, право
на запись в папку заявок, срок сертификата и число сбоев связи с Телеграмом.
Если что-то не так, пишет в тему ошибок. Молчит, когда всё в порядке.

**Делает резервную копию.** Каждый день кладёт в `data/backup/ГГГГ-ММ-ДД.json`
заявки, привязки чата и тексты сайта. Держит четырнадцать копий, старые удаляет.
Восстановление: взять нужный файл и положить его содержимое обратно в
`leads.json`, `bindings.json` и `content.json`.

Срок сертификата PHP берёт из `data/cert.json`, а кладёт туда дату корневой
скрипт `/usr/local/sbin/rocketcdn-cert.sh` (расписание в `/etc/cron.d/rocketcdn-tls`).
Папку `/etc/letsencrypt` сайту не открываем: рядом с сертификатом лежит закрытый ключ.

Вкладка «Состояние» в админке показывает всё это одним экраном: сколько заявок
без ответа и сколько ждёт самая старая, когда был отчёт и резервная копия,
сколько дней осталось сертификату, сколько свободно на диске и через какой
адрес сейчас ходит бот.

## 13. Запас прочности сцен на WebGL

На странице три сцены: ракета, глобус и стойка. Браузер вправе отобрать
контекст: на айфоне это случается при нехватке памяти или когда контекстов
слишком много. Раньше холст в этом случае чернел навсегда.

`assets/rc-gl.js` держит счётчик и страховку. Бюджет считается от устройства:
одна сцена на слабом, две на телефоне, три на планшете, четыре на настольном.
Сцена сверх бюджета просто не заводится. Если контекст всё же отобрали, сцена
останавливается и убирается с глаз: ракета исчезает, стойка прячет свой блок,
трёхмерный глобус подменяется плоским. Страница продолжает работать, событие
уходит в аналитику меткой `glloss`.

## 14. Скорость: что где грузится

Критический путь до готовности разметки - около 600 КБ: стили, шрифт,
логотипы, свои скрипты. Объёмный слой (three.js на 670 КБ плюс три сцены)
в него не входит: `rc-gl.js` тянет его после события `load`, в простой
браузера или на первое касание экрана. Замер на боевой сборке: разметка
готова на 1210 мс, `three.js` стартует на 1517 мс, то есть уже после.

Кому объём не положен - не платит за него ни байтом. При включённой в
системе экономии движения библиотека не качается вообще, сайт работает на
плоском глобусе, ракета скрыта, весь текст и все ленты на месте.

Первому экрану объём не нужен: там плоский глобус на обычном холсте.

## 15. Разметка для поисковиков

В `index.html` четыре блока `application/ld+json`: `Organization`,
`WebSite`, `Service` с перечнем продуктов и `FAQPage` с восемью вопросами.

**Важно:** вопросы в `FAQPage` продублированы текстом прямо в разметке,
потому что сам список вопросов рисуется скриптом и в исходном HTML его нет.
Если поменять вопросы через админку, разметку надо поправить руками, иначе
поисковик будет показывать старые ответы. Блок лежит в шапке страницы,
искать по слову `FAQPage`.

## Выкладка из облачной сессии Claude (проверено 17.08.2026)

Прямого SSH из облачной сессии на сервер клиента нет: порт 22 закрыт наружу.
Ходим через VPS-агента OKO, у него доступ есть.

```bash
source <(base64 -d secrets.env.b64)          # ключи в окружение
# обёртка vexec описана в OKO_BOOTSTRAP.md
tar czf /tmp/rc.tgz index.html assets/... # только изменённые файлы
base64 -w0 /tmp/rc.tgz > rc.b64
split -b 60000 -d -a 2 rc.b64 part_          # тело запроса ограничено, шлём частями
for f in part_*; do vexec "printf '%s' '$(cat $f)' >> /tmp/rc.b64"; done
vexec 'base64 -d /tmp/rc.b64 > /tmp/rc.tgz && md5sum /tmp/rc.tgz'   # сверить с локальной суммой
vexec 'sshpass -p "..." scp /tmp/rc.tgz ubuntu@217.19.122.132:/tmp/'
vexec 'sshpass -p "..." ssh ubuntu@217.19.122.132 "
  sudo cp -a /var/www/rocketcdn /var/www/rocketcdn.bak-$(date +%F-%H%M)
  sudo tar xzf /tmp/rc.tgz -C /var/www/rocketcdn
  sudo chown -R www-data:www-data /var/www/rocketcdn"'
```

Копия перед распаковкой обязательна: откат это `cp -a` из `rocketcdn.bak-*`.
После выкладки проверяем боевой curl'ом по каждому новому файлу и дёргаем
`api.php?action=selftest` - он покажет, что почта, бот и папка данных на месте.

## Связь с Телеграмом на этой площадке

Резолвер сервера отдаёт для `api.telegram.org` адрес шестой версии
(`2001:67c:4e8:f004::9`), до которого с площадки сети нет: каждый вызов молча
висел восемь секунд и падал по таймауту. Лечится тремя вещами, все уже в
`config.php`:

1. `CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4` - только четвёртая версия.
2. Перебор известных адресов, найденный запоминается в `data/tg_ip.txt`.
3. Если и они молчат - адрес спрашивается у публичных резолверов по HTTPS
   (`1.1.1.1` и `dns.google`), ответ живёт четверть часа в `data/tg_dns.json`.

Одинаковые жалобы в журнал пишутся не чаще раза в четверть часа с числом
повторов: иначе `errors.log` забивался и в нём терялось важное.
