## 0. КАК ПОЛЬЗОВАТЬСЯ ЭТИМ ФАЙЛОМ И ГДЕ ОН ЛЕЖИТ

(в любом репозитории клиента), мозг агентов, MCP-сервисы и сервер `okoteam.top/key`
должны опираться на него. Если правило встречается и здесь, и в старых записках —

первым.

**Где лежит и как раскатан (правило распространения).**
- Источник правды: `oko-agents/docs/OKO_ПРОДАКШН_БИБЛИЯ.md`.
- Копия в КАЖДОМ репозитории клиента (`docs/OKO_ПРОДАКШН_БИБЛИЯ.md`) — чтобы в любом
  чате Claude по любому клиенту файл был под рукой.
- Ссылка-указатель в шапке `CLAUDE.md` каждого репозитория: «ГЛАВНЫЙ ПАСПОРТ
  ПРОДАКШЕНА — читать `docs/OKO_ПРОДАКШН_БИБЛИЯ.md`». Так его видит любая сессия.
- На сервере: подтягивается на `okoteam.top/key` (единое хранилище знаний).
- В мозге агентов: загружается как знание (тег `production_bible`), чтобы агент
  опирался на него и вне диалога, при сборке касаний, контента и ответов.

**Как обновлять.** Меняется движок, тайминг, норма, промпт-правило — правим ЗДЕСЬ,
затем: `git add` + коммит + пуш в текущую и дефолтную ветку каждого репозитория,
плюс синхронизация на сервер и в мозг. Никаких «правил в переписке» — только в файле.

**Дисциплина чисел.** Все количества (сколько H3 на ролик, сколько 3D, сколько
референсов) и тайминги (сколько секунд генерация) — это НОРМАТИВЫ, а не пожелания.
От них считается ёмкость карты, план на день и себестоимость. Меняются нормативы —
пересчитываем раздел 18.

## 1. КАРТА (GPU-БОКС «МАШИНА ДЕНЕГ»)

Своя видеокарта под ВСЕ генерации без поштучных API: видео, фото, 3D, звук, музыка,
клон голоса, аватар, локальный код-LLM. Смысл — чтобы каждая генерация стоила ноль
сверх аренды карты. Полный технический паспорт карты — `docs/МАШИНА_ДЕНЕГ.md`; здесь
собрано то, что нужно продакшену на каждый день.

### 1.1 Железо
- Карта: **NVIDIA RTX PRO 6000 Blackwell Server Edition** (95 ГБ VRAM), провайдер RunPod,
  дата-центр EU-RO-1, аренда **~$2.09/час**.
- Системная память ~283 ГБ. Постоянный сетевой том хранилища **oko-stack** (250 ГБ,
  EU-RO-1) держит ВСЕ модели: видео, фото, 3D, аудио, код-LLM. Том DC-locked: карта
  поднимается только в EU-RO-1, где лежит том.
- Модели пережили несколько пересборок машины: установщик их не перекачивает, только
  подключает том. Исключение — первый холодный запрос после включения (см. тайминги).

### 1.2 Доступ и запуск через вкладку «Карта» в админке (основной способ для человека)
- **`okoteam.top/admin` → вкладка «Карта»** — единственная кнопочная точка для Даниэля.
  Показывает статус живьём (обновление каждые 5 секунд):
  - 🟢 **Карта работает** — тип GPU, время сессии, накопленная стоимость, простой (X/10 мин);
  - 🟡 **Ищу карту…** — идёт подбор свободного GPU;
  - 🔴 **Не нашёл свободную карту** — все заняты, зови человека (Клода), с причиной;
  - ⚪ **Выключена**.
  - Кнопки **Включить** / **Выключить**.
- Технически кнопки бьют в `api.php?action=gpu&sub=status|start|stop` (за проверкой
  ключа админа), который запускает `python3 /opt/oko-poster/gpu/gpu.py <sub>`.
- **Первое сообщение в code / первая генерация после включения** думает **1-3 минуты** —
  это грузится модель (18 ГБ у код-LLM, веса у видео/фото) с сетевого тома через mmap.
  Дальше всё быстро (тёплый режим держится сутки). Это НЕ поломка, а разовая загрузка.

### 1.3 Авто-старт карты по требованию (без участия человека)
- **Из любого чата Claude / любого проекта клиента:** карта включается САМА в момент
  первого картового вызова (H3, 3D, аватар, Krea, музыка, SFX). Общий модуль
  `core/card.py`: `card.нужна()` (алиас `ensure`) идемпотентно поднимает под, ждёт
  готовности стека, ставит адрес svc в окружение и двигает таймер простоя;
  `card.тронуть()` (`touch`) держит карту живой при активности. Ленивый старт — не на
  входе в сессию, а на первом обращении к генерации, чтобы не жечь зря.
- Вшито в `core/avatar.py`; любой новый картовый вызов первым делом зовёт `card.нужна()`.

### 1.4 Авто-поиск замены (карту отобрали / все заняты)
- Нажал «Включить» (или код вызвал старт) → в состоянии ставится флаг `want_on=True`.
- Свободного GPU нет («no instances») → статус `searching`, флаг остаётся, сторож
  (cron раз в минуту) сам зовёт старт снова — **добивает слот, пока не поднимет**.
- При старте перебираются **7 типов GPU** в EU-RO-1/EUR-IS-1: Blackwell Server /
  Workstation / Max-Q, H100 80GB, H100 PCIe, L40S, RTX 6000 Ada. Это авто-подбор замены.
- **Если за 20 минут слот не нашёлся** (`search_giveup_minutes`) — поиск сдаётся,
  ставится `search_failed` с причиной, статус в админке = «Не нашёл, зови человека».
- Ручной «Выключить» ИЛИ авто-стоп по простою → `want_on=False`, карта остаётся
  выключенной, сама не воскресает.

### 1.5 Авто-выключение по простою (экономия)
- **Простой 10 минут → карта гаснет сама** (`idle_stop_minutes=10`). Защитное окно
  на загрузку стека — 15 минут (`grace_minutes=15`).
- **Простой считается по ДВУМ источникам сразу:** очередь генерации (ComfyUI) И
  активность в OpenCode (свежесть файлов сессии кода). Пока пишешь в code или гонишь
  генерацию — карта живёт и НЕ вырубается посреди работы; как обе линии замолчали на
  10 минут — гаснет. Проверка активности OpenCode — `_opencode_active` в `gpu.py`.
- Сторож — cron `* * * * * python3 /opt/oko-poster/gpu/gpu.py watchdog`.

### 1.6 Тайминги карты (замерено на Blackwell 01.09.2026)
| Что | Режим | Время |
|---|---|---|
| Холодный старт (первый запрос) | загрузка весов с тома | +~150 секунд разово |
| H3 видео 5 секунд | 4 шага turbo | **72 секунды** (тёплый) |
| H3 видео 5 секунд | 8 шагов | 120 секунд |
| 3D-объект | Hunyuan3D / TripoSplat / SAM 3D | **15-30 секунд** |
| Аватар-вставка 3.24 секунды | InfiniteTalk 4 шага | ~32 секунды |
| SFX 8 секунд | Stable Audio 3 | ~4 секунды |
| Фото | ChatGPT в браузере | ~1-2 минуты |
| Код-LLM (Qwen3-Coder 30B) | тёплый | 95-129 токенов/с |
| Полный ролик (только карта) | H3 + 3D + аватар + SFX | **~6-12 минут** серийно |

### 1.7 Экономика карты
- Карта горит только когда работает: **~$2.09/час**. Автостоп через 10 минут простоя.
- Полный ролик ест ~6-12 минут карты → **~$0.2-0.4 карты на ролик** сверх аренды.
- День на 30-60 роликов = ~4-9 часов серийной генерации = **~$9-19/день карты**.
- Всё, что через браузер (ChatGPT-фото, ElevenLabs-голос) — вне карты, по подписке, ноль.

### 1.8 Ёмкость (сколько проектов тянет одна карта)
- Одна карта — серийная (одна генерация за раз).
- При реальных нормах на ролик (см. раздел 11): H3 3-5 × 72с + 3D 3-10 × 15-30с +
  аватар (30% роликов) 3-4 × 32с + SFX 3-10 × 4с ≈ **6-12 минут карты на ролик**.
- **Одна карта комфортно тянет 5-10 проектов × 5-6 роликов/день.** Даже 60 тяжёлых
  роликов = ~9 часов серийной генерации. Упрёмся в пик — фолбэк Runway или вторая карта.

### 1.9 Жёсткие правила карты
1. Держать карту НЕ дольше работы: закончил — «Выключить» (или сама через 10 минут).
2. Секьюр-том oko-stack держит все модели — НЕ качать заново при перезапуске.
3. Community-под БЕЗ тома монтировать нельзя (для аватара исключение — 6 файлов
   InfiniteTalk можно докачать на community, ~26 ГБ, см. раздел 8 и `МАШИНА_ДЕНЕГ.md`).
4. Платные поштучные API не трогаем (Higgsfield off, Gemini paid off, OpenAI off).

## 3. ВИДЕО №1 — H3 (MiniMax FL2VA) — ОСНОВНОЙ ДВИЖОК ВИДЕО НА КАРТЕ

### 3.1 Что это и под что
- **H3 = MiniMax FL2VA** — «First+Last frame → Video+Audio». Модель берёт СТАРТОВЫЙ кадр
  (`first_frame`) и, опционально, ФИНАЛЬНЫЙ кадр (`last_frame`) и генерит между ними
  видео, попутно синтезируя звук. Это два референс-кадра из ChatGPT/Krea.
- Под что: реф-driven сложные сцены, эффекты, бренд-ревилы, оживление статичных
  картинок, hero-кадры, переходы между двумя состояниями объекта/сцены, динамика
  вставок в монтаж. Это ОСНОВНОЙ источник сгенерированного видео.

### 3.2 Точная обвязка (ноды и файлы модели — не менять)
- UNETLoader: `minimax_h3_fl2va_pruned_fp8_scaled.safetensors`, weight_dtype `default`.
- CLIP: `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`, type `minimax`.
- VAE видео: `minimax_h3_video_vae_fp16.safetensors`; VAE аудио: `minimax_h3_audio_vae_fp32.safetensors`.
- turbo-LoRA: `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` (strength 1.0).
- Нода сдвига: `MiniMaxH3SigmaShift`, shift_video 3.0, shift_audio 3.0.
- Нода видео: `MiniMaxH3ImageToVideo` — входы `clip`, `vae`, `prompt`, `width`, `height`,
  `length`, опц. `first_frame` + `last_frame` (ДВА референс-кадра).
- Негатив: `ConditioningZeroOut` (обнулённый позитив).
- KSampler: cfg 1.0, sampler `euler`, scheduler `simple`, denoise 1.0, `steps` = 4 или 8.
- Декод: `VAEDecode` (видео) + `VAEDecodeAudio` (звук) → `CreateVideo` (fps 24) → `SaveVideo` (mp4 h264).

### 3.3 Скорость и режимы (замер Blackwell, 5с клип 1344×768, тёплый)
- **4 шага turbo = 72 секунды — ОСНОВНОЙ режим на поток.** Качество почти не отличается
  от 8 шагов (проверено на кадрах: детализация, композиция, эффекты, динамика совпадают).
- 8 шагов = 120 секунд — только под максимум-детализацию финалку, когда 4 шага на глаз
  проседают.
- Холодный старт (первый ролик после включения карты) +~150 секунд разово — грузятся
  веса H3 (fp8) и энкодер qwen3vl_32b.
- **Дефолт в коде — 4 шага** (`oko.py video` даёт video→4 шага, photo остаётся 8).

### 3.4 Формат клипа
- Горизонт (пост/сайт/YouTube): 1344×768 (16:9).
- Вертикаль (рилс/сторис/TikTok): 768×1344 (9:16), флаг `--vertical`.
- Длина: 124 кадра (≤5с) / 243 кадра (до ~10с) при 24 fps.

### 3.5 Промпт H3 — ЭФФЕКТ-DRIVEN (выстрадано на кадрах 01.09)
Главное правило, добытое сравнением кадров: **эффект, а не заливка.** Гнать
расходящиеся кольца энергии, плазму, шок-волны, брызги, дым, раскал ядра, объёмный
свет; при этом тело/объект оставлять ЧИТАЕМЫМ (стекло/материал/лицо), НЕ пересвечивать
свечением целиком. «Кольцо/плазма + раскал ядра» выигрывает у «подсветить весь объект».
- Промпт английский, от 2000 знаков, 10+ параметров: сцена, движение камеры
  (dolly / orbit / pull-back / push-in), материалы и фактуры, свет с направлением,
  частицы/дым/блики, цвета бренда в HEX, движение ОБЪЕКТОВ сцены (не всего кадра),
  настроение, качество 4k, cinematic.
- Анимируем объекты сцены, а не весь кадр целиком — так реалистичнее.

### 3.6 Норма H3 на ролик
- **3-5 генераций H3 на ОДИН монтаж ролика (минимум 3).** H3 всегда первый; Runway
  подключаем ТОЛЬКО если очередь H3 на карте занята.

### 3.7 Как запускать
- Один кадр: `python3 oko.py video "<английский промпт 2000+>" --ref кадр.png --steps 4 --sec 5 [--vertical]`.
- Два кадра (first+last): свой раннер (`run_h3.py` из истории аватар-чата), который в
  графе задаёт и `first_frame`, и `last_frame`. Это штатный режим FL2VA — старт-кадр
  фас, финал-кадр другой ракурс/состояние, между ними сложное движение с эффектами.
- Файл `oko.py` живёт на томе `/workspace/projects/oko.py` — правки переживают перезапуск.

### 3.8 Пошагово (как делать H3-вставку в ролик)
1. Определяем по сценарию, где в ролике нужен генеративный кадр (обычно 3-5 точек).
2. Готовим 1-2 референс-кадра под каждую точку (ChatGPT/Krea, однотонный/дизайнерский фон).
3. Пишем эффект-driven промпт 2000+ (см. 3.5), задаём формат (верт/гориз) по площадке.
4. Гоним 4 шага (72с). Если это финалка и хочется максимум — 8 шагов (120с).
5. Проверяем кадрами: держится ли материал объекта, читается ли эффект, нет ли пересвета.
6. Кладём клип в монтаж рядом со стоком/наложениями/3D.

### 3.9 Грабли H3
- Слишком короткая длина под фразу/движение — рвётся динамика; держи 124 кадра под 5с.
- Пересвет всего объекта заливкой — теряется материал; гони кольца/плазму, не заливку.
- 8 шагов дороже вдвое по времени при почти том же качестве — на поток бери 4.

### 5.6 Разнообразие фото (правило владельца)

## 7. 3D — ПРОВЕРЕНО ЖИВЬЁМ 02.09.2026 (замеры на карте, не теория)

### 7.0 ОДНА КОМАНДА, БОЛЬШЕ НИЧЕГО НЕ ПРИДУМЫВАТЬ
```
python3 /workspace/gen3d.py <фото.png> <слаг> <материал>
# материал: металл | глянец | матовый | кожа | дерево | камень | авто
```
Внутри: TripoSplat → SplatToMesh → децимация QEM → снятие unlit → PBR → нормализация.
В коде агента: `oko.py model3d <фото> --ref <материал>`; ядро — `g_object3d` + `_finish_glb`.

### 7.1 ЗАМЕРЫ (реальные)
| что | время |
|---|---|
| модель на ТЁПЛОЙ карте | **12-24 секунды** |
| первая модель после включения карты | 60-85 секунд (грузятся веса) |
| финиш материала (PBR + габарит) | 0.1 секунды |
| вес готовой модели | 7-9 МБ при 147-150k треугольников |

Чтобы держаться в 30 секундах — карта должна быть ТЁПЛОЙ. Пачку объектов гнать подряд,
не давая карте уснуть (простой 10 минут её гасит).

### 7.2 ТРИ ПРИЧИНЫ, ПОЧЕМУ 3D ВЫХОДИЛО ПЛОХО (найдены и закрыты)
1. **Серые модели.** Путь Hunyuan3D даёт форму БЕЗ цвета: `baseColorFactor 0.22`, textures 0.
   Цвет живёт только в сплате. Поэтому основа — TripoSplat → SplatToMesh (цвет в вершинах, COLOR_0).
2. **Неживой плоский вид.** ComfyUI `SaveGLB` ставит расширение **`KHR_materials_unlit`** —
   рендер БЕЗ света: ни бликов, ни объёма, материал не читается. Снимать обязательно,
   иначе никакой реализм не появится. Делает `_finish_glb`.
3. **Рваньё и «осколки».** `DecimateMesh` в режиме `midpoint` рвёт меш (было 0 граничных
   рёбер — стало 79 306). Использовать **`qem`** с `feature_edge_quadric_weight` (сохраняет
   острые рёбра). Для монтажа можно вообще не децимировать: вес там не важен.

### 7.3 ВХОД РЕШАЕТ ГЕОМЕТРИЮ (главное правило)
3D делается ТОЛЬКО из фото-референса. Из текста реализма не будет: текст сначала
превращаем в реалистичное фото (ChatGPT), и уже фото идёт в 3D.

**Работает:** один предмет, ракурс 3/4 (видно две-три грани), объект целиком с полями,
фон простой или вырезан, ровный мягкий свет, всё в фокусе.
Проверено: ключ, часы, станция — настоящий объём.

**Не работает:** фронтальный кадр фасада или стены — выходит плита, даже если фон вырезан.
Проверено: дом, башня, стена почтовых ящиков (88% рваных рёбер).
Для здания фронтально — снимать в 3/4 либо мультивью (`Hunyuan3Dv2ConditioningMultiView`).

### 7.4 ПРОМПТ РЕФЕРЕНСА ПОД 3D (английский, от 2000 знаков)
Один объект на бесшовном светло-сером фоне · ракурс три четверти сверху · объект целиком,
поля со всех сторон, ничего не обрезано · материалы честно (фактура, зерно металла, фаска) ·
мягкий верхний свет плюс заполняющий, без жёстких бликов и засветов · f/11, всё в фокусе,
без размытия · без текста, логотипов, реквизита и отражений окружения.
ОБЯЗАТЕЛЬНО `PROJECT=<слаг>` при вызове драйвера ChatGPT, иначе он возьмёт чужую картинку
из общего чата `default` (реальный случай: вместо часов пришёл баннер «17 семей на весь дом»).

### 7.5 МАТЕРИАЛЫ (PBR, ставятся за 0.1 секунды)
| материал | metallic | roughness | под что |
|---|---|---|---|
| металл | 0.90 | 0.28 | сталь, латунь, техника, украшения |
| глянец | 0.05 | 0.25 | пластик, стекло, лак, косметика |
| матовый | 0.00 | 0.85 | ткань, бумага, резина |
| кожа | 0.00 | 0.65 | сумки, обувь, салон |
| дерево | 0.00 | 0.70 | мебель, интерьер |
| камень | 0.00 | 0.80 | бетон, кирпич, керамика |

### 7.6 КУДА ИДЁТ РЕЗУЛЬТАТ
- **Сайт / просмотр:** GLB на `okoteam.top/3d/` (страница на `model-viewer`, крутится

## 8. АВАТАР — InfiniteTalk (говорящая голова, вставки под монтаж)

### 8.1 Идея (правило владельца)
На весь ролик нужна НЕ минута говорящей головы, а **8-12 секунд аватара** — 2-3 куска
по ~3.24с, вставленных в монтаж рядом с B-roll, наложениями, инфографикой, 3D, стоком.
Сценарий заранее говорит, где кусок аватара (обычно начало/середина/конец). Каждая
вставка независима: свой кадр (ракурс+фон), своя озвучка, своё движение/взгляд, свой seed.

### 8.2 Модель и обвязка
- **InfiniteTalk** (Wan2.1 I2V база + патч). Модуль `core/avatar.py` (`собрать`, `вставка`).
- База `wan2.1_i2v_480p_14B_fp8_scaled` (weight_dtype `fp8_e4m3fn_fast`), патч
  `wan2.1_infiniteTalk_single_fp16` (нода ModelPatchLoader), аудио-энкодер ТОЛЬКО
  `wav2vec2-chinese-base_fp16` (english даёт ошибку размерности), LoRA
  `lightx2v_I2V_14B_480p_cfg_step_distill_rank64` + **cfg=1 + 4 шага**, ModelSamplingSD3
  shift 8. clip_vision НЕ нужен. 25 fps, чанк 81 кадр (3.24с). start_image = кадр,
  audio_encoder_output = 16кГц wav.
- S2V и Dancer НЕ используем (S2V «видно нейронку», Dancer мылит).

### 8.3 Пайплайн аватара (полный, как договорились)
1. **Паспорт лица клиента (одна генерация, постоянный).** Клиент даёт 3-4 ракурса своего
   фото → одной генерацией в GPT собираем **паспорт лица** (эталонный референс). Дальше
   он ПОСТОЯННО используется как реф, чтобы генерить фото клиента с разной одеждой, фоном,
   ракурсом, локацией. Это «паспорт ракурсов».
2. **Ракурсы под конкретный ролик.** На каждый монтаж с аватаром генерим по смыслу ролика
   **2-3 ракурса**: либо одна комната с разных ракурсов, либо разные фоны/локации по
   смыслу. Нужен человек 1:1 в конкретной локации — при генерации референса прикладываем
   **паспорт лица + объект/комнату/фон**, на котором должен быть аватар.
3. **Озвучка целиком.** Генерим ВСЮ озвучку ролика в ElevenLabs (клон клиента/лучший голос).
4. **Оживление кусками.** Прикладываем кусок аудио + ракурс-референс → InfiniteTalk оживляет.
   3-4 таких куска. Формат кадра задаёт формат клипа (вертикаль 480×832 под рилс).
5. **Монтаж.** Вставляем 3-4 аватар-куска в монтаж, губы 1:1 совпадают с озвучкой.

### 8.4 КРИТИЧНО: синхрон губ (выстрадано)
- **Длина видео ОБЯЗАНА покрыть всю речь**, иначе губы обрываются до конца слов
  (рассинхрон). Длину берём из ТОЧНОЙ длительности wav (PCM), не по mp3 (VBR занижает).
- **Длина принимается только вида 4k+1** (81=4·20+1, 85, 89, 97…): иначе einops падает
  на аудио-ноде. В коде: `need=ceil(dur*25)+3; длина=max(81,need); while (длина-1)%4: длина+=1`.
- Драйв губ и звук ролика — от ОДНОЙ дорожки (wav → mp3), кадр в кадр.

### 8.5 Норма и тайминг
- Аватар — 3-4 куска, примерно **в 30% роликов**, только если клиенту нужен ЕГО аватар.
- Тёплая вставка 81 кадр (3.24с) ≈ 32 секунды (H200/Blackwell). Минута сплошного аватара
  ≈ 10 минут, но реальные 8-12с монтажа = 2-3 куска ≈ 1.5 минуты.

### 8.6 Когда НЕ используем аватар
- **Клиенту не нужен его аватар → аватар вообще НЕ используем.** Ролик собираем чисто на
  генерациях **H3 + Runway (фолбэк) + стоки Envato**.
- Нет референсов объектов → придумываем всё сами без них.
- Есть → лучше использовать: клон голоса + ИИ-аватар ~30% роликов, логотип в референсах,
  объекты/фоны/локации клиента в референсах.

### 8.7 Разное движение/взгляд под текст (правило владельца)
- Не пялиться в камеру весь ролик. Приветствие — взгляд в камеру + жест рукой; объяснение
  — взгляд вбок + жест в сторону; закрытие — лёгкий наклон вперёд + открытый жест. Всё
  через `ITPROMPT` (env драйвера) + разный `ITSEED`. Разные ракурсы/фоны через свой кадр
  на каждую вставку. Одинаковых кусков подряд не бывает.

- Фото-референсы (ChatGPT) — вне карты, параллельно, ~1-2 мин каждая.
- Стоки Envato — вне карты, скачивание.
- Озвучка ElevenLabs — вне карты, браузер/ключ.
- **Итого карты на полный ролик: ~6-9 минут (без аватара ~5-7 мин, с аватаром ~8-10 мин).**

### 11.3 Что вне карты (параллельно, не занимает очередь GPU)
- Фото (ChatGPT/Gemini), озвучка (ElevenLabs), стоки (Envato), сборка монтажа (ffmpeg на VPS).
- Это можно готовить, пока карта гонит видео/3D/аватар.

## 12. ПОЛНЫЕ ПАЙПЛАЙНЫ (пошагово)

### 12.1 РОЛИК С АВАТАРОМ (клиенту нужен его аватар)

4. Паспорт лица клиента (если ещё нет): 3-4 ракурса → одна генерация GPT → постоянный реф.
5. Кадры аватара: 2-3 ракурса/локации под смысл (паспорт + фон/объект в реф при 1:1 локации).
6. Референсы под H3 и 3D: фото с нужными фонами/объектами (2-5 рефов на генерацию видео).
7. Озвучка ВСЕГО ролика в ElevenLabs (клон клиента / лучший голос), темп 1.4х.
8. H3: 3-5 клипов (4 шага, 72с каждый) — эффект-driven, вертикаль.
9. 3D: 3-10 объектов (15-30с каждый) под нишу.
10. Аватар: 3-4 куска InfiniteTalk (кусок озвучки + ракурс), длина 4k+1, губы 1:1.
11. SFX: 3-10 (Stable Audio 3) на каждую анимацию.
12. Стоки Envato под B-roll (70-80% хронометража), уникальные.
13. Монтаж (ffmpeg/reels-machine): сток + наложения + H3 + 3D + аватар-вставки + SFX + музыка + субтитры.
14. Приёмка до 100/100 (раздел 16), правки, публикация.

### 12.2 РОЛИК БЕЗ АВАТАРА (клиенту аватар не нужен)
1-3. Как выше (анализ, сценарий, разметка) — но без аватар-точек.
4. H3: 3-5 клипов (4 шага) — эффекты, hero-кадры, оживление картинок.
5. 3D: 3-10 объектов под нишу.
6. Стоки Envato — основа B-roll.
7. Озвучка ElevenLabs (лучший голос под нишу, клон клиента если есть).
8. SFX 3-10, музыка (Envato → MiniMax).
9. Монтаж (сток + H3 + 3D + наложения + SFX + музыка + субтитры), приёмка, публикация.

### 12.3 КАРУСЕЛЬ (5-10 слайдов, 4:5)
1. Анализ конкурентов, сценарий текста слайдов (хук на первом, воронка на последнем).
2. Фото каждого слайда — ChatGPT (промпт 2000+, текст вшит в сцену, лого + ник/домен + нумерация).
3. Часть слайдов оживить (по картинке H3/Runway) ради вау-эффекта.
4. Приёмка, публикация. Хештеги ТОЛЬКО в описании карусели.

### 12.4 СТОРИС (серия 3-10, 9:16)
1. Сценарий серии, фото каждого кадра ChatGPT (9:16).
2. Часть кадров оживить. SFX/звук ElevenLabs.
3. Хештегов в сторис НЕТ. Приёмка, публикация.

### 12.5 ПОСТ (16:9 или 1:1)
1. Текст с чистого листа НЕ пишем: разбор конкурентов, черновик, прогон по скиллам, humanize.
2. Визуал ChatGPT (разный каждый раз), текст вшит в сцену или заголовок поверх.
3. Премиум-эмодзи по смыслу (1-2), хештегов в TG-постах НЕТ. Приёмка, публикация.

### 12.6 СТАТЬЯ
1. Текст по скиллам (хук, удержание, суть), живой язык. Визуал статьи 16:9 (ChatGPT).
2. Хештегов НЕТ. Приёмка, публикация.

### 12.7 МУЗЫКА
1. Ищем в Envato под настроение/темп/хронометраж. Подошло — берём (лицензия чистая).
2. Не подошло — MiniMax Music на карте (запас Stable Audio 3). Проверка на попадание в ролик.

### 12.8 3D-ОБЪЕКТ
1. Реф-фото с однотонным фоном (ChatGPT/Gemini/Krea, 1 реф или 4 ракурса в одном).
2. Модель: меш (Hunyuan3D) / сплат (TripoSplat) / человек (SAM 3D Body). Порог 0.0, shift 3.
3. `oko.py mesh|splat|human` (15-30с). Реализм — главная ось приёмки. Анимация/риг при надобности.
4. В монтаж или на сайт.

## 13. ПРОМПТ-ИНЖИНИРИНГ (правила промптов по движкам)

### 13.1 Общие правила (для всех визуальных промптов)
- Английский, от 2000 знаков, 10+ параметров. Промпт несёт ВЕСЬ мир сразу:
  сцена + текст + лого + референсы + эффекты + дизайн + свет + моушен + 3D. Ничего не
  наклеено, каждый раз разный.
- Цвета бренда в HEX (у OKO: чёрный #000000 + лайм #9AFF00; у клиента — его палитра).
- Текст на картинке — внутри промпта в кавычках, вшит в дизайн (или осознанно слоем).
- Референсы: лого, товар, лицо, интерьер, локация — по необходимости.

### 13.2 Фото (ChatGPT/Gemini/Krea)
- Сцена, объект, материалы и фактура, свет (направление+мягкость), объектив и глубина,
  композиция и ракурс, цвета HEX, настроение, стиль, свободное место под текст, качество
  (8K, ultra sharp, commercial product photography).

### 13.3 Видео H3 (эффект-driven)
- Движение камеры (dolly/orbit/pull-back/push-in), эффекты (кольца энергии, плазма,
  шок-волны, частицы, дым, блики, раскал ядра), объект остаётся читаемым (материал не
  пересвечивать), движение объектов сцены (не всего кадра), 4k cinematic.

### 13.4 Аватар (движение/взгляд под текст)
- ITPROMPT описывает движение и взгляд куска: приветствие в камеру + жест; объяснение
  взгляд вбок + жест в сторону; закрытие наклон вперёд + открытый жест. Разный ITSEED,
  разные ракурсы/фоны на каждую вставку.

### 13.5 3D
- Реф-фото — чистый объект, однотонный фон, ровный свет, без окружения. Негативный
  промпт против пластиковых лиц. Порог поверхности 0.0, shift 3.

### 13.6 Голос (ElevenLabs v3)
- Интонационные теги в тексте: `[warm]`, `[confident]`, `[curious]` и т.п. Темп 1.4х.
  ОКО — одним словом, ударение на первое О (о́ко).

# 14. АДАПТАЦИЯ ПОД КЛИЕНТА И НИШУ

Одна и та же машина (H3, Runway, ChatGPT, ElevenLabs, аватар, 3D) даёт совершенно
разный результат в зависимости от того, под кого и под какую нишу мы работаем.
Раздел про то, как не выпустить «универсальный» ролик, который не заходит никому.

## 14.1 Первый шаг в любой нише — насмотренность (жёстко, до производства)

Правило владельца: в НОВОЙ нише сначала 50+ крутых референсов, потом производство.
Порядок разбора перед первой единицей контента:

1. **Собрать 10 конкурентов от миллиона подписчиков/просмотров** в нише (Instagram,
   TikTok, YouTube Shorts, Telegram). Не «похожие», а именно топ: у кого ниша
   выстрелила. `core/competitor_pool.find` поднимает каналы и по 30 роликов с
   каждого от миллиона просмотров.
2. **По каждому ролику снять:** формат (говорящая голова / b-roll / скринкаст /
   3D / инфографика), длину, где хук (к 2-й секунде обязателен), первую строку,
   что удерживает, где воронка, какой CTA, какой оффер, какой визуальный приём.
3. **Свести в таблицу** «что общего у топа ниши»: длина, ритм, палитра, тип
   визуала, тон речи, длина предложений, наличие/отсутствие лица, музыка.
4. **50+ статичных референсов** (карусели, посты, сторис конкурентов и топ-
   дизайнеров ниши) — на уровень дизайна, типографики, сетки, цвета.
5. Только после этого — черновик под нашу цель, на этом уровне или выше.

Без этого шага любой ролик — «в вакууме»: технически чистый, но мимо ниши.
Насмотренность в мозге агента живёт тегом `reference`, разбор — тегом `niche_teardown`.

## 14.2 Что настраивается под клиента (карта переменных)

| Переменная | Откуда берём | Куда влияет |
|---|---|---|
| **Ниша** | карточка клиента, competitor_pool | палитра, тон, форматы, длина, музыка |
| **Бренд-цвета** | бриф / сайт клиента / логотип | HEX в каждом промпте, наложения, рамки |
| **Логотип клиента** | материалы репо клиента | реф в промпт (не наш OKO-лого) |
| **Лицо/спикер** | фото клиента (несколько ракурсов) | аватар, реф в фото-промпт |
| **Товар/объект** | фото товара, интерьера, дома | реф в фото/3D, герой сцены |
| **Тон речи** | разбор конкурентов + бриф | ElevenLabs теги, текст сценария |
| **Язык** | бриф (RU/EN/…) | сценарий, субтитры, голос, текст на картинке |
| **Целевое действие** | воронка клиента | CTA, последний слайд, оффер |

Наш OKO-логотип и наш бренд (чёрный + лайм #9AFF00, Bebas Neue + Montserrat) —
это для НАШЕГО контента (okoteam.top, продажи OKO). Для контента КЛИЕНТА берём
ЕГО бренд: его цвета, его логотип, его шрифты. Путать нельзя — на карточке
клиента лаймовый OKO-логотип не ставим, ставим логотип клиента.

## 14.3 Ниша → формат (типовые связки)

- **Недвижимость / интерьеры:** b-roll объекта (Runway облёт по фото) + 3D-план +
  текст-цифры поверх. Аватар-риелтор во вставках. Музыка спокойная премиум.
- **Товар / e-com:** товар героем, H3 с эффектами (вращение, распад на частицы,
  сборка), 3D-модель товара для 360°. Карусель «до/после», «характеристики».
- **Услуги / эксперт (юрист, коуч, врач):** говорящая голова-аватар 8-12с +
  b-roll подложка + инфографика-тезисы. Тон доверительный. Голос тёплый.
- **Ресторан / еда:** макро-съёмка (Envato-сток + Runway оживление), сочные
  цвета, никакого 3D, музыка аппетитная. Сторис «блюдо дня».
- **Авто / техника:** H3 с экшн-эффектами (пыль, блики, скорость), 3D-модель,
  динамичный монтаж, драм-музыка.
- **Бьюти / мода:** чистый свет, кожа/фактура, Runway плавные движения, палитра
  пастель или контраст, аватар-модель.
- **IT / SaaS / стартап:** скринкаст интерфейса + инфографика + 3D-абстракция
  (данные, сеть, ядро), холодный неон, четкая типографика.

Связка — стартовая точка, а не догма. Насмотренность по конкретной нише может
показать, что топ делает иначе — тогда идём за топом.

## 14.4 Клиентский репозиторий как источник настроек

Каждый клиент живёт в своём репо `oko-client-<slug>` (`core/client_repo.py`).
В `materials/` лежат карточка, бриф, конкуренты, Система роста, фото товара/лица,
бренд-гайд. ПЕРЕД производством контента для клиента — читаем `materials/`, а не
выдумываем. Логотип клиента, его цвета, его товар — оттуда. Готовый контент
складываем в тот же репо (`materials/content/<дата>/`), чтобы история осталась.

# 15. КОНТЕНТ-СТРАТЕГИЯ И ПЛАНИРОВАНИЕ ЛЕНТЫ

Отдельные ролики не продают. Продаёт лента: ритм форматов, воронка, регулярность.

## 15.1 Микс форматов (правило «не два похожих подряд»)

Владелец: визуал ВСЕГДА разный. В ленте чередуем:
- рилс говорящая голова (аватар) — экспертность, лицо бренда;
- рилс b-roll + текст — атмосфера, эмоция;
- рилс H3-эффекты — вау, останавливает пролистывание;
- карусель — польза, сохранения, глубина;
- сторис-серия — прогрев, быстрый контакт, опрос;
- пост с одним визуалом — мысль, анонс, оффер;
- статья/лонг — SEO, доверие, экспертиза.

Два рилса подряд одного типа — стоп. Два одинаковых визуальных приёма подряд — стоп.

## 15.2 Воронка в контенте (каждая единица знает свою роль)

- **Верх (охват):** хук-контент, тренды, вау-эффекты, польза без продажи. Цель —
  досмотр, репост, подписка. CTA мягкий («сохрани», «подпишись»).
- **Середина (прогрев):** кейсы, «как мы делаем», разбор боли, до/после,
  закулисье. Цель — доверие. CTA «напиши», «узнай».
- **Низ (конверсия):** оффер, тариф, отзыв, дедлайн, приглашение. Цель — заявка.
  CTA прямой («оставь заявку», «записывайся», ссылка).

Лента без низа не продаёт, лента из одного низа выжигает аудиторию. Баланс
примерно 60/30/10 верх/середина/низ, подстраивается под задачу клиента.

## 15.3 Ритм публикаций

Регулярность важнее объёма. Лучше 1 сильный ролик в день, чем 10 слабых в неделю.
Для контент-завода: план на неделю вперёд (7-14 единиц), с разложенными форматами
и ролями в воронке, чтобы не было провалов и повторов. Публикацию держит
`core/content_engine`, дубли режет `_is_dupe()` по SHA256 первых 400 символов.

## 15.4 KPI и обратная связь

Смотрим: досмотр (retention), удержание на хуке (первые 3с), репосты, сохранения,
переходы, заявки. `mcp__HIGGSFIELD__virality_predictor` даёт прогноз виральности
ДО выпуска — если низко, переделываем хук/первую секунду. После выпуска — реальные
цифры возвращаются в разбор: что зашло, повторяем приём; что нет — убираем.

# 17. ЖИВОЙ ТЕКСТ (humanize, действует ВЕЗДЕ)

Касается всего: переписки, КП, договоров, постов, сценариев, отчётов, кода,
комментариев, коммитов, ответов в чатах Claude Code, описаний под ролики.

## 17.1 Запреты (жёстко)

1. **Длинное тире — НИКОГДА.** Только дефис. Первый признак машины.
2. **Никаких противопоставлений «не X, а Y».** «Это не просто сайт, а система»,
   «дело не в цене, а в объёме» — запрещено. Говорим прямо, одним утверждением.
3. **Никаких иишных структур:** «важно отметить», «стоит отметить», «таким
   образом», «кроме того», «в рамках», «на сегодняшний день», «комплексный
   подход», «индивидуальный подход», «в кратчайшие сроки», «позволяет вам»,
   списки ради списков, заголовок в каждом абзаце, «во-первых, во-вторых».
4. **Обращение к человеку по имени.** Слов «клиент», «заказчик», «пользователь»
   в третьем лице не бывает, даже когда пишем не ему.
5. **Прочитал вслух, звучит как реклама — переписал.**

## 17.2 Как держится в коде

`core/humanize.clean()` чистит каждое исходящее в `core/safe_send.py` и каждый
ответ агента в `core/assistant.py`. `core/humanize.check()` показывает, что не
так. `tests/test_humanize.py` не даёт длинному тире вернуться в репозиторий.
Разбор ВХОДЯЩЕГО текста тире знать обязан (клиенты его пишут) — правило про то,
что пишем МЫ.

## 17.3 Текст в контенте

Сценарий ролика, подпись, текст на картинке, слайды карусели — по тем же
правилам. Живая речь, короткие фразы, обращение к человеку. С чистого листа
текст не пишется никогда: сначала разбор конкурентов и насмотренность, черновик
под цель, прогон по скиллам (хук, сценарий, виральность, психология покупки,
humanize), оценка `oko_scenario_score` от 70, проверка на живой язык.

# 19. ГРАБЛИ И ТИПОВЫЕ ОШИБКИ (написано кровью)

Раздел «не наступай сюда снова». Каждая строка стоила времени и/или конвейера.

## 19.1 Выход в сеть

- **«Не поддерживается в вашей стране» — это НЕ приговор, это выход.** Лечится

  только один аккаунт, пауза 60-180с между роликами, режим Explore.

## 19.2 Runway

- **Две генерации разом = бан.** ОДНА очередь на весь сервер (flock
  `_одна_очередь_runway`). 8 клипов = 8 вызовов подряд, они сами выстроятся.
- **Google не пускает браузер с меткой автоматизации.** Runway — настоящий Chrome
  (не Playwright), экран :95/:99, отладчик 9254, профиль хранит вход. Вход делает
  человек, не автоматизируем.
- **MiniMax убран** (перестал быть безлимитным, жёг кредиты). Модель генерации —
  только Gen-4.5, правки — Aleph 2.0.
- **Формат задаётся первым кадром.** Вертикальный кадр 1080×1920 → клип 9:16 фулл
  без полос. Не пытаться получить 9:16 из горизонтального кадра — будут полосы.

## 19.3 H3 (карта)

- **urllib получает 403 от runpod-прокси** (питоновский User-Agent блокируется).
  Всегда curl subprocess, не urllib, для box svc.
- **Холодный старт +150с** — первый клип после включения карты дольше. Не паника.
- **4 шага — прод-дефолт** (72с, качество владелец одобрил на h3_ac). 8 шагов —
  когда нужно чуть чище, ценой +48с.

## 19.4 Аватар (InfiniteTalk)

- **Смазанная каша = LEN слишком короткий.** LEN должен быть 4k+1 И покрывать всю
  длину wav. `need=ceil(dur*25)+3; длина=max(81,need); while (длина-1)%4: длина+=1`.
- **Мерить длину по PCM wav16, не по mp3.** mp3-длительность врёт, губы разъедутся.
- **Не 4k+1 → einops error.** Округление обязательно.
- **Патч-файл переименован на HF** — качать под ожидаемым именем
  `Wan2_1-InfiniTetalk-Single_fp16.safetensors` (Kijai/WanVideo_comfy/InfiniteTalk).
- **Порядок аргументов в run3.sh:** `run(){ local name=$1 seed=$2 prm=$3; }` —
  сид не читать как промпт.

## 19.5 Карта RunPod и админка

- **STATE в /tmp мешал www-data писать** — перенесено в `/opt/oko-poster/gpu/rt/`
  (0777, файл 666).
- **sudo для okoposter запрещён** — root-файлы правим через docker (okoposter в
  группе docker): `docker run --rm -v /var/www/...:/mnt python:3.12-alpine ...`.
- **Ollama install падал** без zstd — `apt install zstd pciutils lshw` перед
  установкой. Контекст 131072 душил (9 ток/мин) → 32768 + flash attention = 129 ток/с.
- **4-часовой grace маскировал OpenCode-сессии** — убран до 15 мин + детект
  активности OpenCode (`_opencode_active`).
- **Слот карты могут отобрать** — авто-повтор (want_on флаг, ретрай в watchdog),
  сдаётся через 20 мин поиска (search_failed), статус виден в админке (Карта).

## 19.6 Промпты

- **ChatGPT режет промпт короче 2000 знаков.** Драйвер сам добивает до 2010, но
  лучше сразу писать полный: сцена, объект, материалы, свет, оптика, композиция,
  цвета HEX, настроение, стиль, место под текст, качество.

# ПРИЛОЖЕНИЕ D. КАКОЕ ФОТО НА КАКУЮ МОДЕЛЬ И ПОЧЕМУ

- **Фото под H3 (видео со звуком/эффектами):** первый кадр = стартовая сцена,
  последний кадр = финальная (куда пришли). Оба из ChatGPT, один мир, один свет.
  H3 сам достроит движение и звук между ними. Доп-референсы (3-5) держат стиль.
  Почему: H3 интерполирует первый→последний, кадры должны быть согласованы.
- **Фото под Runway (движение):** кадр-герой, по которому оживляем ДВИЖЕНИЕ
  объектов сцены (не весь кадр). Вертикальный кадр → клип 9:16 без полос.
  Почему: Runway двигает сцену, формат берёт от кадра.
- **Фото под аватар:** лицо клиента в нескольких ракурсах, чистое, ровный свет.
  Почему: InfiniteTalk строит говорящую голову, разные ракурсы = разные вставки.
- **Фото под 3D:** чистый объект, однотонный фон, ровный свет, без окружения.
  1 фото для mesh, 4 ракурса когда нужна точность формы.
  Почему: модель реконструирует геометрию, мусор в фоне ломает форму.
- **Фото под карусель/пост:** финальный визуал сразу с вшитым текстом и брендом.
  Почему: это конечный слайд, не заготовка под видео.

- `gpu.py status` — работает / ищу (`searching`) / не нашёл (`search_failed`) / выключена,

- Из облачного чата — через `vexec` (мост VPS). Root-файлы веб-корня правим через docker

## G.8 Диагностика: как понять, что модель плохая, до показа владельцу

```python
# читаем JSON-чанк GLB и смотрим три вещи
COLOR_0 в attributes        # есть цвет в вершинах? нет - модель серая
KHR_materials_unlit         # осталось? тогда рендер без света, всё плоское
baseColorFactor             # [0.22,0.22,0.22] = серый Hunyuan, брак
```
Плюс граничные рёбра: у сплат-меша до децимации их 0 (замкнутый), после `midpoint` - десятки тысяч.

Превью рисовать ТОЛЬКО поверхностью (заливка треугольников). Рендер точками по вершинам
врёт: модель выглядит рыхлой и полупрозрачной, хотя она плотная и замкнутая.

## G.9 Грабли

- Драйвер ChatGPT без `PROJECT` берёт чужую картинку из чата `default`.
- `KHR_materials_unlit` убивает весь реализм.
- `DecimateMesh midpoint` рвёт меш.
- Мост `vexec` режет ответ на 45 000 байт.
- Сторож карты считает простой только по очереди ComfyUI: пока идут скрипты и скачивания,
  для него простой, и карта гаснет посреди работы. Гнать объекты пачкой.
- `/var/www/okoteam/3d` должен быть 777, иначе php-приёмник не запишет файл.
- Фоновый запуск через svc (`nohup`) часто умирает: длинные задачи запускать `setsid` или синхронно.
