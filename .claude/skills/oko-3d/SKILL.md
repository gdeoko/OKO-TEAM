# 3D OKO: фото → модель за 12-24 секунды

Проверено живьём 02.09.2026 на карте RTX PRO 6000 Blackwell. Всё ниже - замеры, не теория.
Ничего не придумывать заново: тут готовые команды и цифры.

## 0. ОДНА КОМАНДА

```bash
# на боксе (карта), из /workspace
python3 gen3d.py <фото.png> <слаг> <материал>

# пример
python3 gen3d.py watch2.png chasy металл
```

Материалы: `металл` · `глянец` · `матовый` · `кожа` · `дерево` · `камень` · `авто`

Внутри команды: TripoSplat → SplatToMesh → децимация QEM → снятие `KHR_materials_unlit`
→ PBR-материал → нормализация габарита → GLB в `/workspace/ComfyUI/output/web/<слаг>_00001_.glb`.

Через агента: `oko.py model3d <фото> --ref <материал>` (ядро - `g_object3d` + `_finish_glb`).

## 1. ЗАМЕРЫ (реальные, не обещания)

| что | время |
|---|---|
| модель на ТЁПЛОЙ карте | **12-24 секунды** |
| первая модель после включения карты | 60-85 секунд (грузятся веса) |
| финиш материала + габарит | 0.1 секунды |
| заливка на сайт (9 МБ, 2 чанка) | 3-5 секунд |
| референс в ChatGPT | 60-80 секунд |

**Полный цикл с нуля (фото + модель + публикация): около 3 минут.**
**Цикл при готовом фото и тёплой карте: 15-30 секунд.**

Чтобы держаться в 30 секундах - карта должна быть ТЁПЛОЙ. Объекты гнать пачкой подряд,
простой 10 минут её гасит. Замеренные веса: 7-9 МБ при 147-150k треугольников.

## 2. ВХОД РЕШАЕТ ГЕОМЕТРИЮ (главное правило)

3D делается ТОЛЬКО из фото-референса. Из текста реализма не будет: текст сначала
превращаем в реалистичное фото (ChatGPT), и уже фото идёт в 3D.

**Работает** (проверено: ключ, часы, станция - настоящий объём):
- один предмет в кадре, ничего лишнего;
- ракурс три четверти, видно две-три грани;
- объект целиком, поля со всех сторон, ничего не обрезано;
- фон простой однотонный или вырезан (RGBA);
- свет мягкий ровный, всё в фокусе (f/11), без жёстких бликов.

**Не работает** (проверено: дом, башня, стена почтовых ящиков - выходит плита):
- фронтальный кадр фасада или стены;
- кадр сцены вместо предмета;
- объект в упор без полей.
Для здания фронтально: снимать в 3/4 либо мультивью (`Hunyuan3Dv2ConditioningMultiView`).

## 3. ПРОМПТ РЕФЕРЕНСА ПОД 3D

Английский, от 2000 знаков. Обязательные блоки: один объект на бесшовном светло-сером
фоне · ракурс три четверти сверху · объект целиком с полями · материалы честно (зерно
металла, фаска, фактура) · мягкий верхний свет плюс заполняющий · f/11, всё в фокусе,
без размытия · 8K, ultra sharp, commercial product photography · без текста, логотипов,
реквизита, отражений окружения, рамок и виньетки.

```bash
cd /opt/oko-poster && PROJECT=<слаг> node chatgpt_web.mjs "$(cat промпт.txt)" /tmp/ref.png
```

**`PROJECT=<слаг>` ОБЯЗАТЕЛЕН.** Без него драйвер пишет в общий чат `default` и скачивает
оттуда ЧУЖУЮ картинку. Реальный случай: вместо часов пришёл баннер «17 семей на весь дом»
из другого проекта, из него вышла плита с русским текстом вместо модели.

## 4. ПАРАМЕТРЫ (менять только осознанно)

**SplatToMesh** (цвет и плотность):
```
resolution 512 · kernel 5 · smooth 1 · level 0.5
min_component 2000 · min_opacity 0.10 · color_sharpen 2.0
```
`min_opacity` ниже 0.05 тянет полупрозрачную дымку, выше 0.15 съедает тонкие детали.

**DecimateMesh** - только `qem`, никогда `midpoint`:
```
placement_mode qem · target_face_count 150000
line_quadric_weight 1.0 · feature_edge_quadric_weight 64.0
feature_edge_min_dihedral_deg 25.0 · clamp_v_to_edge true
```

**MeshSmoothNormals**: `crease_angle 40.0`

**PBR-материалы** (ставит `_finish_glb`, 0.1 секунды):

| материал | metallic | roughness | под что |
|---|---|---|---|
| металл | 0.90 | 0.28 | сталь, латунь, техника, украшения |
| глянец | 0.05 | 0.25 | пластик, стекло, лак, косметика |
| матовый | 0.00 | 0.85 | ткань, бумага, резина |
| кожа | 0.00 | 0.65 | сумки, обувь, салон |
| дерево | 0.00 | 0.70 | мебель, интерьер |
| камень | 0.00 | 0.80 | бетон, кирпич, керамика |
| авто | 0.25 | 0.50 | когда не знаешь |

## 5. ТРИ ПРИЧИНЫ ПЛОХИХ МОДЕЛЕЙ (найдены и закрыты)

1. **Серые модели.** Путь Hunyuan3D даёт форму БЕЗ цвета: `baseColorFactor [0.22,0.22,0.22]`,
   `textures: 0`, `COLOR_0: false`. Цвет живёт только в сплате. Основа - TripoSplat.
2. **Плоский неживой вид.** ComfyUI `SaveGLB` ставит расширение **`KHR_materials_unlit`** -
   рендер БЕЗ света: ни бликов, ни объёма, металл неотличим от картона. Снимать обязательно
   (вместе с записью в `extensionsUsed`), иначе реализма не будет никогда.
3. **Рваньё и «осколки».** `DecimateMesh` в режиме `midpoint` рвёт меш: было 0 граничных
   рёбер, стало 79 306. Только `qem`. Для монтажа можно вообще не децимировать.

Ещё две мелочи, которые ломали работу:
- **Мост `vexec` режет ответ на 45 000 байт** - GLB через него не вытащить. Файлы гонять
  приёмником (раздел 6).
- **Сторож карты считает простой только по очереди ComfyUI.** Пока идут скрипты, рендеры
  или скачивания - для него «простой», и карта гаснет посреди работы.

## 6. ПУТИ, СЕРВИСЫ, ПОРТЫ

```
/workspace/gen3d.py                          единая команда
/workspace/finish3d.py                       unlit + PBR + нормализация габарита
/workspace/projects/oko.py                   ядро (g_object3d, g_splat, _finish_glb, post)
/workspace/ComfyUI/input/                    входные фото
/workspace/ComfyUI/output/web/<слаг>_00001_.glb   готовая модель
/opt/oko-poster/chatgpt_web.mjs              драйвер референсов (VPS)
/opt/oko-poster/gpu/gpu.py                   карта: start | stop | status | watchdog
/var/www/okoteam/3d/                         витрина моделей (777, чтобы php писал)
/var/www/okoteam/3d/up.php                   приёмник заливки (токен в cfg/oko3d_up_token.txt)
```

| порт | что |
|---|---|
| 8188 | ComfyUI на карте (изнутри бокса; снаружи отдаёт 404 на `/view`) |
| 7777 | box svc, заголовок `X-Token`, ответ режется на 45 000 байт |
| 9222 | браузер ChatGPT (VPS) |
| 9254 | браузер Runway (VPS) |

**Заливка модели на сайт** (с карты, чанки по 6 МБ - `post_max_size` 8M):
```bash
SRC=$(ls /workspace/ComfyUI/output/web/<слаг>*.glb | tail -1)
for i in 0 1 2 3; do
  dd if=$SRC bs=1048576 skip=$((i*6)) count=6 2>/dev/null > /tmp/part
  [ -s /tmp/part ] || break
  curl -s -X POST --data-binary @/tmp/part \
    "https://okoteam.top/3d/up.php?tok=<токен>&name=<имя>.glb&i=$i"
done
```

**Витрина:** https://okoteam.top/3d/ - `model-viewer`, крутится пальцем с телефона.
Живые примеры: часы 8.75 МБ / 147k треугольников, ключ 7.38 МБ / 150k.

## 7. КУДА ИДЁТ РЕЗУЛЬТАТ

- **Сайт:** GLB напрямую в `model-viewer` или three.js. Вес для web 60-150k треугольников,
  3-10 МБ. Габарит уже нормализован (центр 0, размер 1.0), камера не окажется внутри модели.
- **Монтаж:** в ролик идёт не GLB, а клип объекта с прозрачным фоном. Модель делается один
  раз на карте, обороты и пролёты рендерятся браузером без GPU → PNG-секвенция → WebM/MOV
  с альфой → слой поверх кадра. Из одной модели сколько угодно ракурсов без карты.

## 8. НОРМА НА РОЛИК

3-10 объектов, минимум 3. Референсов: обычно 1 фото на объект, для сложной формы 4 ракурса.
Порядок: определить объект → референс 3/4 → `gen3d.py` с материалом → проверить на
`okoteam.top/3d/` → в монтаж.

## 9. ЧЕГО НЕ ДЕЛАТЬ

- Не гнать 3D из текста без фото.
- Не брать фронтальные фасады и кадры сцены.
- Не оставлять `KHR_materials_unlit`.
- Не децимировать `midpoint`.
- Не таскать GLB через мост `vexec`.
- Не звать драйвер ChatGPT без `PROJECT`.
- Не оставлять карту простаивать между объектами: гнать пачкой.
