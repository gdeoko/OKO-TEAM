# ПРОИЗВОДСТВЕННАЯ БИБЛИЯ КОНТЕНТ-ЗАВОДА (универсальная, для ЛЮБОГО проекта)

> Один документ — все правила. Прикрепляется к каждому проекту. Ассистент обязан выполнять
> это на 100% на КАЖДЫЙ ролик, всегда с нуля, без шаблонов, лени и отговорок. Владелец не
> должен повторять эти правила — они здесь.
>
> Главный принцип: **каждый ролик собирается на основе детального разбора 10 свежих
> роликов-миллионников (1M+). Всё — единое целое: анализ → смысл → сценарий → кадры под слова →
> наложения по смыслу → монтаж → музыка → звук → обложка → озвучка → публикация → аналитика →
> обучение. Не набор галочек, а связка, ведущая к миллиону просмотров и полному разнообразию.**

---

## 0. ЗАКОН №0 — ЧЕСТНОСТЬ И ЛОГИКА ЗАЛЁТА

- **Никогда не рапортовать «сделано/зелено», если не сделано.** Отчитываться тем, что реально
  произошло на этом ролике: какие конкуренты разобраны, что взято, что не удалось и почему.
- **Гарантировать 1M нельзя** — так не работает ни один алгоритм (он взвешивает удержание,
  авторитет аккаунта, аудиторию, тайминг, удачу). Мы играем **вероятность**: каждый ролик
  реально построен на победителях + итерируем по цифрам. На дистанции 500 роликов это и даёт
  миллионники. Логика верная: строишь на 10 миллионниках → резко поднимаешь шанс. Но это
  рычаг, а не переключатель. Честно это и говорим.
- **Качество берётся из анализа, а не из урезания количества.** Объём НЕ уменьшать — только
  растить. Уникальность даёт разбор конкурентов, а не сокращение выпуска.

## 2. ЖЁСТКИЕ ЗАКОНЫ (соблюдать всегда, на каждый ролик)

1. **Анализ ПЕРЕД каждой сборкой** — всегда 10 новых конкурентов, всегда новые реф-ролики 1M+.
2. **Ноль повторов среди 500 роликов** — ни прямых, ни косвенных: тема, сценарий, визуал,
   дизайн, монтаж, музыка, звук, озвучка, наложения, длина, смысл, формат — всё разное.
3. **Хук-первым.** Первые 0.5–1 сек решают. Проектировать первый кадр (стоп-скролл) ДО сценария.
4. **Кадры под смысл слов.** Сток/кадр обязан иллюстрировать то, что звучит/написано сейчас.
   Никаких случайных стоков «для красоты».
5. **Наложения только по смыслу.** Инфографика даёт динамику, но обязана быть по делу и не
   мешать. Декор ради декора (пончики/бары/«vs» на каждом кадре) = язык рекламы = скип. Убрать.
6. **Звук ≠ голос рекламы.** Тренд-музыка / живой голос владельца / человечный разговорный VO.
   TTS-диктор рекламного текста = скип. Если VO — короткий, живой, без «дикторства», без тараторья.
7. **Разнообразие проверяется** внутри ролика И относительно прошлых (журналы USED_*).
8. **Дубли запрещены абсолютно.** Один id → одна публикация на площадку. Тройная защита (см. §9).
9. **Каждое утро 10:00 МСК — полный отчёт** по каждой соцсети.
10. **Обучение по цифрам.** Формат сдулся по данным → убиваем. Стрельнул → размножаем приём.

## 3. ЭТАП 1 — АНАЛИЗ КОНКУРЕНТОВ (перед КАЖДЫМ роликом, с нуля)

### 3.1 Поиск (всегда новые, без повторов)
- Найти **10 самых популярных конкурентов ниши** на момент сборки — каждый раз ДРУГИЕ
  (дедуп по журналу `recon_seen.json`, ротация окна запросов).
- Найти по площадкам **реф-ролики от 1 000 000 просмотров** (меньше — не берём): цель — 5 в
  Instagram + 5 в YouTube. Всегда новые, без повторов.

### 3.2 Раскадровка + транскрипт (ОБЯЗАТЕЛЬНО, реально)
- **Скачать ролик** и/или снять раскадровку, **посмотреть каждый кадр**, послушать озвучку,
  прочитать сценарий целиком.
- **Обход блокировки скачивания** (дата-центр-IP часто ловит 403 при прямом скачивании видео):
  - **Транскрипт** — авто-субтитры: `yt-dlp --skip-download --write-auto-subs --sub-lang en
    --sub-format vtt` → чистим теги → полный сценарий с таймингом. Работает.
  - **Раскадровка** — storyboard-спрайты YouTube: `yt-dlp -f sb0/sb1/sb2` → mhtml → распаковать
    JPEG-сетки (кадры по всему ролику). Отдаётся с CDN картинок, 403 не ловит. Это и есть
    покадровый обзор монтажа — **смотреть глазами модели**.
  - Инструмент: `recon_deep.py <niche> <reel_id> 10` собирает пакет в `analysis/refs/<reel_id>/`
    (meta.json + transcript_i.txt + board_i.jpg + INDEX.md).
  - Где прямое скачивание доступно (Apify/резидентный прокси/локально) — качать полноценно.
- Никогда не подменять реальный разбор метаданными и не писать «сделал раскадровку», если
  был только разбор заголовков. Честно фиксировать, что удалось (транскрипт/раскадровка/оба).

### 3.3 Метрики каждого реф-ролика
- Просмотры (>1M), лайки, комментарии, **репосты, сохранения**, ER% ((лайки+комменты)/просмотры),
  длительность, канал + число подписчиков.
- **Прочитать несколько комментариев** — что зацепило аудиторию, боли, вопросы.

### 3.4 Разбор (что реально заходит)
По каждому и по всей десятке вынести:
- **Хук** — что в первом кадре/первых словах останавливает скролл (шок/лицо/движение/цифра/интрига/ставки).
- **Сценарий/структура** — как построено (проблема→решение, нумерованные советы, до/после, история).
- **Темп** — частота смены планов, длина кадра, ритм под бит.
- **Тип съёмки** — говорящая голова / экшн / демонстрация / скринкаст / b-roll.
- **Воронка продаж** — как ведут к действию, где и какой CTA, кодовые слова, описание.
- **Продукт** — что и как продают (или не продают — ценность вперёд, продажа фоном).
- **Активность/тренды** — общие паттерны десятки, повторяющиеся приёмы, тренд-аудио.

### 3.5 Документ-аналитика в бота
- Собрать **красивый документ** со всеми цифрами и разбором всех 10 конкурентов и реф-роликов
  (ссылки кликабельны) → отправить в Telegram-бота проекта. Это **файл-основа ролика**.

### 3.6 Ручная активность (1 раз в день, без риска бана)
Во время поиска/анализа: **лайк + комментарий + сохранение** каждому реф-ролику; **подписка
только на 3** аккаунта с наибольшим числом подписчиков; **ролики досматривать до конца**.
Лимиты безопасные (≈12 лайков / 6 сохранений / 3 коммента / 3 подписки в день). Если сессия
соцсети мертва/в suspend — активность пропустить, уведомить владельца, не долбить (бан-риск).

## 4. ЭТАП 2 — СБОРКА СЦЕНАРИЯ (на основе анализа 10 конкурентов)

- Писать сценарий **от разбора десятки**, не из головы. Взять их рабочие приёмы (хук, структуру,
  темп, тип съёмки, тон) и **связать с нашим брендом** (кодовое слово, продукт, выгода).
- **Хук-первым**: сначала проектируем первый кадр и первую фразу (стоп-скролл), потом тело.
- Прогнать через скиллы: **маркетинг / продажи / медийность / виральность / хук / humanizer**.
- Проверить: **воронку продаж, кодовые слова, описание** (SEO/дискавери-хэштеги из свежих
  трендов), человечность текста (humanizer — убрать «ИИ-язык», штампы, канцелярит).
- Ценность/эмоция вперёд, продажа — фоном. Цель кадра — удержание, а не «купи».

---

## 5. ЭТАП 3 — СБОРКА РОЛИКА (всё разнообразно, ноль шаблонов)

### 5.1 Кадры/сток (4K, под смысл)
- Подобрать **4K-кадры/сток строго под смысл слов сценария**, смена ~каждые 3 секунды.
- Лучше меньше, но точнее: сильный кадр/экшн под бит, а не 12 случайных стоков-слайдшоу.
- Сверка с `USED_FOOTAGE.md` — те же клипы не переиспользуем.

### 5.2 Наложения / инфографика / моушен (по смыслу, чаще, не мешая)
- Анимации/инфографика/наложения на каждые 3–5 сек — **по смыслу ролика**, добавляют динамику
  и понимание, не декор. Одно слово-панч, важная цифра, подпись — да; пончик ради пончика — нет.
- Проверить по `USED_ANIM.md` / `MOTION_ARSENAL.md`, что набор и порядок **не повторялись** в
  прошлых роликах и это **не шаблон**, переиспользуемый каждый раз.

### 5.3 Проверка разнообразия (внутри и между роликами)
Разными должны быть и НЕ повторяться — ни внутри одного ролика, ни относительно прошлых:
**музыка · анимации · инфографика · наложения · стоковые видео · нарезка · структура · грейд ·
темп · длина · формат · тема · озвучка**. Вести журналы; матрица разнообразия — §8.

### 5.4 Обложка
- Собрать **крутую обложку** (FLUX / Gemini / др.) в бренд-стиле; текст-хук на обложке.
- Для YouTube: ставить кастомную обложку через Data API (`thumbnails.set`) — **требует
  верифицированного канала**, иначе 403 (`uploadRateLimitExceeded` — скользящий лимит, между
  попытками пауза ≥4ч, иначе окно не остывает). Первый кадр видео = брендовая обложка (фолбэк).

### 5.5 Музыка (уникальная на каждый ролик)
- Подбирать под **тип контента/бренд/тему/сценарий** (viral→энергичная, useful→эмбиент,
  sales→уверенно-подъёмная) + тренд-аудио площадки, где уместно.
- **Глобальный дедуп** (`used_music.json`) — трек НИКОГДА не повторяется между роликами.

### 5.6 Озвучка (не «диктор»)
- Проверить **паузы и ударения**, темп (не тараторить), человечность.
- Приоритет: тренд-музыка без голоса / живой голос владельца / человечный разговорный VO.
  Никакого TTS-рекламного дикторства.

## 6. ЭТАП 4 — ПУБЛИКАЦИЯ

- **QA всего ролика**: красота, разнообразие, динамика, число кадров/анимаций/наложений,
  0 повторов, длина (обычно 20–45с; формат — от рефов). **Оценить залёт на 1M** (скоринг
  виральности + при наличии — Higgsfield `virality_predictor` ДО публикации как фильтр).
- Слабый/повторяющийся/«рекламный» ролик — **не публиковать**, пересобрать.
- Публикация во **все 3 соцсети** (TikTok + YouTube + Instagram) + **отчёт в бота**.
- **Пейсинг**: равномерно по дню, **≥1.5ч между роликами**. Не постить всё разом.

## 7. ЭТАП 5 — ОТЧЁТ (каждое утро 10:00 МСК, по КАЖДОЙ соцсети)

Полные реальные метрики (не выдумывать; нет данных → «нет данных», не 0):
- **просмотры, комментарии, лайки, репосты, сохранения, подписчики (прирост),
  переходы на сайт/клики по воронке, жалобы, удержание** — по каждой соцсети.
- Прирост со вчера (snapshot), прогресс к цели (просмотры / N роликов).
- Разбор: что растёт, что проседает, какие хуки/форматы/темы/CTA заходят → в `WINNERS.md`.
- **Защита от холодного старта**: пока ни один ролик не пробил порог тяги (напр. 500 просм),
  низкие просмотры = норма новичка, НЕ резать выпуск. Реальная просадка (уже была тяга и ≥2
  ранее-замеренных ролика встали/вниз) → временный откат темпа, затем снова вверх.

## 8. МАТРИЦА РАЗНООБРАЗИЯ (ноль повторов на 500 роликов)

| Тема/угол | каждый раз новый, из свежего анализа | — |
| Хук | разный тип (шок/цифра/интрига/ставки/лицо/движение) | — |
| Структура | от конкретного рефа, не фикс-скелет | — |

из `BRAND_PROFILE.md`. Всё остальное — разнообразно.

## 9. АНТИ-ДУБЛЬ (железно, тройная защита)

1. **Вечный журнал id** (`gen_ledger.json`) + **самолечение счётчика** (откат состояния не
   пересоздаёт вышедшие id).
2. **Генератор** выдаёт только СВЕЖИЕ id (пропускает опубликованные и стоящие в очереди).
3. **Публикатор — жёсткий guard**: id с существующим yt_id/tt_id/ig_code на площадку повторно
   НЕ заливается. Очередь чистится от уже опубликованного.
4. Периодически сверять реестр с реальным каналом; отклонённые площадкой (дубль) — чистить.

## 10. ЦИКЛ ОБУЧЕНИЯ (петля по аналитике)

- Реальные цифры диктуют следующий ролик, а не заранее-план ротации.
- **Стрельнуло** (высокие просмотры/удержание) → размножить приём (хук/формат/тему) в новых
  роликах, но не копией — вариациями.
- **Сдулось** (по валидным данным, не холодный старт) → формат убить, не повторять.
- Обновлять `WINNERS.md` / `COMPETITORS.md` после каждого отчёта.

## 11. ЧЕСТНЫЕ ТЕХНИЧЕСКИЕ ПРЕДЕЛЫ (знать и обходить, не врать)

- **Скачивание чужого видео целиком** с дата-центр-IP часто = 403. Обход: транскрипт (авто-сабы)
  + раскадровка (storyboard-спрайты) — этого достаточно для реального разбора. Полное скачивание —
  через Apify/резидентный прокси/локально, где доступно.
- **Гарантия 1M невозможна** — играем вероятность (см. §0).
- **Кастомные обложки YouTube** — только на верифицированном канале; лимит частоты (пауза ≥4ч).
- **Метрики TikTok/IG без API** — из кабинета/через сессию; если нет — честно помечать «см. кабинет».
- **Аккаунт в suspend/сессия мертва** — постинг/активность физически невозможны; уведомить
  владельца, поставить площадку на паузу, не долбить (бан-риск), продолжать на живых площадках.

- [ ] Кадры 4K под смысл слов; наложения/моушен по смыслу; обложка собрана
- [ ] Разнообразие проверено (внутри и между роликами) по всем параметрам §8; журналы обновлены
