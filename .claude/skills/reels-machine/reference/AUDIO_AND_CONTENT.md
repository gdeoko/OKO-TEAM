# AUDIO + КОНТЕНТ-СТРАТЕГИЯ — правила v9 (обязательно, требование клиента)

Дополняет MOTION_ARSENAL §7 и DIVERSITY_LAWS. Всё — под анализ темы/сценария ролика.

═══════════════════════════════════════════════════════════════════════
## 1. МУЗЫКА — индивидуально + плавные края (никаких обрывов)
═══════════════════════════════════════════════════════════════════════
- Свой трек на КАЖДЫЙ ролик (Freesound, запрос под настроение темы). Не переиспользовать.
- Начало — плавное появление (fade-in ≥1.2с), конец — плавное затухание (fade-out ≥2.5с).
  НИКОГДА не обрывать музыку резко.
- Если трек короче ролика — зациклить (`aloop=loop=-1:size=...`) ИЛИ взять трек длиннее ролика.
  НЕЛЬЗЯ, чтобы музыка кончилась раньше видео (тишина в конце = обрыв).
- Даккинг под голос (sidechaincompress). Громкость 0.13–0.16.

**ffmpeg (stage3) — обязательный вид музыкального трека:**
```
[MUS:a]aloop=loop=-1:size=2e9,atrim=0:{TOTAL},asetpts=PTS-STARTPTS,
 volume={musvol},afade=t=in:d=1.4,afade=t=out:st={TOTAL-2.6}:d=2.6[musraw];
[musraw][vosc]sidechaincompress=threshold=0.05:ratio=6:attack=15:release=450:makeup=1[mus]
```
`aloop` спасает от обрыва на коротком треке; fade-in/out убирают щелчки на краях.

## 2. SFX — РАЗНООБРАЗНЫЕ, ПО СМЫСЛУ, не на каждом наложении
═══════════════════════════════════════════════════════════════════════
ГЛАВНАЯ ОШИБКА (чинить): один и тот же «вжух» на КАЖДОМ наложении → раздражает,
звучит обрывками и нелогично. Так НЕЛЬЗЯ.

Правила:
- SFX ставим НЕ на каждое наложение, а на СМЫСЛОВЫЕ биты. Плотность ~1 SFX на 3–5 сек.
- Звук подбираем ПО СМЫСЛУ бита, каждый раз РАЗНЫЙ (мимо реестра в пределах ролика):
  | смысл бита | категория SFX |
  |---|---|
  | цифра/статистика/счётчик/сравнение | `impact` / `boom` (глухой удар) |
  | CTA / подписка / позитив / «готово» | `ding` / `success chime` / `notification` |
  | переход между кадрами / появление стока | `whoosh` (РАЗНЫЕ вариации, не один) |
  | появление графики/штампа | `pop` / `click` / `swoosh short` |
  | нагнетание / проблема | `riser` / `dark hit` / `tension` |
  | деньги / продажа | `cash` / `coin` |
  | 3D-объект влетает | `swoosh deep` / `whoosh low` |
- Не «дешёвые» мемные звуки. Чистые, короткие, с fade на хвосте (`afade=t=out:d=0.05`).
- Громкость 0.3–0.45, не перебивать голос.
- Собирать банк под ролик через `pipeline/motion/sfx_bank.py` (Freesound по категориям,
  6–10 разных звуков на ролик), в конфиге ссылаться по имени категории+индексу.

**Банк SFX:** `python3 pipeline/motion/sfx_bank.py <outdir>` — качает по 2 звука в каждой
категории (impact/ding/whoosh/pop/riser/cash/swoosh) → `sfx/<cat><n>.mp3`. В конфиге SFX
чередовать: whoosh1, whoosh2, whoosh3 на разных переходах (не whip1 везде).

## 3. БОЛЬШЕ ИНФОГРАФИКИ, НАРИСОВАННОЙ КОДОМ (красивая, анимационная)
═══════════════════════════════════════════════════════════════════════
- Приоритет — беспоук-инфографика кодом (fx_engine.js/anim.js + Remotion), а не готовые
  Lottie. Она чище под бренд и точнее под цифру/метафору.
- На каждую цифру/сравнение сценария — своя анимированная графика (счётчик, линчарт
  «потолок→пробиваем», донат, бары, gauge, timeline, до/после), написанная под смысл.
- Lottie — как акцент-дополнение, а не основа. Код-графики в ролике должно быть БОЛЬШЕ.
- Всё анимировано (easing, появление по слову озвучки), ноль статики.

═══════════════════════════════════════════════════════════════════════
## 4. ТЕМП — кадр 3–5 сек, наложения тоже, по смыслу
═══════════════════════════════════════════════════════════════════════
- Кадр меняется каждые 3–5 сек (не строго 3) — по смыслу сценария/текста.
- Наложения — тоже по смыслу, каждый кадр или через кадр, привязка к словам озвучки.
- Всё продиктовано анализом темы и сценария, а не механически.

═══════════════════════════════════════════════════════════════════════
## 5. СООТНОШЕНИЕ КОНТЕНТА (по типам роликов)
═══════════════════════════════════════════════════════════════════════
- **50% виральные** (охваты, пересылки, хук-разрыв, эмоция).
- **30% полезные** (сохранения, экспертиза, «как сделать»).
- **20% продающие** (кейсы, оффер, CTA на съёмку).
Распределять по календарю; не идти подряд одним типом. Тип ролика влияет на хук,
структуру, CTA и грейд.

═══════════════════════════════════════════════════════════════════════
## 6. ВСЁ НА ОСНОВЕ АНАЛИЗА + ПРОГОН ЧЕРЕЗ СКИЛЛЫ (каждый шаг)
═══════════════════════════════════════════════════════════════════════
Перед сборкой ролик строится из данных:
- Анализ конкурентов и трендов: ролики от 1М — расшифровка, раскадровка, осмотр,
  комментарии/лайки, анализ продукта.
- Аналитика бренда: прошлые публикации, что зашло/не зашло, статистика наших роликов.
- Бренд, инфо, оффер клиента.

И на КАЖДОМ шаге (сценарий, хук, текст, описание) прогонять через доступные скиллы:
маркетинг, продажи, генератор хуков, медийность, продвижение в соцсетях, **Humanizer**
(убрать ИИ-язык, длинные тире, «не X а Y»). Только очищенный живой текст — в озвучку.

═══════════════════════════════════════════════════════════════════════
ЧЕК перед сдачей (в дополнение к MOTION_ARSENAL):
- [ ] Музыка своя, плавно появляется и затухает, не обрывается, не кончается раньше видео.
- [ ] SFX разные и по смыслу, НЕ один и тот же на каждом наложении, не дешёвые, с fade.
- [ ] Код-инфографики больше, чем Lottie; всё анимировано.
- [ ] Кадр/наложения меняются по смыслу (3–5 сек), привязаны к словам.
- [ ] Тип ролика учтён (виральный/полезный/продающий), соотношение 50/30/20 по календарю.
- [ ] Текст прогнан через маркетинг/хук/медийность/Humanizer.

## 7. ДОСТАВКА В БОТ (правило клиента)
═══════════════════════════════════════════════════════════════════════
- Обложка — ПЕРВЫЙ КАДР самого видео (0.3с в начале), а НЕ отдельным сообщением-фото.
  Отдельное фото обложки НЕ отправлять.
- Ролик отправлять ТОЛЬКО как ФАЙЛ (`sendDocument`), НЕ `sendVideo` — иначе Telegram
  пережимает и качество падает. Описание — в `caption`.
- Миниатюру файла ставить из обложки: `thumbnail=@thumb.jpg` (≤320px, ≤200КБ):
  `ffmpeg -i cover_ai.jpg -vf scale=320:-1 -q:v 6 thumb.jpg`.
- Пример: `curl --cacert <CA> -F chat_id=<id> -F document=@reel.mp4 -F thumbnail=@thumb.jpg
  --form-string "caption=<описание>" .../sendDocument`.

## 8. СУБТИТРЫ + ИНФОГРАФИКА — правила v15 (требование Даниэля, ПОСТОЯННО)
═══════════════════════════════════════════════════════════════════════
- **Субтитры: максимум 2 слова, ВСЕГДА одна строка.** Группировка по 2 слова, без переносов.
- **Без чёрной границы и тени.** ASS-стиль: `Outline=0, Shadow=0` (никакого чёрного бордера/дропшэдоу).
  Шрифт Союз Гротеск (soyuz.ttf), строчные, активное слово оранж `&H2059EA&`, прошлые белые.
  Стандартное `\k`-караоке, одно событие на строку. Format-строка `[Events]` ОБЯЗАНА содержать
  поле `Name` (иначе лишняя запятая утекает в текст — см. BUILD_NOTES §10).
- **Озвучка/караоке без ошибок:** `strip_acc` убирает ТОЛЬКО ударения (U+0301/U+0300),
  й/ё СОХРАНЯТЬ (не через NFD+Mn — иначе «спиной»→«спинои», «живой»→«живои»).
- **Инфографики кодом — БОЛЬШЕ и ЧАЩЕ:** анимированная код-инфографика (canvas/CSS через
  fx_engine + Remotion) на КАЖДЫЕ 3-5 сек ролика, не реже. Типы: bars (сравнение %),
  donut (доля), statcard/counter (число растёт), ratings (звёзды), steps (1-2-3), gauge,
  breakthrough, barrace. Разные в каждом ролике, мимо USED_ANIM. Код-графики ДОЛЖНО быть
  БОЛЬШЕ, чем Lottie. Каждая цифра сценария → своя анимированная код-графика под смысл.
