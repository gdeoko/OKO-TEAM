# 🏭 ЗАКОН КОНТЕНТ-ЗАВОДА — обязательный порядок на КАЖДЫЙ ролик

> Триггер: слышишь **«контент-завод»** (любой проект/клиент) → выполняешь ЭТИ шаги для
> сборки **абсолютно каждого ролика**, каждый день. Ничего не пропускать, порядок строгий.
> Всё бесплатным путём (стоки/озвучка/3D/графика — локально); платный ИИ (Higgsfield) —
> только обложка/карусели и только с разрешения (правило №7).

Переменные под клиента (кол-во роликов, цвета/стиль бренда, какие соцсети) — **из анализа
контекста клиента** (шаг 1). Всё остальное ниже — одинаково для всех проектов.

---

## Шаг 1. Контекст клиента (полный разбор перед всем)
Прочитать и учесть ВСЁ по клиенту: анкета, контекст проекта, инфо о клиенте — кто клиент,
характер, бренд, тематика, ниша, стиль, цели, задачи, условия, договор, правила, бренд-паспорт
(`reference/BRAND_PROFILE.md`), логотип, палитра, голос, CTA. Отсюда берутся: **кол-во роликов
в день, цвета/стиль, список соцсетей** — они индивидуальны для клиента.

## Шаг 2. Аудит и анализ конкурентов (через агентов ОКО на VPS)
1. Найти **10 аккаунтов-конкурентов** в нише бренда, которые **№1 в мире** по охватам/аудитории.
   Площадки: **Instagram, YouTube, TikTok** — искать через агентов ОКО на VPS.
2. У каждого конкурента найти **по 1 ролику с >1 млн просмотров** именно в теме/нише бренда.
3. Все 10 роликов: **посмотреть, скачать, сделать раскадровку + расшифровку**, проанализировать:
   хук, сценарий, формат, стиль, удержание, воронку продаж, CTA, описание, аналитику/статистику,
   комментарии/лайки/репосты/просмотры, продукт ролика и конкурента, сайт + Telegram-канал +
   всё на странице конкурента.
4. Составить **детальный файл анализа** (желательно **.docx**) по 10 конкурентам и 10 роликам >1М.

## Шаг 3. Прогрев из аккаунтов клиента (параллельно шагу 2)
С соцсетей **самого клиента**: из 10 конкурентов **подписаться на 3 лучших**, на **10 роликов
поставить лайк**, на **5 — написать осмысленный комментарий** по смыслу.

## Шаг 4. Сценарий и связка
На основе файла анализа 10 конкурентов/роликов составить: **хук, сценарий, описание, формат,
стиль, озвучку сценария** — связать всё с брендом и нишей клиента.

## Шаг 5. Подбор кадров под сценарий
Под собранный сценарий подобрать **стоковые кадры на каждые 3 секунды** ролика (по битам
сценария и общей теме).

## Шаг 6. Прогон через скиллы-усилители
Сценарий, анализ, кадры, хук, описание, воронку, все тексты прогнать через скиллы:
**humanizer, hook-generator, marketing-psychology, медийность/виральность, воронка продаж,
удержание** и все скиллы, что оживят/усилят ролик до **гарантированного миллиона просмотров**.

## Шаг 7. Сборка и монтаж
Собрать кадры + озвучку по сценарию так, чтобы **стоки менялись каждые 3 секунды** (или чаще —
по динамике речи под бит), по смыслу сценария и темы.

## Шаг 8. Фоновая музыка
Наложить музыку по смыслу (из анализа темы/кадров), громкость **10–15%**, анализировать чтобы
**не перекрывала озвучку**.

## Шаг 9. Наложения монтажа (поверх стоков)
Анимации, инфографика, моушен-дизайн, моушен-графика, графики кодом, gif, 3D/5D, CSS, GLB,
WebGL, WebP, KTX/Basis и т.д. Требования:
- под смысл сценария/кадров/темы, **персонализировано под слова в сценарии**;
- **каждые 3–5 секунд**, на каждый кадр **или через кадр**;
- **всё ВСЕГДА движется** — ничего статичного;
- каждое наложение **красиво появляется и исчезает** (прозрачность / выезд слева-справа-сверху
  и т.д. — по смыслу самого наложения, сценария, озвучки, стоков и музыки).

## Шаг 10. Движение кадров
На все стоки — **зумы (приближение/отдаление), движение по осям** и т.д. по смыслу и **динамике
музыки/озвучки/смены кадров**.

## Шаг 11. Переходы
Между сменами стоков — **красивые профессиональные разные** переходы.

## Шаг 12. Субтитры
Наложить **красивые субтитры**: обычно 2 слова в строку караоке-стилем, либо 2 строки
(сверху жирное слово, снизу подпись) — на каждый проект **разные** (цвета/шрифты/стили), но
**не 2–3 строки**. Субтитры должны **очень чётко совпадать со скоростью/темпом озвучки**.

## ⛔ ЖЁСТКИЙ ЗАКОН ПОВТОРОВ (важнее всего)
**Внутри одного проекта (клиента) — НИКОГДА никаких повторов.** Ни один из следующих
элементов не повторяется **ни внутри одного ролика, ни между разными роликами одного проекта**:
- стоковый кадр,
- наложение / ассет,
- фоновая музыка,
- переход между кадрами,
- тема,
- сценарий,
- конкурент,
- ролик-референс.

То есть на **каждый** ролик завода одного проекта — всегда: **новые конкуренты, новый анализ,
новый сценарий, новая тема, новый хук, новые кадры, новая музыка, новые наложения, новые зумы,
новые переходы, новые субтитры.** Между разными проектами повторы допустимы — внутри одного
проекта повторов быть не должно **никогда**.

Реализация: **пер-клиентские реестры** (`reference/USED_*` в папке клиента) — перед сборкой
читать и исключать всё занятое, после сборки дописывать использованное. Красный флаг = любой
повтор внутри проекта.

---

## Периодичность
Всё вышеперечисленное — **ежедневно**, на каждый ролик, в количестве роликов, заданном
контекстом клиента (шаг 1). Аналитика/обучение/усиление — по общему циклу скилла (см. SKILL.md).
