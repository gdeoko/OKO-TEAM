# Безопасный перенос исправлений Rocket

Ветка `codex/rocket-recovery-20260908-clean` — самостоятельный снимок выпуска, а не замена монорепозитория OKO. В ней намеренно нет общей истории и секретов. Весь её корень нельзя переносить поверх другой ветки или принудительно записывать в `main`.

Проверено 8 сентября 2026:

- исходная Rocket-ветка `claude/rocket-cdn-website-admin-x5482k` сохранена на `6b64106bdde7488bee2b6485b210eaf1db4fc395`;
- в её дереве 1652 файла, включая документы, проверки и другие проекты;
- `main` находится на `69fb03cd95099aafab0c594c165267f7bdc45210`; каталогов `rocketvpn/` и `rocketcdn/` в этом дереве нет;
- ветка выпуска не сливалась в `main`;
- разница деревьев, показывающая отсутствующие файлы в снимке, не доказывает их удаление из исходной ветки. Обычное слияние независимых историй Git также не выполняет автоматически.

`deploy/rocket-overlay.json` содержит только добавляемые и изменяемые файлы Rocket. Удалений в нём нет. Для каждого файла записаны Git blob SHA исходной и новой версии. `required` перечисляет необходимые файлы существующего проекта: инструмент не установит неполный Rocket в пустой каталог.

Проверка подготовленного checkout исходной Rocket-ветки:

```sh
python3 /path/to/release/deploy/integrate.py --target /path/to/rocket-development
```

Применение проверенного списка:

```sh
python3 /path/to/release/deploy/integrate.py --target /path/to/rocket-development --apply
```

Нужен чистый checkout. При параллельном изменении файла инструмент сообщает конфликт до записи. Он не меняет README и инструкции в корне, другие проекты, не удаляет документы и старые проверки. При ошибке записи возвращает свои ранее записанные файлы; более новые параллельные изменения сохраняет. Сам инструмент не создаёт коммит, не делает push и не запускает публикацию.

Шесть изолированных проверок покрывают сохранность посторонних файлов, идемпотентность, конфликт, отсутствующие ассеты, изменённый источник, выход через симлинк и откат при конкурентной записи:

```sh
python3 -m unittest discover -s deploy -p test_integrate.py -v
```

Это инструкция переноса кода. Для действующего сервера используются отдельные выпуски и `deploy/followup.py`, сверяющий базовые контрольные суммы перед переключением. Runtime-данные и доступы не входят в список переносимых файлов.
