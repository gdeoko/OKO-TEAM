# Чем проверять бота на живом API

Все четыре скрипта запускаются НА СЕРВЕРЕ бота (там ключ и модули):

    set -a; . /etc/amberry.env; set +a
    cd /opt/amberry/rocket-panel/bot
    /opt/amberry/.venv/bin/python tools/<скрипт>

## прогон_кнопок.py — сквозной прогон всех кнопок через API

    PROBA_PHOTO=qwen3-image-pro PROBA_REPORT=/root/proba/х.csv \
      python tools/прогон_кнопок.py фото [кнопка,кнопка]

Собирает промпт ровно так, как бот (`prompts.под_предел`), шлёт в API,
качает кадр, считает резкость и пишет строку на кнопку. Отказы видны
столбцом «ОТКАЗ» с причиной. Парной кнопке даёт два референса: с одним
запрос уходил бы не тем, чем уходит у человека.

Платит деньги: кадр $0.039 на базовой модели, $0.079 на pro.

## мера_детализации.py — чем мерить «кашу»

    python tools/мера_детализации.py кадр1.png кадр2.png

**Разброс лапласиана по кадру НЕ ГОДИТСЯ**: он путает мягкий кадр с
кадром, где много ровного фона, и на первой же сверке моделей дал
обратный ответ. Этот скрипт считает силу самых контрастных 5% точек и
делает это отдельно по полосам (лицо, грудь, живот и пах, ноги).

Сравнивать можно только ОДНУ кнопку между собой: у разных кнопок разная
композиция, и числа несопоставимы.

## первый_кадр_ролика.py — взял ли ролик наш кадр

    python tools/первый_кадр_ролика.py ролик.mp4 снимок.png

Вынимает первый кадр ролика и считает отклонение от отправленного
снимка. Свой кадр даёт единицы, чужой — десятки.

Нужно потому, что **поле `modelType` в ответе врёт**: и `lite`, и `wan`
вернули `TEXT_TO_VIDEO`, а кадр обе всё-таки взяли. А чужое поле кадра
сервис молча выбрасывает — ответ 200, задача принята, ролик снят с нуля,
деньги списаны.

## проба_видео.py — какое поле кадра у модели

    python tools/проба_видео.py wan-2.7-i2v-spicy 720p ac_above кадр.png 5

Перебирает известные поля кадра по порядку и останавливается на том,
которое сервис принял. Платит: 5 с на wan 720p — $0.85.
