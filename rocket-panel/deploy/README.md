# Разворачивание AMBERRY

## Две машины, и это не блажь

| | Где живёт | Что делает | Что будет, если пропадёт |
|---|---|---|---|
| **Сервер** | Worldstream, Naaldwijk NL, `62.112.10.168` | бот, база, архив работ, оплаты, статистика, потом сайт и эфиры | всё встало, данные потеряны |
| **Видеокарта** | Hyperstack, Канада, почасово | только генерация фото и видео | бот жив, генерация не идёт |

Карту берут и возвращают по нагрузке, её диск при возврате стирается.
Поэтому на ней не лежит НИЧЕГО, что нельзя потерять: ни база, ни
результаты, ни настройки. Раньше это было не так — имя файла с карты
писалось в базу как адрес работы, и после возврата карты адрес
указывал в никуда. Починено (`bot/archive.py`), но помнить про это
нужно при каждой правке.


Доступы — в `secrets.env` на VPS (`ROCKET_SRV_*`), ключ SSH там же в
`~/keys/rocket_srv`. В git их нет и быть не должно.

## Первый запуск

```bash
ssh -i ~/keys/rocket_srv root@62.112.10.168
curl -fsSL https://raw.githubusercontent.com/gdeoko/OKO-TEAM/claude/rocket-webcam-sborka/rocket-panel/deploy/setup_server.sh -o setup.sh
bash setup.sh
```

Скрипт ставит пакеты, заводит пользователя, тянет код, создаёт
`/etc/amberry.env` и службу `amberry`, закрывает всё кроме SSH.
Гонять его повторно безопасно: базу и файл с ключами он не трогает.

Дальше вписать ключи в `/etc/amberry.env` и:

```bash
systemctl start amberry
journalctl -u amberry -f
```

## Где что лежит

| Путь | Что |
|---|---|
| `/opt/amberry` | код (git, ветка `claude/rocket-webcam-sborka`) |
| `/srv/amberry/amberry.db` | база: люди, коины, оплаты, задания |
| `/srv/amberry/works/<tg_id>/` | архив работ |
| `/etc/amberry.env` | ключи, права 600, в git не попадает |

Служба пишет только в `/srv/amberry` — остальная файловая система для
неё доступна на чтение. Бот принимает данные от посторонних людей,
и ограничение заведено заранее, а не после случая.

## Обновление

```bash
bash /opt/amberry/rocket-panel/deploy/setup_server.sh   # тянет ветку и перезапускает
```

## Чего здесь нет

Генерации и моделей. Они на видеокарте — `../ВЕБКАМ_ГЕНЕРАЦИЯ_УСТАНОВКА.md`.

## Сервер остался без входа: что было и чего теперь не повторится

**21–23.09.2026.** SSH перестал пускать: порт 22 отвечал «connection
refused» двое суток, при живом сайте на 80/443. Всё это время правки
бота лежали в git и на прод не ехали.

**Причина по журналу прошлой загрузки.** Сервер с первого дня
перебирают ботнеты — за сутки сотни попыток подобрать пароль root с
`2.57.122.150`, `103.174.102.29`, `167.99.95.20` и десятка других
адресов. 22.09 в 06:11–06:13 служба ssh несколько раз перезапустилась,
старые `sshd` остались висеть и держать порт («Unit process … remains
running after unit stopped»), новый подняться не смог, и systemd
упёрся в предел попыток: `start request repeated too quickly` →
`start-limit-hit`. После этого он больше не пытался — до перезагрузки
по питанию.

**Как вернули.** Жёсткая перезагрузка через API Worldstream (PDU):

```bash
curl -X PUT -H "X-API-Key: $WORLDSTREAM_API_KEY" \
  -H 'Content-Type: application/json' -d '{"action":"reboot"}' \
  https://api.worldstream.com/dedicated/v1/dedicated-servers/176942/power
```

Состояние питания — `GET …/176942/power-status`. Машина вернулась за
четыре минуты. В самом кабинете кнопки перезагрузки НЕТ (на карточке
сервера только «Clear default password» и «Request cancellation»), в
списке машин «Power on» — это значок состояния, а не кнопка. Путь один
и только через API; метод **PUT**, не POST.

**Что поставлено, чтобы это не повторилось.**

| Что | Где | Зачем |
|---|---|---|
| `PasswordAuthentication no`, `PermitRootLogin prohibit-password`, `MaxAuthTries 3` | `/etc/ssh/sshd_config.d/10-oko.conf` | подбирать нечего: вход только по ключу |
| `StartLimitIntervalSec=0`, `Restart=always`, `KillMode=control-group` | `/etc/systemd/system/ssh.service.d/10-oko-restart.conf` | systemd больше не имеет права сдаться, осиротевшие `sshd` добиваются |
| `ssh-storozh.timer`, раз в 2 минуты | `/usr/local/sbin/ssh-storozh.sh` | проверяет САМ ПОРТ, а не состояние юнита: 22.09 юнит числился упавшим, а процесс висел |
| fail2ban, `maxretry 4`, бан на сутки | `/etc/fail2ban/jail.d/oko.conf` | перебор не жжёт процессы и журнал |
| Копия базы каждую ночь в 03:00, хранение 30 дней | `/usr/local/sbin/amberry-backup.sh`, `amberry-backup.timer` | копий не было вовсе, а в базе люди, коины и оплаты |

Копии снимаются `sqlite3 .backup` (не `cp`: горячая база копируется
нецелостной) и лежат ТОЛЬКО на своём сервере — в `/srv/amberry/backups`.
Перед съёмкой проверяется свободное место: резервное копирование не
имеет права остановить бота.
