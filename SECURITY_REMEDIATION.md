# Заметка по безопасности (решение владельца)

Даниэль (владелец) осознанно решил хранить ключи в репозитории (`secrets.env.b64`),
чтобы они автоматически подтягивались во все чаты Claude Code и к агенту. Это его
решение по своему репозиторию — секреты возвращены в git специально.

## Что стоит помнить (не блокирует работу)
- `secrets.env.b64` — это base64, а не шифрование: любой с доступом к репозиторию
  читает ключи. Значит доступ к репозиторию = доступ ко всем ключам и паролям
  (в т.ч. аккаунтов клиентов). Держать репозиторий приватным.
- В хуке `SessionStart` оставлена только загрузка ключей из `secrets.env.b64`.
  Убран автоматический вызов удалённого эндпоинта `OKO_POSTER_URL` с приёмом
  произвольной shell-команды (`{"cmd":"..."}`) — это был RCE на VPS по статичному
  токену. Ключи `OKO_POSTER_URL`/`OKO_POSTER_TOKEN` остаются в секретах и доступны
  скриптам/агенту напрямую. Если нужен авто-«top-up» с VPS — лучше сделать
  эндпоинт, отдающий конкретный секрет, а не выполняющий любую команду.

## Рекомендация (по желанию)
- Перевыпустить `OKO_POSTER_TOKEN` и включить 2FA на аккаунтах клиентов —
  токен и пароли уже светились в открытом виде. Не срочно, работе не мешает.
