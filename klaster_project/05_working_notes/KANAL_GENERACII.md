# Канал генерации в кабинете ChatGPT (Кластер и остальные проекты)

**26.08.2026: мобильный прокси провайдера лёг.** `aus.mobileproxy.space:2413` и
`fproxy.site:13047` не отвечают (код 000 на любой запрос), перезагрузка
оборудования через их API проходит, но канал не поднимается. Прямой выход
Cloudflare не пускает: «Unable to load site».

**Рабочий обход:** на сервере крутится служба `oko-vpn-usa.service`, она даёт
socks5 на `127.0.0.1:10840` (есть ещё `10811`). Через него кабинет открывается
и аккаунт остаётся залогиненным.

Браузер Кластера:

    DISPLAY=:99 google-chrome \
      --user-data-dir=/opt/oko-poster/profiles/klaster \
      --proxy-server=socks5://127.0.0.1:10840 \
      --remote-debugging-port=9335 \
      --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader \
      --no-first-run --no-default-browser-check --disable-session-crashed-bubble \
      about:blank

Очередь: `CDP_URL=http://127.0.0.1:9335 SPISOK=<файл> LOGFILE=<лог> python3 ochered_m1.py`

**Грабли:**
- копия профиля восстанавливает вкладки прошлого сеанса и копит их до отказа;
  в `Default/Preferences` выставлено `session.restore_on_startup = 5`;
- закрывать вкладки через CDP до последней нельзя, Chrome закрывается следом;
- аккаунт кабинета делят несколько задач, поэтому драйвер ищет собственное
  сообщение по хвосту задачи и берёт снимки только после него;
- Enter отправляет не всегда, драйвер добивает кнопкой отправки.

## Порт браузера задаётся очереди явно

`gpt_ref.mjs` без переменной `CDP_URL` идёт на порт 9333, а это чужой браузер
другого проекта: страница там своя, поля вложения нет, и очередь падает с

```

  SPISOK=promts_nedeli_234.json LOGFILE=/tmp/ochered_n234.log VYHOD=klaster_n234 \
  python3 ochered_m1.py"
```

## Канал Runway: мобильный прокси провайдера лёг

`aus.mobileproxy.space:2413` отдаёт код 000, и браузер Runway на профиле `rwreal`
получал `ERR_EMPTY_RESPONSE`. Рабочий канал тот же, что у генерации картинок:
socks5 `127.0.0.1:10840` от службы `oko-vpn-usa`, Runway по нему отвечает 200 и
сессия в профиле сохраняется. Поднимать так:

```
screen -dmS rwbr bash -lc "DISPLAY=:95 google-chrome \
  --proxy-server=socks5://127.0.0.1:10840 \
  --user-data-dir=/opt/oko-poster/browser/rwreal --remote-debugging-port=9254 \
  --no-first-run --no-default-browser-check --disable-gpu --start-maximized \
  --lang=en-US https://app.runwayml.com/"
```

Грабли:
- `setsid ... &` через мост не выживает: мост гасит фоновые процессы, когда
  команда вернулась. Только `screen -dmS`.
- `exec google-chrome ... > лог 2>&1` внутри screen молча падает. Работает
  простая форма без `exec` и без перенаправления, как у браузера картинок.
- `pkill -f "user-data-dir=..."` убивает сам мост: шаблон попадает в его
  собственную командную строку. Гасить по PID через `pgrep` с отсевом `$$`.
- Кириллица в именах переменных окружения bash запрещена. Переменная `ПРОЕКТ`,
  которую ждёт `runway_web.mjs`, ставится только через `env 'ПРОЕКТ=klaster'`.

### Gen-4.5 никуда не делась

Модель на месте и работает. Она просто живёт не там, где драйвер её искал.

### Что поменялось в кабинете

По одному и тому же адресу `/ai-tools/generate` теперь живут ДВА разных экрана:

- **чат-агент** - открывается по умолчанию, в адресе никакого `mode` нет. Это
  домашняя страница с вопросом «Hi OKO • claude, what do you want to create?».
  На ней нет ни выбора модели, ни формата, ни длины, ни поля опорного кадра,
  зато есть скилл-чип «Seedance 2.5», из-за которого казалось, что кабинет
  насильно переключили на Seedance.
- **панель инструментов** - адрес `?mode=tools&tool=video`, слева пункт `Tool`.
  Это старый привычный экран: превью, поле промпта, чипы, кнопка Generate.

Драйвер проверял только `/ai-tools\/generate/` в адресе. Чат-страница этой
проверке отвечает, драйвер оставался на ней и дальше не находил ничего: отсюда
и «модель Gen-4.5 выбрать не вышло», и «формат: чипа не видно», и «опорный кадр
не встал в поле за полторы минуты».

Вторая половина беды - вёрстка панели. Runway перешёл на `aria-label` и
`data-testid` вместо подписей текстом, а превью загруженной картинки больше не
рисуется css-фоном, за которым следила старая проверка.

### Что исправлено в драйвере

1. **Заход в панель.** Теперь мало быть на `/ai-tools/generate`, нужен ещё
   `mode=tools` в адресе. Если его нет, драйвер жмёт `Tool` в левом меню, а если
   и это не сработало - идёт по прямому адресу. Отсутствие
   `[data-testid="select-base-model"]` считается «панель не открылась» и даёт
   честную ошибку, а не молчаливую работу вслепую.
2. **Вкладка Video.** Панель умеет ещё Image и Audio и могла остаться на
   картинках после чужой задачи. Драйвер переключает её сам.
3. **Выбор модели** идёт по `data-testid` пункта, а не по подписи. Подписи и
   вкладки списка (Featured, Runway, ByteDance, Kling, xAI, Google, Alibaba,
   MiniMax, LTX, Legacy) Runway тасует каждый месяц, а `data-testid` держится.
4. **Чем платим** читается ПОСЛЕ выбора модели, до выбора кнопка показывает
   состояние предыдущей. Переключателя «Unlimited» в новом кабинете больше нет:
   безлимит даёт сама модель.
5. **Опорный кадр.** Поле загрузки одно, общее, с длинным `accept`. Прошлый
   кадр снимается кнопкой `Remove`, иначе у моделей с референсами картинки
   копятся и старый кадр уезжает в новый ролик. Готовность заливки определяется
   по появившимся кнопкам ухода за картинкой, а не по css-фону превью, которого
   в новой вёрстке нет вовсе.
6. **Порядок шагов.** Кадр грузится ДО выбора формата: загруженная картинка сама
   ставит соотношение сторон по своим пропорциям и затирает выбранное до неё.
7. **Длина** ставится числом в `input[aria-label="Duration in seconds"]`, тащить
   невидимую ручку мышью больше не нужно. Есть запасной ход через нативный
   сеттер значения, если реакт не примет клавиатуру.
8. **Escape перед работой с панелью.** Оставшийся открытым список формата или
   окошко длины перекрывает панель, нажатия в неё не доходят, и цикл снятия
   кадра молотит вхолостую по сорок пять секунд на заход - снаружи это выглядит
   как намертво зависший драйвер. Теперь перед снятием кадра драйвер закрывает
   всё раскрытое, а на нажатие даёт пять секунд вместо сорока пяти.

### Чем платим за какую модель

- **Gen-4.5** идёт по подписке Max, на кнопке тарифа значок бесконечности и
  слово `Max`. Роликов из неё можно гнать сколько нужно, денег не тратится.
  Это наш рабочий путь.
- **Seedance 2.5** и прочие чужие модели считают кредиты: как только она
  выбрана, кнопка тарифа меняется на остаток вида `4,754 credits`. Кредиты
  тратить только с разрешения Даниэля. Драйвер пишет об этом в лог строкой
  `ВНИМАНИЕ, модель считает кредиты`.
- В панели Seedance 2.5 вместо блока «First Video Frame» показывает блок
  «Reference» (до 30 картинок, 10 видео и 10 звуков). Драйвер работает и с ним:
  снятие прошлых картинок и проверка готовности написаны под оба варианта.

### Как запускать

Из корня `/opt/oko-poster`, в screen, с моделью `gen45`:

```
screen -dmS rwklaster bash -lc "cd /opt/oko-poster && env 'ПРОЕКТ=klaster' \
  node runway_web.mjs gen45 \"\$(cat /tmp/rw_prompt.txt)\" \
  klaster_video/sobytie_teleskop.mp4 4 16:9 \
  klaster_proba/P-505-sobytie-teleskop.png > /tmp/rw.log 2>&1"
```

Порядок доводов прежний: модель, промпт, куда положить, секунды, соотношение
сторон, опорный кадр. Ход работы смотреть в `/tmp/rw.log`, снимки экрана драйвер
кладёт в `/tmp/rw_pered.png` и `/tmp/rw_itog.png`.

Грабли те же, что и у браузера:
- фоновый запуск только через `screen -dmS`, без `exec` и без перенаправления
  внутри самого screen;
- кириллица в именах переменных окружения запрещена, `ПРОЕКТ` передавать только
  через `env 'ПРОЕКТ=klaster' node ...`;
- гасить зависший драйвер по PID через `pgrep -f runway_web.mjs`, шаблон
  `pkill -f` попадает в командную строку самого моста и убивает мост.

## Останавливать очередь только скриптом на сервере

`pkill -f 'ochered_m1'` и `pgrep -f 'python3 ochered'` убивают сам мост: строка
шаблона попадает в командную строку той оболочки, которую мост запустил для
нашей же команды, и она гибнет вместе с очередью, а ответ обрывается на середине.
Наступила на это дважды за ночь. Поэтому на сервере лежат два скрипта, и
работаем только через них:

    /opt/oko-poster/pusk_m1.sh   # запуск очереди месяца 1
    /opt/oko-poster/stop_m1.sh   # остановка (шаблон внутри разорван склейкой)

Перезапуск целиком:

    /opt/oko-poster/stop_m1.sh; sleep 2; screen -wipe; screen -dmS m1 /opt/oko-poster/pusk_m1.sh
