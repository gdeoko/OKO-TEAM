# Телеграм: правило, написанное ценой четырёх аккаунтов

Дата: 31.08.2026. Погибли acc1 (@ktodaniel), acc2 (@okomanager),
acc3 (@gdedaniel) и acc4 (@okohelp). Восстановление возможно только входом
по номеру телефона с кодом, то есть руками владельца.

## Что убивает аккаунт

Служба `oko-agents` держит сессии Телеграма в памяти постоянно. Любое второе
подключение тем же файлом сессии сервер Телеграма считает утечкой ключа и
аннулирует авторизацию НАВСЕГДА. Ошибка приходит такая:

    406 AUTH_KEY_DUPLICATED - The same authorization key (session file) was
    used in more than one place simultaneously

Копирование файла сессии во временную папку не спасает: ключ внутри файла тот
же самый. Именно так погиб acc4: скрипт сверки скопировал сессию и открыл
второе соединение, пока служба работала.

## Как работать правильно

**Отправка при живой службе - только мостом задач.** Мост шлёт из живого
подключения самой службы, второго соединения не появляется:

```python
from core import taskqueue as q
t = q.enqueue("generic", -1003575806235, "acc4")
q.mark(t, "done", {"text": "текст", "message_thread_id": 9})
```

Мост умеет: `text`, `image_url`, `video_url`, `file_url`, `voice_url`,
`caption`, `message_thread_id` (ветка форума), инлайн-кнопки. Альбомы он не
умеет: серию каруселей и историй шлём кадр за кадром. Потолок текста 4000
знаков, подписи 1000. Пауза между задачами от 7 секунд, иначе антифлуд.

Доставку проверяем по флагу `delivered` у задачи, а не по факту постановки.

**Чтение чата при живой службе невозможно.** Мост читать не умеет, а
подключаться напрямую нельзя. Нужно прочитать переписку - сначала штатно
останавливаем службу, и только потом подключаемся:

```bash
curl -sS -X POST "$CONTROL_URL/agent" -H "X-Token: $CONTROL_TOKEN" \
     -H "Content-Type: application/json" --data '{"op":"agents_stop"}'
# работа с сессией
curl ... --data '{"op":"agents_start"}'
```

Остановка обязана быть ДО подключения, а не после. Порядок наоборот и есть
та самая ошибка, которая стоила аккаунта.

## Предохранитель

`predohranitel.py` спрашивает у systemd, работает ли служба, и при работающей
службе не даёт скрипту подключиться. Он вшит в `otpravka_nedeli.py`,
`chistka9.py`, `otpravka_karuseli.py`, `lenta_etalon.py`. Любой новый скрипт,
который открывает `Client`, обязан звать его первой строкой после импортов:

```python
from predohranitel import проверить_или_выйти
проверить_или_выйти()
```

## Что ещё стоит помнить

Антифлуд Телеграма ловится на паузе меньше 7 секунд. Подпись к фото режется
на 1024 знаках, поэтому текст поста уходит отдельным сообщением, а не
подписью. Один клиент это один аккаунт навсегда, кросс-акк-переписки
запрещены.
