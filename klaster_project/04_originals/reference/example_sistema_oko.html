ПЕРЕД НАЧАЛОМ РАБОТЫ
Что Claude обязан прочитать, понять и подтвердить до создания первой строчки кода

Что даётся на вход каждой сессии

Каждая сессия создания системы начинается с передачи 4 файлов:

1Анкета клиента (заполненная) — HTML файл с ответами на 8 разделов (64 вопроса). Это главный источник данных о клиенте. Вся система строится на основе анкеты.
2Данное ТЗ — полная инструкция как строить систему. Обязательно к прочтению целиком.
3HTML файл предыдущего этапа — то что уже создано. Claude продолжает, не переделывает.
4TXT-отчёт предыдущей сессии — что сделано, что делать дальше, переменные клиента, выявленные корректировки.
📌
Первая сессия — исключение
В первой сессии HTML и TXT-отчёт ещё нет. Есть только анкета и ТЗ. Первая сессия начинается с анализа анкеты + веб-поиска конкурентов и трендов ниши.

Обязательный алгоритм перед стартом

1
Прочитать анкету полностью
Все 8 разделов, все 64 вопроса. Зафиксировать: ниша, продукты, имя клиента, цвета бренда, цели, период, соцсети, аудитория. Именно из анкеты берутся все данные для персонализации.
2
Прочитать TXT-отчёт (если есть)
Что уже сделано. Какие переменные зафиксированы. Что делать в этой сессии. Корректировки которые нужно учесть.
3
Подтвердить понимание Даниэлю
Коротко: ниша клиента, период, что создаём в этой сессии, какой результат будет на выходе. Ждать команду «старт».
4
Только после «старта» — начинать
Не начинать создавать что-либо до явной команды Даниэля. Это правило без исключений.

JavaScript — Canvas анимация
// Canvas background — частицы цвета акцента клиента
function initCanvas() {
  const canvas = document.getElementById('bg-canvas');
  const ctx = canvas.getContext('2d');
  
  // Цвет частиц = акцент клиента из CSS переменной
  const accentRGB = getComputedStyle(document.documentElement)
    .getPropertyValue('--accent').trim();
  
  let particles = [];
  const PARTICLE_COUNT = 60;
  
  function resize() {
    canvas.width = window.innerWidth;
    canvas.height = window.innerHeight;
  }
  
  class Particle {
    constructor() { this.reset(); }
    reset() {
      this.x = Math.random() * canvas.width;
      this.y = Math.random() * canvas.height;
      this.size = Math.random() * 2 + 0.5;
      this.speedX = (Math.random() - 0.5) * 0.4;
      this.speedY = (Math.random() - 0.5) * 0.4;
      this.opacity = Math.random() * 0.4 + 0.1;
    }
    update() {
      this.x += this.speedX;
      this.y += this.speedY;
      if (this.x < 0 || this.x > canvas.width ||
          this.y < 0 || this.y > canvas.height) this.reset();
    }
    draw() {
      ctx.beginPath();
      ctx.arc(this.x, this.y, this.size, 0, Math.PI * 2);
      ctx.fillStyle = accentRGB;
      ctx.globalAlpha = this.opacity;
      ctx.fill();
    }
  }
  
  // Инициализация частиц
  for (let i = 0; i < PARTICLE_COUNT; i++) {
    particles.push(new Particle());
  }
  
  // Линии между близкими частицами
  function drawConnections() {
    for (let i = 0; i < particles.length; i++) {
      for (let j = i + 1; j < particles.length; j++) {
        const dx = particles[i].x - particles[j].x;
        const dy = particles[i].y - particles[j].y;
        const dist = Math.sqrt(dx*dx + dy*dy);
        if (dist < 120) {
          ctx.beginPath();
          ctx.moveTo(particles[i].x, particles[i].y);
          ctx.lineTo(particles[j].x, particles[j].y);
          ctx.strokeStyle = accentRGB;
          ctx.globalAlpha = (1 - dist/120) * 0.08;
          ctx.lineWidth = 0.5;
          ctx.stroke();
        }
      }
    }
  }
  
  function animate() {
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    particles.forEach(p => { p.update(); p.draw(); });
    drawConnections();
    requestAnimationFrame(animate);
  }
  
  window.addEventListener('resize', resize);
  resize();
  animate();
}

// Вызов при загрузке
window.addEventListener('load', initCanvas);

Canvas в генераторах (КП, лид-магниты и тд)
В каждом отдельном HTML генераторе (КП, партнёрство, лид-магниты, лендинги) Canvas инициализируется аналогичным кодом. Цвет частиц берётся из бренда клиента. Opacity: 0.3–0.4 чтобы не перекрывать контент.

1
Уровень 1 — Календарь месяцев
Визуальный календарь: строки = недели, колонки = дни. Каждый день-ячейка показывает: номер дня, количество контент-единиц, индикатор (точка/линия цвета акцента если есть контент). Клик на день → раскрывается уровень 2 прямо под ячейкой (НЕ всплывающее окно).
2
Уровень 2 — Список контент-единиц дня
Для каждой единицы дня: иконка формата (Ф1-Ф8 + карусель + TG пост + сторис), краткая тема (1 строка), бейдж типа (виральный / кодовое слово / лид-магнит). Клик на строку → раскрывается уровень 3.
3
Уровень 3 — Полный контент единицы
Текст ролика / карусели / поста полностью. Описание. Кодовое слово (если есть). Кнопки действий (детально ниже).

Фазы публикации (из анкеты)

Количество контент-единиц в день берётся из анкеты клиента:

Фаза 16 единиц в день: 3 виральных + 2 с кодовым на продукт + 1 с лид-магнитом
Фаза 212 единиц в день: 6 виральных + 4 с кодовым + 2 с лид-магнитом
Фаза 318 единиц в день: 9 виральных + 6 с кодовым + 3 с лид-магнитом

Правило тёплого окружения

📌
Продающий ролик всегда окружён виральными
Каждый ролик с кодовым словом на продукт окружён виральными роликами с обеих сторон. Порядок в день: виральный → кодовое → виральный → кодовое → виральный. Никогда два продающих подряд.

Заглушки и заполнение по сессиям

Контент-план заполняется поэтапно — по 10 дней за сессию (Этапы 6, 7, 8...). До заполнения дни показываются как заглушки:

▸Заглушка: «День X — будет заполнен в следующей сессии»
▸Визуально отличается от заполненных (пунктирная граница, пониженная яркость)
▸Структура дня создаётся сразу (ячейка в календаре), только контент пуст

Визуальный ежедневный чек-лист с категориями, прогресс-баром и связью с контент-планом

Структура чек-листа

Чек-лист — ежедневный список задач. Работает как Контент-план: сначала календарь, клик на день → задачи дня.

Календарь дней

▸Аналогичен контент-плану: сетка дней с индикатором выполнения
▸Цвет ячейки: серый = нет данных, оранжевый = частично, зелёный = выполнен
▸Текущий день — выделен акцентом, авто-открывается

Задачи дня — категории

Задачи группируются по категориям. Состав категорий адаптируется под нишу клиента из анкеты:

✓Контент — снять, смонтировать, опубликовать, написать описания, ответить на комментарии
✓Бизнес — задачи из бизнес-плана на этот день, встречи, звонки
✓Маркетинг — рассылки, реклама, коллаборации
✓Продажи — обработать заявки, написать потенциальным клиентам, закрыть сделки в CRM
✓Аналитика — проверить метрики, внести в трекер
✓Развитие — обучение, нетворкинг, партнёрства

Прогресс-бар

▸Общий прогресс дня: % выполненных задач
▸Прогресс по периоду: сколько дней полностью завершено
▸Анимация прогресс-бара при отметке задачи
▸Сохранение состояния в localStorage браузера

Связь с Контент-планом

▸Кнопка «Открыть контент этого дня» → Контент-план → нужный день
▸Задача «Опубликовать контент» кликабельна → открывает нужный день контент-плана

function addTrackerEntry(platform, currentCount) {
  const key = 'tracker_' + platform;
  const entries = JSON.parse(localStorage.getItem(key) || '[]');
  
  const prevCount = entries.length > 0 ? entries[entries.length - 1].count : currentCount;
  const delta = currentCount - prevCount;    // авто-дельта
  const deltaPercent = prevCount > 0 ? ((delta / prevCount) * 100).toFixed(1) : 0;
  
  entries.push({
    date: new Date().toLocaleDateString('ru-RU'),  // авто-дата
    timestamp: Date.now(),
    count: currentCount,
    delta: delta,             // прирост от предыдущей записи
    deltaPercent: deltaPercent
  });
  
  localStorage.setItem(key, JSON.stringify(entries));
  renderTracker(platform);
  renderTrackerChart(platform);
  updateTrackerForecast(platform);
}

▸Сохранения: самый сохраняемый формат — делать полезными (чек-листы, инструкции, топы)
▸Инструмент: Canva или Gemini по промпту

▸Что: Аватар клиента говорит его голосом. Клиент не снимается — пишет текст, HeyGen генерирует видео
▸Требования: клиент должен заранее записать клонирование голоса и внешности в HeyGen
▸Промпт системы: готовый текст сценария — клиент только вставляет в HeyGen
▸Лучшие темы: обучающий, экспертный контент где важна подача но не живые эмоции

КОДОВЫЕ СЛОВА — ПРАВИЛА И ЛОГИКА
Как выбирать, куда ставить, правило тёплого окружения, запреты

Что такое кодовое слово

Кодовое слово — слово которое зритель пишет в комментарии или директ, и SMMBot автоматически отвечает с нужной ссылкой/материалом. Это основа автоворонки.

Правила кодовых слов

▸ЛИБО в ролике ЛИБО в описании — никогда в обоих. Дублирование убивает органику
▸Максимум 1 кодовое слово в день на 1 продукт — не спамить
▸В описании — формат: первая строка — кодовое, вторая — ссылка (или в закреп-комментарий)
▸В ролике — формат: произносится естественно в конце: «Напиши [слово] — и я пришлю...»

Правило тёплого окружения

Продающие ролики (с кодовым словом) должны окружать виральные (без кодового). Соотношение: на каждый продающий — минимум 2 виральных вокруг него.

▸Виральный → Виральный → Продающий → Виральный → Виральный → Продающий
▸Виральные — без кодовых слов, направлены на максимальный охват
▸Продающие — с кодовым + ссылка. Не более 30–40% контента

Как подбирать кодовые слова

▸Связь с темой ролика: если ролик про пасту — кодовое «ПАСТА», если про завтраки — «ЗАВТРАК»
▸Лид-магниты: кодовое = название лид-магнита («РЕЦЕПТ», «ГАЙД», «ПЛАН»)
▸Продукты: уникальное слово связанное с продуктом («КЛУБ», «АКАДЕМИЯ», «УЖИН»)
▸Можно добавить цифру: «РЕЦЕПТ3», «КЛУБ2» — для разных лид-магнитов одной категории

ПРАВИЛА ЯЗЫКА И СТИЛЯ ТЕКСТОВ
Живой язык, запрещённые конструкции, структура описаний, хуки, адаптация под нишу

Главный принцип — живой язык

Все тексты (сценарии, посты, описания, скрипты) пишутся как живая речь — так, как говорит сам клиент. Не как учебник, не как ChatGPT, не как рекламный буклет.

Запрещённые конструкции

✗Тире в середине предложения — заменять на «и», «или», «но», «а»
✗Противопоставления «Однако», «Тем не менее», «Несмотря на» — убирать
✗ИИ-штампы: «В мире где», «На современном этапе», «Как никогда актуально» — удалять
✗Списки через запятую в середине предложения — разбивать на отдельные мысли через «и»
✗«Не только... но и» — заменять на прямое утверждение
✗Пассивный залог: «было сделано», «является» — заменять на активный

Обязательные правила

▸Единый поток мысли — не разрывать на тезисы, если это пост или сценарий
▸Перечисление через «и» — «фокус и системность и результат», не «фокус, системность, результат»
▸Конкретные цифры — «за 3 недели» вместо «за короткое время»
▸Глаголы действия — «получишь, сделаешь, узнаешь» вместо «будет возможность получить»
▸«Ты» — обращение — не «вы», не «аудитория» — только «ты» если нет причин для «вы»

Структура хука (первые 3 сек видео / первые 2 строки поста)

▸Ключевые слова — в начало. Не «сегодня я расскажу» а сразу суть
▸Конкретный результат или цифра: «За 30 дней +10К подписчиков», «5 техник которые...»
▸Триггеры: деньги / подписчики / просмотры / время / страх потери / эксклюзив
▸Соотношение хуков: 50% широкие (любой человек зацепится) + 50% нишевые (только ЦА)

Структура описания к ролику

▸Строка 1: кодовое слово (если продающий) ИЛИ цепляющая фраза-продолжение хука
▸Строка 2: ссылка на оплату или лид-магнит (если продающий)
▸Далее: развёрнутый текст поста — раскрытие темы ролика, дополнительная ценность
▸В конце: ссылка на TG канал
▸Финальная строка: «Для поиска:» + 15–30 ключевых слов через пробел
✗Никаких цен в описании. Никаких @никнеймов TG в соцсетях (только ссылки)

Главный принцип — анализ клиента определяет всё
Длина текстов, тон, стиль, темп, юмор, глубина — всё зависит от ниши, возраста, характера, локации, пола и аудитории клиента. Шеф-повар из Бангкока говорит иначе чем финансовый аналитик из Москвы. Правила ниже — это универсальный каркас. Наполнение всегда индивидуальное.

1. Сценарий ролика (видео)

Структура универсальная, длина и стиль — под клиента.

Структура: Хук → Тело → CTA

▸Хук (первые 2–4 сек): одна фраза. Ключевые слова в начало. Конкретный результат или цифра. Триггер (деньги / подписчики / страх / эксклюзив). Задача — остановить скролл.
▸Тело (60–80% хронометража): раскрытие обещания хука. Польза / доказательство / история / инструмент. Делится на 2–4 смысловых блока без явных разрывов — единый поток. В виральных роликах: 100% польза. В продающих: 70% польза + подготовка к CTA.
▸CTA (последние 3–8 сек): одно конкретное действие. Для продающих — кодовое слово. Для виральных — призыв подписаться / сохранить / поделиться. Никогда двух CTA одновременно.

2. Описание к ролику (caption)

▸Строка 1: кодовое слово (если продающий) ИЛИ продолжение хука ролика — зацепить тех кто дочитал
▸Строка 2: ссылка на продукт / лид-магнит (если продающий)
▸Основной текст: развёрнутое раскрытие темы ролика — дополнительная польза которой нет в видео. 70% польза, 30% контекст и призыв.
▸Предпоследняя строка: ссылка на TG канал
▸Последняя строка: «Для поиска:» + 15–30 ключевых слов через пробел — релевантные нише и теме ролика
❌ ЗАПРЕЩЕНО в описаниях
✗Цены — никогда. Ни в одном описании ни одного формата.
✗@никнейм TG в тексте — только ссылка t.me/...
✗Кодовое слово одновременно в ролике И в описании
✗Два продающих ролика подряд в один день

3. ТГ-пост

Тип поста определяется на основе анализа клиента и его контент-плана. Три базовых типа:

Тип 1 — Экспертный пост

▸Зачин (1–2 строки): утверждение или факт который удивляет или противоречит ожиданиям аудитории
▸Раскрытие (основной текст): объяснение, доказательство, личный опыт или кейс. 3–5 смысловых абзацев. Единый поток без списков.
▸Вывод + CTA: что делать с этим знанием. Ссылка или кодовое слово если продающий.
▸Длина: 600–1200 символов. Адаптируется под возраст аудитории — молодая читает короче.

Тип 2 — Кейс / цифры

▸Заголовок: результат цифрой — «0 рублей на рекламу и 200 заявок», «За 30 дней +8К подписчиков»
▸Контекст: кто клиент (без имени), с чего начали, что было до
▸Что сделали: конкретные шаги — 3–5 действий. Каждое действие понятно и применимо.
▸Результат + CTA: цифра которую обещал заголовок + следующий шаг
▸Длина: 500–900 символов

Тип 3 — Оффер / продающий

▸Зачин: кодовое слово + проблема которую решает продукт
▸Описание продукта: что получит человек, конкретно и ёмко. Без перечисления «входит то и это» — только результат.
▸Социальное доказательство: одна фраза — сколько клиентов, какой результат
▸CTA: одно действие — написать кодовое / перейти по ссылке. Цены нет.
▸Длина: 300–600 символов — короче, конкретнее
📌
Адаптация ТГ-постов под клиента
Тип поста, длина, тон — на основе анализа: аудитория клиента молодая или зрелая? Ниша серьёзная (финансы, медицина) или лёгкая (еда, lifestyle)? Клиент говорит «ты» или «вы»? Локация влияет на культурный контекст примеров и кейсов. Всё это определяет стиль каждого поста.

5. Сторис С1–С5

Размер 1080×1920 (9:16). Для каждого типа: промпт фона + полный текст что говорить.

ТипСтруктура текстаПромпт фонаАдаптация под клиента
С1 — Экспертная Тезис (1 фраза) → объяснение (2–3 фразы) → вывод + призыв писать в директ или ответить на вопрос EN-промпт: тёмный фон в цветах бренда, минималистичный, акцент на типографике, без лиц Тон и тема — на основе ниши. Финансы: строгий. Lifestyle: живой и личный.
С2 — За кулисами «Покажу...» или «Сегодня...» → показ процесса голосом (30–40 сек) → CTA написать реакцию Живое видео клиента, промпт не нужен Место съёмки должно совпадать с нишей. Повар на кухне, тренер в зале.
С3 — Вопрос-ответ Зачитать вопрос из директа → 30–45 сек ответ по существу → «Ещё вопросы — пиши» Фон с виджетом вопроса или минималистичный тёмный Вопросы — из реальных директов клиента. Если нет — придумать типичные для ниши.
С4 — Прогрев Упоминание продукта косвенно → личная история или наблюдение → кодовое слово как ответ EN-промпт: атмосферный фон в стиле бренда, эмоциональный, тёплый Стиль прогрева зависит от продукта. Дорогой продукт — мягче. Массовый — прямее.
С5 — Опрос / вовлечение Вопрос аудитории (без текста — только виджет опроса) → реакция на результаты в следующей сторис Фон БЕЗ текста — только виджет опроса в редакторе соцсети Тема опроса — из болей аудитории клиента. На основе анализа ЦА из анкеты.

6. Правило 70/30 — соотношение пользы и CTA

В любом тексте: 70% — польза, инструменты, знание, история. 30% — контекст продукта, кодовое слово, ссылка, CTA.

▸Виральный контент: 100% польза. Без CTA на продукт. Максимум — призыв подписаться/сохранить.
▸Продающий контент: 70% польза + 30% продажа. Польза всегда первая — CTA в конце.
▸Никогда два продающих подряд. Минимум 2 виральных между продающими.
▸Лид-магнитный контент: 80% польза + 20% «хочешь больше — напиши слово»

НАВИГАЦИЯ ИЗ ЧЕК-ЛИСТА — ПОЛНАЯ ЦЕПОЧКА
Как кнопка в чек-листе открывает нужный материал в другом разделе — полная техническая цепочка

Принцип навигации

Каждая задача в чек-листе может иметь кнопку «Открыть материал» которая ведёт точно к нужному контенту. Не просто к разделу — а к конкретному блоку, подблоку, раскрытому аккордеону с подсветкой нужного элемента.

Полная цепочка

1showPage(section) — переключить страницу (content / biz / materials / visual / persp)
2setTimeout(300мс) — подождать пока страница отрендерится
3openBlock(blockId) — открыть нужный блок (карточку в меню блоков)
4setTimeout(200мс) — подождать анимацию открытия блока
5openSubBlock(subId) — открыть подблок внутри блока (если есть вложенность)
6toggleCI(itemId) — раскрыть аккордеон / CI элемент (промпт, сценарий, описание)
7el.scrollIntoView({behavior: 'smooth', block: 'center'}) — прокрутить к элементу
8highlight-flash 1.8 сек — подсветить элемент мигающей лаймовой обводкой

Технический код навигации

function navToItem(page, blockId, subBlockId, itemId) {
  showPage(page);
  setTimeout(function() {
    if (blockId) openBlock(blockId);
    setTimeout(function() {
      if (subBlockId) openSubBlock(subBlockId);
      if (itemId) {
        setTimeout(function() {
          toggleCI(itemId);
          var el = document.getElementById(itemId);
          if (el) {
            el.scrollIntoView({behavior: 'smooth', block: 'center'});
            el.classList.add('highlight-flash');
            setTimeout(function() {
              el.classList.remove('highlight-flash');
            }, 1800);
          }
        }, 300);
      }
    }, 200);
  }, 300);

АНАЛИТИКА-ЦИКЛ
Раз в месяц: LiveDune + трекеры → корректировки контент-плана, бизнес-плана и задач

Три источника данных

1Файл LiveDune — выгрузка аналитики соцсетей за месяц. Охваты, просмотры, подписки/отписки, сохранения, комментарии, переходы в профиль по каждому посту/ролику.
2Трекер аудитории (внутри системы) — клиент ведёт ежедневно: количество подписчиков в каждой соцсети на конец дня (+/-). 30 строк за месяц.
3Трекер продаж / CRM (внутри системы) — каждая сделка, по каждому продукту, с датой. Откуда пришёл клиент (кодовое слово / ролик / директ).

Алгоритм ежемесячной корректировки

ШагЧто анализируемЧто корректируем
1. Топ роликовКакие 3–5 роликов дали максимальный рост аудитории и/или продаж? Какой тип, тема, хук, формат?Контент-план следующего месяца: больше похожих тем и форматов
2. АнтилидерыКакие ролики дали 0 или отток? Тема / формат / время публикации?Убираем повторение этих тем/форматов. Корректируем время публикации.
3. Кодовые словаКакое кодовое слово принесло больше всего заявок? Из каких роликов?Больше роликов с этим кодовым. Кодовые которые не сработали — меняем слово или формат.
4. Динамика аудиторииВ какие дни трекер показывал рост? Что было опубликовано в эти дни? В какие дни отток?Оптимизация расписания. Корректировка соотношения типов контента.
5. Продажи по продуктамКакой продукт продавался лучше? Откуда приходили покупатели?Корректировка воронки SMMBot. Возможно увеличить промо самого продаваемого продукта.
6. Финансовый планФакт vs план. Отклонение в %.Пересчёт плана на следующий месяц. Корректировка KPI в бизнес-плане.

Что меняется по итогам анализа

▸Контент-план: темы, форматы, соотношение виральных/продающих, расписание
▸Чек-лист: задачи следующего месяца на основе нового контент-плана
▸Бизнес-план: финансовый план, KPI, план по продуктам
▸Воронки SMMBot: кодовые слова, тексты веток — на основе того что сработало
▸Промпты: если визуал определённого типа давал лучший результат — вшить его стиль

Все генераторы адаптируются под клиента
Структура — универсальная.
