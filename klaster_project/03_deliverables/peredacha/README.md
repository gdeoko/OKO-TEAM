# Страница передачи проекта «Кластер»

Закрытая паролем страница для заказчика: что сделано, где живёт, какие доступы
переходят, что осталось за заказчиком.

- Публичный адрес: `https://okoteam.top/peredacha/klaster/?k=<пароль>`
- Калитка (проверка пароля): `/var/www/okoteam/peredacha/klaster/index.php` на VPS,
  пароль задан в ней же, страница отдаётся через `readfile`.
- Сама страница лежит ВНЕ корня сайта: `/opt/oko-poster/peredacha/klaster.html`,
  права 644, владелец okoposter.

## Почему лежит здесь

04.10.2026 в 12:42:38 файл `/opt/oko-poster/peredacha/klaster.html` и содержимое
`/var/www/okoteam/klaster-den/` были удалены (обе папки опустели в одну секунду,
в кронах уборки таких путей нет, в логах nginx и git следов сборки не осталось).
Заказчик 05–07.10 получал 500: калитка жива, отдавать нечего. Страница собрана
заново 07.10.2026, и теперь исходник хранится в репозитории, чтобы разворачивать
её одной командой.

## Как развернуть заново

```sh
python3 peredacha_build.py          # соберёт klaster.html рядом (лого внутрь, base64)
# затем на VPS:
cp klaster.html /opt/oko-poster/peredacha/klaster.html
chmod 644 /opt/oko-poster/peredacha/klaster.html
curl -s -o /dev/null -w "%{http_code}\n" "https://okoteam.top/peredacha/klaster/?k=<пароль>"
```

## Правила страницы

- Самодостаточная: ни одного внешнего запроса, лого внутри файлом base64.
- Без эмодзи, тёмный верх и фирменный лайм-янтарь «Активити», mobile-first.
- `noindex, nofollow` в разметке, в robots.txt путь не светим.
- Паролей и ключей внутри НЕТ: только перечень передаваемых доступов.
  Сами пароли передаются лично в рабочем чате или письмом подписанту.
