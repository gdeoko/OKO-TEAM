## 1. О проекте

- **Что:** кинематографичный «магический» 3D-сайт для реального гейм-клуба DUCK'S GAME SPACE
  в Москве (покер, дартс, бильярд, бар). Клуб уже работает.

  ощущение «бесконечного живого мира»).
- **Концепция (НЕ МЕНЯТЬ):** единый непрерывный 3D-мир, камера летит вперёд. Утка-маскот
  (в чёрном худи и очках) → распадается на частицы → собирается в МОЗГ (слоган «играй мозгами»)
  → при клике мозг превращается в ТУННЕЛЬ из частиц, летящий НА зрителя → внутри текст.

- **Заказчик:** Caterina (через OKO TEAM). Деплой — сам клиент: ZIP → ISPmanager → `/www/ducks.games/`.

## 2. Стек и архитектура

- **Сборка:** Vite 5 (`vite.config.js`: `base: './'` — относительные пути, работает в любой папке хостинга;
  `assetsInlineLimit: 0`, `target: es2022`).
- **3D:** Three.js **0.164.1** (строго эта версия).
- **Скролл:** Lenis (плавный). **Анимации:** GSAP (timeline для интро).
- **Звук:** Web Audio API — ВСЁ синтезом, без файлов (`src/audio/sound-system.js`).
- **Загрузка моделей:** GLTFLoader + DRACOLoader. Декодер Draco **локальный** в `public/draco/`
  (`setDecoderPath('draco/')`) — НЕ с gstatic CDN (VPN/блокировки ломали загрузку).

### Файлы
```
index.html              # разметка: nav, #content (hero, about), #brain-detail, #loader, #sound-ind
src/main.js             # ВСЯ логика (~790 строк): сцена, частицы, камера, интро, скролл, туннель
src/style.css           # стили + адаптив (@media max-width:768px)
src/audio/sound-system.js   # SoundSystem: пэд + слои + эффекты (синтез)
src/three/environment.js    # ClubEnvironment: загрузка scifi_bar.glb, неон, PMREM-свет
vite.config.js
public/draco/           # draco_decoder.wasm + draco_wasm_wrapper.js (ЛОКАЛЬНО)
public/models/          # duck.glb (~1MB), brain.glb (~1.4MB), scifi_bar.glb (~0.17MB) — Draco+сжатые
public/.htaccess        # MIME для wasm/glb/webp + SPA fallback
dev-assets/             # НЕиспользуемые тяжёлые ассеты (ball8.glb, dart.glb, references/) — НЕ в сборку
verify.cjs              # headless-проверка (puppeteer) — НЕ в сборку (в .gitignore)
```

### Ключевые параметры в `src/main.js` (верх файла)
- `PCOUNT = isMobile ? 65000 : 115000` — число частиц.
- `HERO_Y`, `SUBJ_SCALE`, `DUCK_FACE = 270°` — позиция/разворот утки (клювом в камеру).
- `DUCK_DIST` — расстояние фигуры от камеры (моб 6.5 / ПК 4.6).
- Камера (подобрана клиентом, НЕ менять без спроса):
  `CAM0 = {x:0.39, y:0.10, z:20.69}`, `LOOK = {x:-0.49, y:-5.52, z:-8.27}`.

### Debug-параметры URL
- `?fast` — пропустить интро (для скриншотов финальной композиции).
- `?tune` — OrbitControls + HUD с координатами (для подбора ракурса фона).
- `?duck=град`, `?camy ?look ?camz ?roty ?dx ?dy ?dist` — тонкая подстройка.
- Тест-хуки (в коде, безвредны): `window.__setScroll(v)`, `window.__teleport`,
  `window.__openBrain()/__closeBrain()`, `window.__lenis`, `window.__scene`, `window.__camera`.

## 3. Как устроена анимация частиц (важно для правок)

Один `THREE.Points`. `sampleModel()` сэмплирует треугольники GLB по площади и **заполняет объём**
(cbrt-распределение → мозг плотный, не просвечивает).

Состояния по `tp` (scrollProgress 0..1):
- `tp 0..0.5`: утка → «взрыв»/облако (`explodePos`).
- `tp 0.5..1`: облако → мозг (`brainPos`).
- `tp > 0.75`: `onBrain` — мозг собран, можно кликать.

**Туннель** (`tunnelBlend` 0→1 плавно): кольца частиц (угол+радиус+фаза глубины), летят по −Z НА камеру.
Труба **предповёрнута на −brainYaw**, чтобы при любом угле вращения мозга лететь РОВНО на зрителя
(без «увода вбок» и без рывка-доворота на входе/выходе).

**Физика (текущая, рабочая):**
- `RETURN_SHAPE/RETURN_TOUCH` — насколько держится форма / мягкий возврат после касания.
- Касание = мягкое «раздвигание песка» (НЕ пружина, НЕ взрыв) + свечение внутри + плавное оседание.
- Само-движение «живое» — в ШЕЙДЕРЕ, привязано к точке формы (масса не расплывается).
- `reform` — окно сильной пересборки мозга после выхода из туннеля (чинит «дырку»).
- `brainBurst` — лёгкий толчок при входе (0.35, не взрыв).

**Свет/материал частиц:** монохром ледяной-белый, мягкое круглое зерно, объёмная подсветка,
свечение от скорости/касания. Фон клуба гаснет у мозга (`env.fade`), чтобы неон не просвечивал.

## 5. ОШИБКИ, которые уже были (НЕ ПОВТОРЯТЬ)

1. **`Object.assign(new THREE.PointLight(...), {position:...})`** → `position` read-only → краш всей сцены
   → вечная загрузка. **Фикс:** `mkLight()` с `l.position.set()`. (Виновата была НЕ хостинг, а код.)
2. **Draco-декодер с gstatic.com** блокировался VPN → модели не декодировались. **Фикс:** локально в `public/draco/`.
3. **Абсолютные пути `/assets/`,`/models/`** ломались на хостинге. **Фикс:** vite `base: './'`.
4. **Импорты вперемешку с кодом** → "Cannot access 'ri' before initialization". **Фикс:** все import сверху,
   `let orbit=null` рядом с верхом.
5. **Тяжёлые модели (29 MB)** → часы загрузки. **Фикс:** gltf-transform Draco+сжатие до 1–1.4 MB.
6. **Сэмплинг 70k+ точек** морозил headless. Держать разумный PCOUNT.
7. **Скриншоты headless ловили середину анимации** (низкий FPS) → казалось, что сломано.
   **Фикс:** `?fast` + тест-хуки `__teleport/__setScroll`, давать время на сходимость, мерить ЧИСЛАМИ.
8. **Трогала фон** (прятала меши вентилятора) — клиент против. Фон ЗАФИКСИРОВАН.
9. **`?roty=` в адресной строке** делал вид «сломано» (серая стена) — открывать чистый ducks.games.
10. **JS-«поток» со слабым удержанием** → масса расплывалась, теряла форму мозга.
    **Урок:** форму держать жёстко (JS), «жизнь» — в шейдере, привязанной к точке.
11. **Частицы additive на тёмном фоне** → серость и просвечивание. **Фикс:** плотное непрозрачное зерно + cbrt-объём.
12. **Вращение трубы вокруг Z** → «вправо-влево». **Фикс:** труба предповёрнута на −brainYaw, летит по −Z.
13. **Дырка после туннеля** — частицы догоняли трубу/застывали кольцом. **Фикс:** окно `reform` + сброс vel/glow/disturb.
14. **enter-screen** перекрыт прелоадером + `pointer-events:none` → некликабельно, утка пропадала. ОТКАЧЕНО.
15. **Edit падал на смайл/юникод-комментариях** — копировать точную строку из файла, не «на память».
16. **Дамп сырых байтов в терминал** (`od -c` на кириллице) однажды вызвал сбой API. НЕ дампить бинарь/мусор.
17. **Ложь в коммите** («tool output tampered») — так НЕ делать. Сообщения честные.
18. **Пустые/битые вызовы инструментов** (SendUserFile без files, AskUserQuestion без questions) — проверять аргументы.

## 8. История фидбэка клиента (суть)

Клиент очень внимателен к деталям и устал от итераций. Ключевые требования, повторённые много раз:
- Частицы как у igloo: **полностью заполненный мозг** (не просвечивает), **каждая частица бегает**
  по всей форме (внутри и снаружи, иногда за контур), движение быстрое но **плавное**, не «дрожит на месте».
- Касание: **не пружина/резина/жвачка**, а «палец в песке» — мягко раздвигает, светится, плавно стекается.
- Туннель: строго **НА зрителя**, без увода вбок и без поворота мозга на входе/выходе; после выхода
  мозг **полностью собирается** (была «дырка»); текст приближается из точки; затемнение плавное.
- Звук на каждый смысловой момент (загрузка, кубики, утка, запуск, туннель), шелест частиц на мозге.
- 1 экран: текст появляется ПОСЛЕ кубиков; утка ровно, не налезает; кнопки под лапками.
