# ВХОДЫ DIESEL: три площадки, закреплены намертво

Читать в любом чате, в любом репозитории. Дальше спрашивать про входы не нужно:
они держатся сами, проверяются одной командой и восстанавливаются из бэкапа.

**Паролей в этом файле нет и не будет.** Они живут на сервере в
`/opt/oko-poster/cfg/secrets.env` и в мастер-хранилище, оба приезжают в сессию
хуком. Git ключи не хранит, даже в base64.

---

## 0. ОДНА КОМАНДА, КОТОРАЯ ОТВЕЧАЕТ НА ВСЁ

```bash
vexec 'bash /opt/oko-poster/vhody_proverka.sh'
```

Печатает по каждой площадке живой вход или мёртвый, с именем канала и числами.
Ничего не публикует. Обёртка `vexec` описана в `OKO_BOOTSTRAP.md`.

Если из чата нет `vexec`, ключи не подтянулись. Лечится двумя переменными в
Environment variables на claude.ai: `OKO_POSTER_URL` и `OKO_POSTER_TOKEN`.
Это единственное, что нужно новому аккаунту.

## 1. HOOPPY СНЯТ С МАРШРУТА НАВСЕГДА

Слово владельца 07.09.2026. Сервис не используем ни для постинга, ни для
аналитики, ни в одном проекте.

Снято живьём в тот же день: 35 скриптов убрано, 11 ключей `HOOPPY_*` удалено из
секретов, семь рабочих модулей переписаны. Снятое лежит на сервере в
`/opt/oko-poster/cfg/snyato_hooppy_<дата>/` на случай разбора, в работу не
возвращается.

Что потеряли осознанно: счётчик постов TikTok в отчёте `diesel_bot.py` и
подписчиков TikTok в отчёте по МЕТАНОЙЕ. Эти поля теперь пустые, а не нулевые:
неизмеренное это не ноль, иначе выводы строятся на выдумке.

**Публикация в TikTok идёт прямой браузерной сессией:**

```bash
vexec 'cd /opt/oko-poster && CAPB64=$(printf "%s" "текст подписи" | base64 -w0) \
       DISPLAY=:99 node tt_upload.mjs /путь/ролик.mp4 /opt/oko-poster/cfg/tt_diesel_prof'
```

`TT_DRY=1` доводит до кнопки и не нажимает: так проверяют путь, ничего не
публикуя. Ответ последней строкой: `RESULT POSTED`, `RESULT DRY`, `RESULT FAIL`
с причиной. В конвейере это уже зашито в `post_direct.py` и `publish_next.py`.

Две грабли, на которых загрузчик уже спотыкался и которые он теперь обходит сам:
TikTok Studio кидает поверх редактора модалки «Turn on automatic content checks»
и «New editing features added», они перехватывают нажатие и клик виснет по
таймауту; и фокус в поле подписи ставится изнутри страницы, снаружи его
перехватывает то же наложение. Подпись вставляется одним событием, посимвольный
набор на длинном тексте оставляет поле пустым для приложения.

**TikTok ходит через socks5 `127.0.0.1:10811`.** Порт 10843 из старых записей
мёртв, живые на 07.09.2026 это 10811 и 10840.

## 3. БЭКАПЫ СЕССИЙ: вход не теряется, даже если профиль убьют

```bash
vexec 'bash /opt/oko-poster/vhody_backup.sh'      # снять бэкап прямо сейчас
vexec 'ls -la /opt/oko-poster/cfg/vhody/'         # что лежит
```

Снимает профили TikTok и Instagram целыми архивами и проверяет живость
refresh-токена YouTube. Держит три поколения: `имя.tgz` свежее, `имя.1.tgz` и
`имя.2.tgz` прошлые. Пишет через временный файл и заменяет целевой только после
проверки архива: оборванный архив вместо рабочего это потерянный вход.

Ставится в cron раз в сутки. Журнал `/opt/oko-poster/logs/vhody.log`.

**Восстановить профиль из бэкапа:**

```bash
vexec 'cd /opt/oko-poster/cfg && tar xzf vhody/tiktok_diesel.tgz -C /opt/oko-poster/cfg'
vexec 'cd /opt/oko-poster && tar xzf cfg/vhody/instagram_diesel.tgz -C /opt/oko-poster/browser'
```

Свежий архив битый, а вход всё равно не встал, значит брать `имя.1.tgz`.

## 4. ЕСЛИ ВХОД ВСЁ-ТАКИ СЛЕТЕЛ

Порядок жёсткий, сверху дешевле.

**Сначала проверить выход в сеть, а не аккаунт.** Половина «слетевших входов»
это мёртвый прокси. Отказ по стране лечится сменой выхода, а не выводами.

```bash
vexec 'curl -s --socks5-hostname 127.0.0.1:10811 https://ipinfo.io/json'
vexec 'set -a; . /opt/oko-poster/cfg/secrets.env; set +a; curl -s -x "$IG_PROXY_HTTP" https://ipinfo.io/json'
```

Мобильный прокси отвечает `407`, значит в строке потерялись логин с паролем.
Брать их у самой панели, а не из памяти:

```bash
vexec 'set -a; . /opt/oko-poster/cfg/secrets.env; set +a
       curl -s "https://mobileproxy.space/api.html?command=get_my_proxy" \
            -H "Authorization: Bearer $IG_PROXY_API_TOKEN"'
```

**TikTok просит код.** Он приходит на почту `ssm101002@gmail.com`, и забирает
его сам скрипт `tt_code.py` по IMAP. Человек не нужен. Пароль приложения почты
лежит в секретах. Перед запуском убить все старые процессы входа и запустить
РОВНО ОДИН: девять параллельных попыток однажды дали
«Maximum number of attempts reached» на весь аккаунт.

**Instagram просит подтвердить, что вы человек.** Капчу не автоматизировать,
она от этого ужесточается. Пройти в приложении Instagram с телефона, с реального
мобильного адреса, кнопка «Продолжить», около тридцати секунд.

**YouTube отдаёт пустой access-токен.** Refresh-токен отозван, нужен новый через
OAuth-приложение OKO в Google Cloud. Это единственный случай из трёх, где нужен
владелец.

## 5. ЧЕГО НЕ ДЕЛАТЬ

- Не подключаться к живой сессии Телеграма при работающей службе `oko-agents`.
  Правило написано ценой четырёх аккаунтов: второе подключение тем же файлом
  сессии Телеграм считает утечкой ключа и аннулирует авторизацию навсегда.
- Не чистить профили браузера и не запускать их без прокси.
- Не публиковать неутверждённое. Наряд отвечает, КАК сделано, утверждение
  отвечает, СОГЛАСЕН ли клиент. Это разные двери, обе обязательны.
- Не возвращать Hooppy.
